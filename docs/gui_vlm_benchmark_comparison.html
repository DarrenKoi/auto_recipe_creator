Observed Kimi-VL Limitations in RCS Automation

Based on real-world testing with CD-SEM/RCS engineering UI automation, Kimi-VL exhibits critical failures in production scenarios.

Narrow-Range Element Detection Failure

When multiple UI elements are packed closely together in a narrow region (e.g., toolbar buttons, dropdown items, tab headers, tree-view nodes), Kimi-VL cannot reliably distinguish adjacent elements.

  • Click coordinates drift to neighboring elements when targets are < 20px apart
  • Overlapping bounding boxes for closely-spaced buttons/labels
  • Toolbar icon clusters produce ambiguous coordinate outputs
  • Tree-view and list-view rows with small row-height are frequently confused
  • RCS recipe editor has dense control panels with < 10px element spacing

Root Cause: No GUI Spatial Training

General-purpose VLMs are trained on natural images, documents, and web screenshots — not dense engineering UIs. They lack:

  • Sub-pixel coordinate precision required for small targets
  • GUI-specific spatial encoding for element boundary detection
  • Widget-type awareness (buttons vs labels vs inputs look similar in legacy UIs)
  • High-resolution patch processing for professional displays (1920x1080+)
  • ScreenSpot-Pro confirms: accuracy degrades rapidly as target box area decreases, and icon-only grounding drops to < 5% for general models
Impact on RCS Automation: In the CD-SEM recipe editor, a single misclick on a densely-packed parameter panel can select the wrong measurement region, alter critical recipe values, or trigger an unintended tool calibration sequence. Kimi-VL's inability to precisely target narrow-range elements makes it unreliable for production-grade automation of complex engineering software.

Key Takeaways

Problem: Kimi-VL Limitations

  • 34.5% on ScreenSpot-Pro — misses 2 out of 3 click targets
  • Not trained on GUI-specific data
  • Icon/widget detection near-zero on engineering UIs
  • API dependency — latency, cost, availability risk
  • No fine-tuning possible (closed-source API)

Solution: GUI-Specialized Models

  • 61.6% accuracy (UI-TARS-1.5-7B) — +78% improvement
  • Trained specifically on GUI screenshot→coordinate tasks
  • Open-source, self-hosted — no API costs, no vendor lock-in
  • Fine-tunable on proprietary RCS/CD-SEM screenshots
  • Low latency: local GPU inference vs. cloud API round-trips
