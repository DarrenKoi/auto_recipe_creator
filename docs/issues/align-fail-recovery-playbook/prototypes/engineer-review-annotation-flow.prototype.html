엔지니어 검토와 annotation 흐름

질문: 행동 수행자가 모든 클릭을 다시 설명하지 않아도, 하나의 검토 묶음이 Recovery Action 의미·모호한 Guard·분기 이유·Outcome·적용 범위를 보여 주고, 시스템이 묻는 최소 질문에 append-only annotation 으로만 답하며, Playbook 승인자의 승인이 annotation 과 분리된 기록으로 남는가?

성공 Recovery Episode 가 아직 0건이라 아래 Episode 는 필드 모양을 시험하기 위한 가상 자료입니다. frame 번호는 자리표시자이며 실제 이미지는 없습니다. 검토 묶음은 저장하는 정본이 아니라 recovery_episode.json + candidate Playbook + annotation 기록에서 매번 다시 만드는 파생 view 라는 가정을 깔고 있습니다(이 가정 자체가 검토 대상).

현재 상태

검토 묶음 (엔지니어가 보는 화면)

자유 실행

행동 수행자 (Recovery 를 실제로 한 엔지니어)

판독·분류 annotation 은 근거 frame/event 를 가리켜야 값을 바꿉니다. 근거가 없으면 rationale 로만 남습니다.

Playbook 승인자

승인자는 관측을 대신 판독하지 않습니다. 승인 / 근거 요청 / 반려 와 rationale 만 남깁니다.
