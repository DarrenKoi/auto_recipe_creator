## Slide 9. 기술 스택 + 인프라 요약

**기존 검증된 기술 스택 위에 채팅 UI와 세션 관리만 추가 — 새로운 기술 리스크 최소화**

| 계층 | 기술 | 역할 | 상태 |
|------|------|------|------|
| **GPU 서버** | H200 클러스터 + vLLM | VLM 추론 (Qwen3-VL) | 연결 필요 |
| **VLM 모델** | Qwen3-VL-30B-Instruct | 화면 인식 + 의사결정 | ✅ 확보 |

| **화면 캡처** | mss | 고속 스크린 캡처 (~10ms) | ✅ 구현 완료 |

✅ 비가역 작업 전 승인 게이트 (레시피 저장, 측정 실행, 삭제)

✅ 에러 다이얼로그 감지 → 즉시 중단 + 스크린샷 보고
✅ 모드 전환 즉시 반영 (< 100ms)

## Slide 12. 리스크 및 대응

**핵심 리스크를 사전 식별하고, 각 리스크에 대한 대응 전략을 이미 설계**

| **H200 GPU 할당 지연** | 중 | 높음 | 외부 API(Kimi-2 등) 백업 경로 확보, 경량 모델 대안 테스트 |
| **RCS UI 업데이트로 자동화 파손** | 낮 | 높음 | VLM 기반 → UI 변경에 강건함, 상태 재학습 프로세스 구축 |
| **엔지니어 수용성 부족** | 중 | 중 | Supervised 모드 시작 (강제 아닌 제안), 초기부터 피드백 반영 |
| **보안팀 협조 지연** | 중 | 중 | Host PC 기반 이미지 제어 → VM 내부 설치 불필요 |
| **복합 워크플로우 성공률 미달** | 중 | 중 | 단순 작업 먼저 안정화, 복합 작업은 SUPERVISED 모드로 보완 |
