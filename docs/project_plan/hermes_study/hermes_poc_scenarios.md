# Hermes Agent 오피스 PoC 시나리오 — 설계안

> 상태: **설계안(제안)**. 2026-07-01 작성. 착수 결정 아님.
> 전제: 오피스 = Claude 없음(로컬 GLM 5.2·Kimi-K2.6만), Hermes self-host. 관련 판단은
> `hermes_agent_feasibility.md`(특히 §7) 참조.
> 선정 원칙: 첫 Hermes 도입은 **비안전·읽기 위주 + 장비/RCS 무접촉**으로 리스크를 최소화하고,
> "로컬 모델 위 상시 에이전트"가 실제로 도는지부터 검증한다.

## 시나리오 1 — Consensus 수집 감시 · 일일 브리핑 봇 (프로젝트 인접, 비안전)

### 왜 이걸 고르나
workflow_3의 알려진 실제 pain은 **consensus history pool 적재 부족**이다. 첫 오피스 실행에서 join이
`8/193`밖에 안 됐고("worklist 채우려면 HISTORY_ROOT 적재가 레버"), consensus가 비면 조용히 rcp 폴백으로
성능이 떨어진다. 이건 **데이터 수집 운영 문제**라 제어 루프를 안 건드리고 **읽기 전용 리포팅**만으로 공략된다.
장비·RCS 무접촉이라 첫 Hermes 시험에 이상적이다.

### 하는 일
매일 아침 정해진 시각(cron)에:
1. `ALIGN_CONSENSUS_CACHE_DIR`(= `<root>/<class>/<recipe>/events/<event_id>/S*.jpeg`, eqp 무관)와
   `HISTORY_ROOT`를 스캔.
2. class·recipe·modality(OM/SEM)별 **수집된 S 프레임 수**를 집계, `min_s`(=3) 미만 recipe를 flag.
3. 라우팅 커버리지(consensus 적격 recipe 비율, 예의 `8/193` 지표)를 계산.
4. 전일 대비 증감(어제 스냅샷은 Hermes 메모리에 저장)과 **만성 미달 recipe Top-N**을 요약.
5. Slack/메일로 브리핑 발송(로컬 모델이 표+한 줄 코멘트 생성).

기존 자산 재활용: `poc/workflow_3/align/diagnostics/verify_consensus_path.py`가 이미 read-only로 `[DIGEST]`를
찍는다 → Hermes는 이 출력을 **스케줄링 + 집계 + 메모리 diff + 통지**로 감싸는 얇은 층.

### Hermes 기능 매핑
- **cron 스케줄러** → 매일 자동 실행(Claude Code엔 없는 배포형 상시성).
- **Python tool + skill** → 스캔/집계 스크립트를 skill로 저장, 포맷을 사용 중 자기개선.
- **3층 메모리** → 어제 커버리지 스냅샷 보관 → 증감·추세.
- **messaging gateway** → Slack/Telegram/메일 통지.
- **로컬 모델**(Kimi-K2.6 요약, GLM 스크립트 생성) → 오피스에서 Claude 없이 구동.

### 안전/리스크
- **읽기 전용 FS 스캔.** RCS·마우스·키보드·장비 무접촉. SAFE_MODE 무관.
- 최악의 실패 = "브리핑이 틀리거나 안 옴" → 사람이 원본 digest로 즉시 대조 가능.

### 성공 기준 (측정 가능)
- 5영업일 연속 07:30에 정확한 커버리지 표 자동 도착(수동 digest와 일치).
- `min_s` 미달 recipe 명단 정확도 100%(read-only라 결정론적, LLM은 문구만).
- 만성 미달 Top-N이 재등록/수집 우선순위 회의에 실제로 쓰임.

### 구현 단계 (PoC)
1. Hermes 설치 + GLM/Kimi 로컬 endpoint 연결(`hermes model`), Slack webhook 등록.
2. 스캔·집계 함수 작성(기존 `verify_consensus_path.py` 로직 래핑) → Hermes tool/skill 등록.
3. 어제-오늘 diff용 메모리 키 설계(커버리지 스냅샷).
4. cron 등록(매 영업일 07:30) + 통지 포맷 확정.
5. 5일 관찰 → 수동 digest와 대조.

### Claude Code로 안 되는 이유(오피스)
오피스에 Claude 없음 → Claude Code 미구동. 게다가 이건 **배포형 상시 cron 서비스 + 온프레 데이터**라
대화형 개발 도구의 형태가 아님.

### 확장 여지
- 재등록 worklist 리포트(`golden_reregister_report_cond.py`)와 합쳐 "수집↔재등록" 통합 주간 브리핑.
- 임계 미달이 오래가면 자동 에스컬레이션(담당 엔지니어 멘션).

## 시나리오 2 — 사내 SOP/매뉴얼 Q&A 봇 (프로젝트 무관, 범용)

### 왜 이걸 고르나
장비 SOP·설비 매뉴얼·사내 절차 문서는 방대하고, 엔지니어는 "이 상황에 뭐부터?"를 반복 질문한다. 이건
recipe creator와 무관한 **일반 지식 자동화**지만, Hermes의 차별 조합(RAG + 메모리/skill + messaging +
온프레 데이터)을 한 번에 실증하기 좋다. fab 문서는 반출 금지라 **온프레 self-host 모델**이 필수 —
정확히 Claude Code(클라우드)가 못 채우는 자리.

### 하는 일
1. 대상 문서 세트(설비 SOP, 장비 매뉴얼, 사내 위키 일부)를 로컬 인덱스로 구축.
2. 엔지니어가 Slack/Telegram 채널에서 자연어 질문.
3. Hermes가 인덱스에서 관련 구절 검색 → 로컬 GLM/Kimi로 **근거 인용 포함** 답변.
4. 답 못 하거나 문서에 없으면 "문서 없음"을 명시(환각 금지 게이트).
5. 자주 나온 Q&A를 **skill/메모리로 저장** → 반복 질문에 점점 빨라짐.

### Hermes 기능 매핑
- **RAG(검색+추출+요약)** + **MCP**(로컬 벡터 검색 서버 연동 가능).
- **3층 메모리 + 자율 skill** → FAQ 축적, 자기개선.
- **messaging gateway** → 엔지니어가 쓰던 Slack에서 바로.
- **완전 self-host + 로컬 모델** → fab 문서 온프레 유지, 반출 0.

### 안전/리스크
- **읽기 전용 인덱스 + 답변만.** 어떤 시스템도 조작 안 함.
- 핵심 리스크 = **환각**. → "문서 근거 없으면 답하지 않음" 게이트 + 항상 출처 표기(사내 문서 룰:
  layout→crop→recognize 정상경로, all-in-one 금지와 동일 철학). 안전-무관 정보성이라 오답도 사람이 검증.

### 성공 기준 (측정 가능)
- 상위 FAQ 20문항에서 **근거 인용 정답률 ≥ 목표치**(예 ≥ 85%), 환각(없는 사실) = 0 목표.
- 출처 링크가 실제 해당 문서 구절을 가리킴(스팟 검증).
- 2주 후 반복 질문 응답 시간 단축(skill 축적 효과 계측).

### 구현 단계 (PoC)
1. 소규모 문서 세트(1~2개 매뉴얼)로 시작 — 스코프 좁게.
2. 로컬 임베딩/검색 구성(사내에 OpenSearch+bge-m3 자산 있으면 재사용 검토, 없으면 경량 벡터 store).
3. Hermes에 검색 tool + "근거 없으면 답 금지" 프롬프트/skill 등록, GLM/Kimi 연결.
4. Slack 채널 봇 페어링.
5. FAQ 20문항 골든셋으로 정답률·환각 평가.

### Claude Code로 안 되는 이유(오피스)
문서 반출 금지 + 오피스 무 Claude → 클라우드 API 기반 Claude Code 부적합. 온프레 로컬 모델 봇만 가능.

### 확장 여지
- 온콜/인시던트 채널로 확장: 알람 로그가 뜨면 과거 유사 사례를 메모리에서 찾아 초기 대응 가이드 제시.
- 답변 만족도 피드백(👍/👎)을 메모리에 반영해 skill 품질 자기개선.

## 공통 유의 (두 PoC 모두)

- **기대치 = "비안전 잡무 자동화".** 자기개선 루프·답변 품질은 **구동 모델(GLM/Kimi)에 종속** — Claude 수준을
  기대하지 말고 골든셋으로 실제 품질부터 계측.
- **workflow_3 제어 루프와 물리적 분리.** Hermes는 RCS·장비를 절대 건드리지 않는다(read-only/통지/답변만).
- **모델 역할 분담(경험칙):** 구조화·스크립트·인용 정확도 = GLM, 요약·한국어 프로즈·추론 = Kimi-K2.6.
  PoC에서 문항별로 A/B해 확정.
- **성공하면** 다음 단계: 통지→가벼운 쓰기(예: 티켓 자동 생성) 순으로 권한을 **점진 확대**, 각 단계 게이트.
