# 00. 요약 (Summary)

## 1. 프로젝트 목적

계측 Lot을 운영하다 보면 Align Fail(정렬 실패)이 자주 발생하는데, 이를 AI로 무인 대응하는
것이 1차 목표입니다. Align Fail이 나면 장비가 멈추고, Line 구성원이 직접 장비에 접속해 정렬을
다시 맞춰야 재개됩니다.

- **발생 빈도**: 주 평균 약 400건.
- **As-Is (현재)**: Line 구성원이 직접 감지·접속·수동 재정렬 — 1건당 평균 5분.
- **To-Be (목표)**: AI가 감지부터 보정까지 무인 자동 대응 — 1건당 1분까지 단축(4분 감소).
- **효과**: 대응이 빨라진 만큼 회수되는 장비 가동 시간으로 주 WAFER 약 100장을 추가 측정할 수
  있습니다.

사람이 하던 "감지 → 장비 접속 → 정렬 재수정"을 AI가 대신 맡아 장비 idle 시간을 줄이고 계측
처리량을 회복하자는 것이 핵심입니다.

**왜 어려운가 (문제 정의):**

- **UI 자동화가 어렵습니다.** 대상 계측 클라이언트는 화면 요소가 표준 컴포넌트로 만들어져
  있지 않아, 일반적인 UI 자동화 도구가 버튼·입력창을 인식하지 못합니다. 그래서 화면을 이미지로
  보고 좌표를 찾아 클릭하는 방식이 필요합니다.
- **Align Fail은 근본적으로 되풀이되는 현상입니다.** 장비 recipe에 등록된 Align Key 이미지와
  실제 Wafer에 찍힌 Align Key 이미지 사이에 공정 Variation으로 인한 차이가 생기면서 발생합니다.
  특히 연구소 팹(R3)은 Split Lot이 많아 공정 조건이 다양한 탓에, 이런 차이가 자주 나타날 수밖에
  없습니다.
- 사람이 만든 화면에서 매번 조금씩 달라지는 Align Key를 찾아 정확한 좌표로 재정렬하려면 화면의
  의미 이해와 픽셀 단위 정밀도를 동시에 갖춰야 합니다.

## 2. PoC 핵심 방향 — VLM과 CV의 역할 분리

이 프로젝트가 처음부터 지켜 온 설계 원칙은 이렇습니다.

> **VLM(Vision Language Model, 화면을 이해하는 AI)은 "어디를 볼지"를 이해하고, CV(컴퓨터 비전)는
> "정확히 어디인지"를 정량적으로 결정합니다. 낮은 CV 점수를 VLM 답변이 덮어쓰거나, 반복 가능한
> 판단을 VLM이 임의로 결정하게 하지 않습니다.**

**왜 전부 VLM으로 대체하지 않는가 (CV를 함께 쓰는 이유):**

- VLM은 화면의 의미를 이해하는 데는 강하지만 **정확한 픽셀 좌표를 반복적으로 맞히는 데는 약합니다**
  (같은 화면을 봐도 답이 조금씩 흔들리고, 이전 화면을 기억하지 못합니다).
- Align 재정렬은 몇 픽셀만 어긋나도 실패하므로, 최종 좌표는 반복 가능하고 정량적인 CV가
  결정해야 합니다.
- 반대로 CV만으로는 "화면 어디에 무엇이 있는지, 지금 상황이 보정 가능한지"를 판단하기 어려운데,
  이 부분을 VLM이 맡습니다.
- 화면 이해를 거대 단일 모델 하나에 전부 맡기면 하드웨어 비용도 비현실적입니다(§4 참조).

| 구분 | 담당 | 이유 |
|------|------|------|
| **VLM** | "어디를 볼까" — UI 요소 위치, Align Key 후보 영역, 촬영 모드 판독, 모호성 설명 | 화면 의미 이해에 강함. 단, 픽셀 정확도·기억 한계 |
| **CV** | "얼마나 닮았나 / 정확히 어디" — 이미지 매칭 점수, 최종 클릭 좌표 | 반복 가능·정량적. VLM의 픽셀 한계를 보완 |

이렇게 역할을 나눈 덕분에 화면 이해(VLM)와 정밀 좌표(CV)를 각자의 강점에 맡겨 무인 자동화의 신뢰도를 확보했습니다.

## 3. 설계 흐름 (Design Flow)

전체 시스템은 아래 4단계 흐름으로 설계·구축했습니다.

1. **VLM 인프라 확보** — 화면을 이해할 오픈소스 소형 모델을 조사·선정해 자사 HCP(Hybrid Cloud
   Platform)에 설치하고, 하나의 통합 API로 운영합니다.
2. **GUI 자동화 가능성 증명** — 표준 컴포넌트가 아닌 계측 화면에서도 VLM으로 좌표를 찾아 안정적으로
   클릭할 수 있음을 증명합니다(대략 위치 → 정밀 좌표 → 확인의 다단계 파이프라인).
3. **정렬 정확도 확보** — Align Key 매칭 정확도를 오프라인 평가 환경에서 A/B·튜닝해 검증된
   방식만 채택합니다.
4. **실시간 통합 루프** — 위 세 가지를 하나로 묶어 알람 감지부터 자동 보정·기록까지 무인으로 도는
   실시간 루프를 구축합니다(현재 주력).

## 4. 핵심 성과 (Highlights)

- **VLM 인프라 자체 확보**: 화면 좌표 인식과 문자 인식(OCR)에 필요한 능력을 자사 HCP에 GPU 1~2장
  규모의 소형 오픈소스 모델(화면 이해 VLM 3종 + OCR 2종)로 나눠 배포했습니다. 대규모 GPU가 필요한
  단일 거대 모델 없이도 사내에서 자체 구동하며, 외부 의존 없이 기반기술센터가 직접 서비스할 수 있는
  역량을 갖췄습니다.
- **GUI 자동화 가능성 증명**: 단일 모델로는 마우스·버튼 위치 지정 같은 조작이 불안정했지만, 소형
  모델 두 개를 단계적으로 조합하니(대략 위치 → 정밀 좌표) 표준 컴포넌트 인식 없이도 계측 화면
  좌표를 안정적으로 클릭하고 OCR로 클릭 결과까지 확인할 수 있었습니다.
- **정렬 정확도 개선**: recipe에 처음 등록된 Align Key만 쓸 때보다 최근 성공 사례를 종합한 기준
  이미지를 썼을 때 Align Key 탐색 정확도가 크게 올랐습니다(오프라인 평가 기준: 후보 포함률
  0.434 → 0.876, 1순위 적중률 0.318 → 0.764). 다만 이 수치는 오프라인 평가 기준이고, 오피스
  실데이터 현장 검증은 진행 예정입니다(실제 운영에서는 성공 사례를 더 많이 요구하는 보수적 기준을
  적용합니다).
- **실시간 통합 루프 구현**: 알람 감지 → 장비 접속 → 자동 보정 → 실패 시 담당자 알림 → 상시 녹화 →
  자동 종료로 이어지는 end-to-end 무인 루프를 구축했습니다.

## 5. 기대 효과 (Business Impact)

| 항목 | 값 | 비고 |
|------|-----|------|
| 대상 장비 수 | **28대** | 계측 장비 |
| 주 평균 Align Fail 발생 건수 | **약 400건/주** | 정렬 실패 알람 기준 |
| 1건당 수동 대응 시간 (감지~보정) | **평균 5분** | 현재 구성원 대응 |
| 완전 자동화 시 대응 지연 | **5분 → 1분** | 4분 감소 |
| 연간(주간) 절감 환산 | **주 WAFER 약 100장 추가 측정** | 장당 15분 가정 |

- 환산 근거: 「400건/주 × 4분 단축 ÷ 15분/장 ≈ 주 100장」에 해당하는 장비 가동 시간을 회수해
  추가 측정에 쓸 수 있습니다.
- 정량 효과 외에 야간·주말 무인 모니터링·보정, 실패 시점 화면 증거의 자동 보존(원인 분석 시간
  단축), 수집 데이터의 학습 자산화 같은 정성적 효과도 있습니다.

## 6. 확장성 (Scalability)

- **적은 자원으로 다수 장비 커버**: 무거운 단일 거대 모델 없이 소형 모델을 조합해, 비교적 적은
  자원(GPU 1~2장 규모)으로 28대 규모의 모니터링을 감당하도록 설계했습니다.
- **데이터 자산화**: 상시 녹화 기능으로 엔지니어가 장비를 직접 컨트롤하는 과정까지 프레임으로
  저장·분석·Data화해 향후 VLM 학습 자료로 활용합니다.
- **지속적 정확도 개선**: 녹화 데이터와 정렬 성공 사례를 꾸준히 쌓아 정렬 재수정 정확도를 계속
  끌어올립니다. 같은 recipe면 장비가 달라도 성공 이력을 공유하도록 설계해, 신규 장비로 확대할 때
  추가 작업이 최소화됩니다.

## 8. 예상 허들 (Risks)

- **정확도 수치의 현장 검증 갭**: 정렬 정확도는 오프라인 벤치 기준으로, 오피스 실데이터 검증에서
  달라질 수 있습니다(확정 전에는 보수적 기준 운영).
- **성공 이미지 적재가 선행 조건**: 성공 사례 기반 보정은 Recipe별 성공 이미지가 쌓여야 효과를
  내며, 수집 기능 구현이 활성화 조건입니다.
- **재등록이 필요한 Recipe**: 헷갈리기 쉬운 위치에 등록된 정렬 키는 알고리즘 개선만으로 풀리지 않아,
  엔지니어와 협의한 재등록이 필요합니다.
- **VLM 서버 가용성**: 서버 메모리 제약과 재시작 시 재설치 소요(약 3~4시간)가 무인 운영의 가용성
  리스크입니다.

바랍니다.
