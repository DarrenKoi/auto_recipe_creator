# 01. VLM 인프라 확보 — 사내 HCP 오픈소스 소형 모델 배포

> 목적: 자사 **HCP(Hybrid Cloud Platform)** 에 오픈소스 **소형 LLM/VLM**을 직접 배포하여 프로젝트에
> 활용합니다. 화면을 이해하고(VLM) 화면의 텍스트를 읽는(OCR) 능력을 사내 자원으로 확보하는 단계입니다.

## 1. 설치한 모델 (5종)

SOTA(최신 최고 성능)급 모델을 중심으로 모두 **5종**을 골라 내려받아 설치했습니다. 화면을 이해하는
**VLM 3종**과 텍스트를 읽는 **OCR 2종**입니다.

| 구분 | 모델 | 역할 |
|------|------|------|
| VLM | **UI-Venus** | 대략 위치 인식 — 전체 화면에서 타겟 UI의 대략 영역 |
| VLM | **MAI-UI** | 정밀 좌표 — 대략 영역을 확대해 픽셀 단위 클릭점 결정 |
| VLM | **UI-TARS** | 단일 모델 화면 조작(Action) 대안 — 좌표 정확도 문제로 현재 비활성 |
| OCR | **PaddleOCR-VL** | 화면 텍스트 읽기 — 클릭 결과 검증 |
| OCR | **GOT-OCR** | 보조 OCR — 좁힌 영역 재판독 |

## 2. 단일 모델의 한계 (평가에서 확인한 점)

처음에는 화면 조작까지 하나의 모델(GUI 조작형 단일 모델)에 맡겨 봤습니다. 하지만
**단일 모델은 마우스 위치 인식이나 버튼 위치 지정 같은 Action 기능을 안정적으로 해내지 못했습니다.**

- 클릭 좌표가 실제 대상에서 어긋나는 **좌표 shift**가 나타났습니다.
- 반복해 돌릴수록 **오류율이 높아져**, 무인 자동화에 필요한 신뢰도를 확보하기 어려웠습니다.

## 3. 해결 — 2개 소형 모델의 coarse → fine 방식

한 모델에 다 맡기는 대신 **소형 모델 두 개를 단계적으로 사용**해, 클릭 위치를 2번에 걸쳐
좁혀 잡도록 했습니다.

- **1단계 · 대략 위치 (UI-Venus)**: 전체 화면에서 목표 UI가 있는 **대략의 영역**을 빠르게 찾습니다.
  넓은 화면을 한눈에 훑어 후보 영역을 잡는 데 강합니다.
- **2단계 · 정밀 좌표 (MAI-UI)**: 그 영역만 잘라 **확대**한 뒤 **픽셀 단위의 정확한 클릭 지점**을
  결정합니다. 좁은 영역에서 세밀하게 위치를 짚는 일에 능합니다.

작은 화면으로 좁혀 두 번 판단한 덕분에, 단일 모델에서 나타나던 좌표 어긋남을 크게 줄였습니다.

- **OCR 검증**: 클릭이나 입력을 한 뒤 화면의 텍스트를 OCR로 읽어 **의도한 대로 클릭·입력됐는지 확인**합니다.
  확인되지 않으면 다시 시도해 무인 신뢰도를 높입니다.

## 4. 사내 HCP 설치 구성과 제약

모델은 사내 HCP에 직접 올려 GPU 1~2장 규모로 돌립니다. 운영하면서 확인한 **제약 사항**은
다음과 같습니다.

- **가용 시스템 메모리 16GB 제약**: 할당된 시스템 메모리가 16GB에 불과해, **여러 장의 이미지를 한꺼번에
  처리하거나 API를 잦게 호출하는 작업은 어렵습니다.**
  - 여러 장 이미지 처리가 필요한 대표 사례: **녹화된 화면 이미지를 정리해 지식 자산화**하는 작업.
- **서버 재시작 시 재설치 부담**: HCP 서버가 재시작되면 VLM 구동 환경 패키지를 매번 새로 깔아야
  하고, 여기에 **약 3~4시간**이 걸립니다.

## 5. 확보한 역량

- HCP 서버 안에서 **Flask로 여러 VLM 모델을 함께 운영하는 knowhow**를 쌓았습니다.
- 외부에 기대지 않고 **자체적으로 모델을 구동해 기반기술센터 안에서 서비스할 수 있는 역량**을 갖췄습니다.

## 6. 향후 계획

- **GPU 1~2장으로 돌릴 수 있는 소형 LLM/VLM**도 빠르게 발전하고 있습니다.
- 주기적으로 SOTA 모델을 살펴보다가 더 나은 것이 나오면 **교체·업그레이드**하겠습니다.
