# 02. GUI 자동화 검증 (workflow 1) — RCS 자동 조작 및 CCTV 캡처 PoC

> 목적: **RCS(Remote Control System)** 는 장비 제어로 들어가는 첫 관문(Gateway)입니다. 장비
> 자동화에 앞서 VLM이 RCS를 직접 조작할 수 있는 환경부터 갖춰야 합니다. 이 단계에서는 RCS
> GUI 자동화와, Align Fail 시점을 기록하기 위한 CCTV 캡처의 실현 가능성을 평가했습니다. 현재는
> 동결(frozen) 상태이며, 운영 경로는 실시간 통합 루프(04 문서)로 옮겼습니다.

## 1. As-Is → To-Be

이 단계에서 자동화로 바꾸려는 대상과, 검증한 목표 상태는 다음과 같습니다.

| 항목 | As-Is (사람 수동) | To-Be (이 단계에서 검증한 자동화) |
|------|------------------|----------------------------------|
| RCS 조작 | 엔지니어가 직접 로그인하고 장비 목록에서 대상 장비를 찾아 접속 | VLM이 화면 좌표를 찾아 로그인 → 장비 선택 → 대응 화면 진입까지 자동 수행 |
| 알람 확인 | 사람이 알람을 수시로 확인 | 1~2분 주기로 자동 확인, 정렬 실패 알람만 선별(중복·지연 보고 처리) |
| 실패 시점 기록 | 기록이 남지 않아 원인 분석 시 재현이 어려움 | Align Fail 시점 화면을 자동 캡처·저장 |

검증 결과: RCS 자동 조작은 클릭·타이핑 정확도 90% 이상으로 가능성을 증명했고(§3), CCTV 기반
기록 추출은 한계를 확인해 중단했습니다(§5). 검증된 자동화의 운영은 실시간 통합 루프(04 문서)로
이관했습니다.

## 2. 검증한 자동화 파이프라인

VLM으로 RCS를 자동 조작하는 파이프라인을 구현하고 평가했습니다.

1. **로그인 & 탐색** — RCS를 실행해 로그인한 뒤 장비 목록으로 들어갑니다.
2. **정렬 실패 알람 감지** — 계측 알람을 1~2분 주기로 확인해 정렬 실패 알람만 골라냅니다. 중복
   알람이나 뒤늦게 보고되는 알람도 놓치지 않습니다.
3. **대응 화면 진입** — 감지된 장비에 접속해 대응 화면으로 이동합니다.
4. **알림 & 로그** — 처리 결과는 팝업과 로그로 남기고, 같은 장비에서 중복으로 뜨는 알람은 해제한
   뒤 재발할 때만 다시 알립니다.

여기에 더해 Align Fail 시점의 기록을 확보하려고 CCTV 캡처도 함께 평가했습니다(§5 한계 참조).

## 3. 핵심 확보 기술

RCS는 화면 요소가 표준 컴포넌트로 만들어져 있지 않아, 일반 UI 자동화 도구로는 버튼이나 입력창을
인식하지 못합니다. 그래서 화면을 이미지로 보고 좌표를 찾는 VLM 방식으로 구현했습니다.

- **Coarse + Crop & Zoom (2단계 좌표 인식)**: 전체 화면에서 대략적인 위치를 먼저 잡고(Coarse), 그
  영역을 잘라 확대(Crop & Zoom)한 뒤 정밀 좌표를 정합니다. 이 방식으로 VLM 버튼 클릭·키보드
  타이핑 정확도 90% 이상을 확보했습니다.
- **재시도 & fallback**: 실패하면 재시도하고, 그래도 안 되면 대체 경로(fallback)로 넘어가도록 해
  무인 신뢰도를 높였습니다.
- **OCR 확인**: 클릭·입력 후 화면 텍스트를 OCR로 읽어 의도대로 됐는지 검증합니다.
- **이미지 크기 보정(rescale)**: recipe에 등록된 이미지 크기와 RCS의 Tool Monitor에 실제로 표시되는
  이미지 크기가 달라(등록 이미지보다 작게 표시됨) 좌표가 어긋날 수 있습니다. 두 크기의 비율로
  rescale 보정 변환을 구현해 클릭 좌표를 맞췄습니다.

## 4. 데이터 자산화

- **성공 align 이미지 저장**: Align Fail이 잦은 recipe는 엔지니어가 수동으로 작업해 성공한 align
  이미지를 저장해 둡니다. 이후 같은 recipe에서 Align Fail이 재발하면 VLM이 참고할 자료로 씁니다.
- **엔지니어 작업 기록 저장**: 엔지니어의 작업 과정(마우스 이동·클릭·장비 컨트롤 등)을 이미지로
  캡처해 저장합니다. 앞으로 필터링을 거쳐 VLM 학습에 쓸 수 있는 형태로 변환할 계획입니다
  (Langgraph 기반 워크플로우).

## 5. 한계와 배운 점

- **CCTV 기록 추출의 복잡성**: CCTV로 과거 기록을 뽑아 워크플로우로 만들어 보려 했지만, CCTV
  화면을 추출하는 과정이 복잡해 구현에 시간이 오래 걸렸습니다. 가능성만 확인한 채 추가 평가는
  중단했습니다.
- **개선 방향**: RCS의 녹화 자료가 저장되는 DB에 직접 접속해 파일을 추출하는 방식이 필요합니다.
- **배운 점**: GUI "화면 읽기"가 곧 Align Key "찾기"는 아니며, Align Key 정밀 매칭은 CV의 영역입니다.
  또한 모든 단계를 VLM 호출에만 의존하면 비용과 지연 부담이 커집니다.

## 6. 동결(frozen) 사유

- 운영 화면 자동화는 유지보수를 일원화하기 위해 실시간 통합 루프(04 문서)로 옮겼습니다.
- 이 단계에는 CCTV 관련 실험과 초기 데이터가 남아 있습니다.
