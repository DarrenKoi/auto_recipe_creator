# Align Fail 무인 대응 Agent — 업무 보고서

> 대상: R3 CD-SEM 계측 장비 28대 / 작성 기준일: 2026-09-03

---

## 1. 해결하려는 업무 문제

### 1.1 대상 업무

R3 연구소 팹의 CD-SEM(계측) 장비 28대에서 발생하는 **Align Fail(정렬 실패) 대응** 업무입니다.

계측 장비는 Wafer를 측정하기 전에 Recipe에 등록된 Align Key(정렬 기준 이미지)를 실제 Wafer
화면에서 찾아 좌표를 맞춥니다. 이 정렬에 실패하면 장비는 그 자리에서 멈춥니다. 사람이 들어가 정렬을 다시 맞춰 줄 때까지
측정이 재개되지 않습니다.

- 발생 빈도: **주 평균 약 400건**
- 대상 알람: Smart Alarm System 알람코드 **9006 (Align Fail)**

### 1.2 기존 업무 방식 (As-Is)

| 단계 | 현재 수행 방식 |
|------|----------------|
| 감지 | Line 구성원이 알람 화면을 눈으로 확인 |
| 접속 | RCS(Remote Control System)를 실행·로그인해 해당 장비 화면에 원격 접속 |
| 판단 | 멈춘 화면을 보고 Align Key가 어디 있는지 육안으로 탐색 (필요 시 배율 변경) |
| 보정 | 해당 위치로 화면을 재조정한 뒤 확정(OK) |
| 기록 | 별도 기록 없음 — 무엇이 왜 실패했는지 남지 않음 |

**1건당 평균 대응 시간은 5분**(감지~보정)입니다. 이 시간 전체가 장비 idle 시간입니다.

### 1.3 주요 불편 / 병목

1. **장비 가동률 손실이 곧바로 발생합니다.** 주 400건 × 5분 = 주당 약 33시간의 계측 장비
   idle이 사람의 반응 속도에 묶여 있습니다.
2. **야간·주말에는 대응이 지연됩니다.** 감지 자체가 사람의 확인에 의존합니다. 무인 시간대에는
   알람이 떠도 다음 근무자가 볼 때까지 장비가 멈춰 있습니다.
3. **반복성 단순 작업이 숙련 인력의 시간을 소모합니다.** 대응 절차 자체는 정형화돼 있습니다.
   다만 화면 판단이 필요해 위임이 어렵습니다.
4. **원인이 축적되지 않습니다.** 실패 시점의 화면 증거가 남지 않아 "어떤 Recipe가 만성적으로
   실패하는지"를 사후에 분석할 수 없습니다.
5. **근본적으로 되풀이되는 현상입니다.** 공정 Variation으로 등록 Align Key와 실제 Wafer
   이미지가 달라지면서 발생합니다. Split Lot이 많은 연구소 팹 특성상 빈도가 구조적으로 높습니다.

### 1.4 이 업무에 AI가 필요한 이유

- **일반 UI 자동화 도구가 동작하지 않습니다.** 계측 클라이언트 화면이 표준 컴포넌트로 만들어져
  있지 않아 버튼·입력창이 프로그램적으로 인식되지 않습니다. **화면을 이미지로 보고 좌표를 찾는
  방식(VLM)** 외에는 자동화 경로가 없습니다.
- **정답이 매번 조금씩 다릅니다.** 공정 Variation 탓에 화면의 Align Key가 등록 이미지와
  픽셀 단위로 일치하지 않습니다. 고정 좌표·고정 템플릿 스크립트로는 풀리지 않습니다.
  **유사도를 정량 판단하는 CV**가 필요합니다.
- 즉 "화면의 의미 이해"와 "픽셀 단위 정밀도"가 동시에 필요한 업무입니다. 규칙 기반
  자동화의 사각지대입니다.

## 2. 제작 내용

### 2.1 설계 원칙 — VLM과 CV의 역할 분리

> **VLM은 "어디를 볼지"를 이해하고, CV는 "정확히 어디인지"를 정량적으로 결정합니다.**
> 낮은 CV 점수를 VLM 답변이 덮어쓰지 못하게 하고 반복 가능한 판단을 VLM이 임의로
> 결정하게 두지 않습니다.

| 구분 | 담당 | 이유 |
|------|------|------|
| VLM | UI 요소 위치, Align Key 후보 영역, 촬영 모드 판독, 모호성 설명 | 화면 의미 이해에 강함 (단, 픽셀 정확도·기억 한계) |
| CV | 이미지 매칭 점수, 최종 클릭 좌표 | 반복 가능·정량적 |

이 분리 덕분에 GPU 1~2장 규모의 **소형 오픈소스 모델**(화면 이해 VLM + OCR)만으로 28대 규모를
감당합니다. 모델은 자사 HCP에 자체 배포·운영하며 외부 의존이 없습니다.

### 2.2 주요 기능

| # | 기능 | 내용 |
|---|------|------|
| 1 | 실시간 알람 감지 | 10초 주기로 Smart Alarm System을 조회해 Align Fail(9006)만 선별, 신규 발생 시점에만 1회 발동 |
| 2 | RCS 자동 접속 | RCS 실행·로그인·장비 목록 탐색·해당 장비 접속을 무인 수행. RCS가 떠 있지 않으면 자동 재실행·재로그인 |
| 3 | 오클릭 차단 게이트 | 장비 목록에서 클릭할 행만 잘라 OCR로 대상 장비 ID를 확인. 확인되지 않으면 클릭하지 않음 |
| 4 | 성공 사례 기반 자동 보정 | 최근 정렬 성공 이미지를 종합한 기준으로 위치를 찾아 재조정. 성공 이미지가 부족하면 등록 이미지로 자동 폴백 |
| 5 | 촬영 모드 자동 판독 | 화면에서 저배율(OM)/고배율(SEM)을 직접 읽어 해당 모드 기준 이미지로 매칭. 읽지 못하면 추측하지 않고 보류 |
| 6 | 다배율 탐색 | 정렬 위치가 화면에 없으면 배율을 낮춰 격자 탐색 후 접근 |
| 7 | 보정 가능 여부 판정 | 비슷한 후보가 많아 근본적으로 헷갈리는 Recipe는 "Align Key 재등록 권고"로 기록 |
| 8 | 상시 화면 녹화 | 대응 전 구간을 프레임으로 저장. 엔지니어가 직접 조작한 구간도 함께 기록 |
| 9 | 엔지니어 작업 감지 | 엔지니어가 직접 재정렬에 나서면 감지해 자동 감시를 종료하고 장비 창을 닫음 (조작 충돌 방지) |
| 10 | 결과 알림(Cube) | 감지 직후 사전 고지 1회, 대응 종료 후 결과 1회 발송 |
| 11 | 대응 1건 = 기록 1줄 | 어느 단계에서 끝났고 결과가 무엇인지 집계 가능한 형태로 적재 (Recovery Episode) |
| 12 | 점검 전용 모드 | 실제 보정 없이 접속 → 화면 1장 캡처 → 판정 → 종료만 수행하는 진단 모드 |

### 2.3 작동 흐름

```
[10초 주기 폴링] Smart Alarm System — ALID 9006 조회
        │
        ▼ (신규 Align Fail 감지)
  담당자 사전 고지 (Cube)  ─ "자동화가 이 장비를 잡습니다"
        │
        ▼
  RCS 실행 → 로그인 → 장비 목록에서 대상 장비 행 확인(OCR 게이트) → 접속
        │                                     └─ 병렬: 과거 정렬 성공 이미지 수집
        ▼
  상시 화면 녹화 시작
        │
        ▼
  화면 캡처 → SEM 화면 영역 검출 → 촬영 모드(OM/SEM) 판독
        │
        ▼
  CV 매칭: 성공사례 기준 이미지(우선) / 등록 이미지(폴백) → 보정 가능 여부 판정
        │
        ├─ 판정 가능 ──▶ 정렬 위치 재조정(자동)  ──▶ ★ 확정(OK)은 엔지니어 ★
        ├─ 모드 불명 ──▶ 보정 보류, 엔지니어에게 인계
        ├─ 위치 모호 ──▶ 에스컬레이션 + 재등록 권고 기록
        └─ 타인 점유 ──▶ 화면 공유 요청 후 관전 녹화 / 쿨다운 후 재시도
        │
        ▼
  결과 알림 (Cube) — 성공 외의 모든 결과는 반드시 발송
        │
        ▼
  뒷정리 보장(try/finally): 녹화 종료 → 장비 창 닫기 → 팝업 정리
        │
        ▼
  Recovery Episode 기록 1줄 적재 → 다음 알람 대기
```

**설계상의 안전 규약 3가지**

1. **뒷정리는 어떤 예외에서도 수행합니다.** 중간 단계가 실패해도 녹화 종료·창 닫기·팝업 정리는
   순서대로 끝까지 수행해 장비를 항상 깨끗한 상태로 되돌립니다.
2. **확인되지 않으면 클릭하지 않습니다(fail-closed).** 좌표는 VLM이 찍고 그 자리의 라벨을 OCR로 읽습니다.
   확인된 경우에만 실제 클릭이 나갑니다.
3. **관측 실패를 실패로 단정하지 않습니다.** 화면을 못 본 경우는 "판정 불명"으로 남겨
   불필요한 에스컬레이션이나 잘못된 "성공" 보고로 새지 않게 했습니다.

### 2.4 최종 산출물

| 구분 | 산출물 |
|------|--------|
| 실행 시스템 | 실시간 Align Fail 무인 대응 Agent (알람 감지~보정~기록 end-to-end 루프) |
| | 점검 전용 모드 (비파괴 진단 진입점) |
| 인프라 | 자사 HCP 상의 VLM/OCR 서비스 (통합 API, 소형 모델 상시 2종 운영) |
| 정확도 검증 환경 | 오프라인 A/B 평가 하니스 — 정렬 알고리즘 변경을 실장비 없이 사전 검증 |
| 운영 산출 데이터 | 대응 1건당 Recovery Episode 기록 1줄 (시도 횟수·판정 근거·결과) |
| | Align Fail 시점 화면 증거 + 대응 전 구간 녹화 영상 |
| | Align Key **재등록 권고 Recipe 목록** (현업 협의용) |
| 지식 자산 | 엔지니어 조작 녹화 → 조작 타임라인 → 한국어 절차서 변환 경로 |
| 문서 | 운영 Runbook, 설계 문서·ADR, 진행 보고서 |

### 2.5 사용자 검토 / 승인 절차

**(1) 운영 중 — 매 건 단위의 사람 확정 (반자동 설계)**

되돌릴 수 없는 조작만 사람에게 남겼습니다.

| 단계 | 수행 주체 | 근거 |
|------|-----------|------|
| 장비 접속·화면 확보·판정 | 자동 | 되돌릴 수 있는 조작 |
| 정렬 위치 재조정(reposition) | 자동 | 되돌릴 수 있는 조작 |
| **최종 확정(OK 버튼)** | **엔지니어** | 잘못된 확정은 측정 결과에 그대로 영향 |

보정을 마치면 시스템은 완료가 아닌 **"확정 대기(awaiting engineer OK)"** 상태로 종료하고
담당 엔지니어에게 Cube 알림을 보냅니다. 이 상태를 성공과 별도로 둔 이유가 있습니다.
성공으로 처리하면 알림이 생략되어 "OK를 눌러 달라"는 요청이 조용히 사라집니다. 엔지니어가 확정을 누르는
장면까지 녹화가 계속되어 사후 확인이 가능합니다.

**(2) 이상 시 — 즉시 중단 + 사람 호출**

- 보정 이후 측정 과정을 계속 감시하다 오측이 감지되면 **즉시 측정을 중단**하고 Cube 알람을
  보냅니다.
- 촬영 모드 판독 실패, 정렬 위치 모호, 타인 점유 등 자동 판단이 서지 않는 모든 경우는
  자동 조작을 포기하고 엔지니어에게 인계합니다.
- 엔지니어가 직접 개입하면 자동화는 감시를 종료하고 물러납니다.
- 긴급 정지 단축키로 진행 중인 조작을 즉시 중단할 수 있습니다.

**(3) 확대 적용 승인 절차 (단계적 게이트)**

```
점검 모드(비파괴) 검증 ─▶ 첫 실알람 대응을 엔지니어 입회하에 관찰
   ─▶ 단일 장비 pilot ─▶ 현업 엔지니어 합동 평가 ─▶ 다장비 확대
```

각 게이트는 이전 단계의 Recovery Episode 기록으로 근거를 남기고 통과 여부를 판단합니다.
현재는 **첫 실알람 완주 확인 대기** 단계입니다.

## 3. 업무 변화 및 효과

### 3.1 업무 변화 (As-Is → To-Be)

| 항목 | As-Is (사람 수동 대응) | To-Be (무인 자동 대응 Agent) |
|------|------------------------|------------------------------|
| 감지 | 구성원이 알람 화면을 확인 | 10초 주기 자동 확인, 9006만 선별 |
| 접속 | 수동 RCS 실행·로그인·장비 탐색 | 자동 접속 (RCS 부재 시 자동 재실행) |
| 보정 | 육안 탐색 후 수동 재정렬 | 성공사례 기반 자동 재조정, 확정만 사람 |
| 실패 대응 | 사람이 발견할 때까지 지연 | 즉시 담당자 알림 + 오측 감지 시 측정 중단 |
| 기록 | 없음 | 화면 증거 + 대응 전 구간 녹화 + 대응 1건 = 기록 1줄 |
| 야간·주말 | 사실상 미대응 | 동일하게 무인 대응 |
| 1건당 대응 시간 | 평균 5분 | 목표 1분 |
| 엔지니어 역할 | 감지~보정 전 과정 수행 | **확정·예외 판단만** 수행 |

### 3.2 정량 효과

| 항목 | 값 |
|------|-----|
| 대상 장비 | 28대 (R3 CD-SEM) |
| 주 평균 Align Fail | 약 400건 |
| 1건당 대응 시간 | 5분 → 1분 (**4분 단축**) |
| 주당 회수 장비 시간 | 400건 × 4분 ≈ **약 27시간/주** |
| 환산 효과 | **주 WAFER 약 100장 추가 측정** (장당 15분 기준) |

> 산출 근거: 400건/주 × 4분 ÷ 15분/장 ≈ 100장/주

### 3.3 정성 효과

- **야간·주말 무인 대응**: 사람의 근무 시간에 묶여 있던 감지·대응이 24시간 균질해집니다.
- **원인 분석 시간 단축**: 실패 시점의 화면 증거가 자동 보존되므로 사후 재현 없이 원인을
  분석합니다.
- **개선 지점의 데이터화**: 어느 단계에서 실패가 몰리는지 자동 집계됩니다. 다음 개선 순서를
  감이 아닌 분포로 정합니다.
- **만성 실패 Recipe의 가시화**: 알고리즘으로 풀리지 않는 Align Key(헷갈리기 쉬운 위치에
  등록된 Recipe)를 재등록 권고 목록으로 뽑아 현업과 근본 개선을 협의할 수 있습니다.
- **암묵지 자산화**: 숙련 엔지니어의 조작 과정을 녹화·절차화해 학습 자산으로 축적합니다.
  입력 후킹 없이 화면만 관측해 동의 범위를 코드로 고정했습니다.
- **자체 AI 운영 역량 확보**: 외부 API 의존 없이 사내 HCP에서 화면 이해 AI를 직접 배포·벤치·
  교체하는 체계를 확보했습니다. 동일 구조를 다른 장비 UI 자동화로 확장할 수 있습니다.

### 3.4 확장성

- 소형 모델 조합 구조라 GPU 1~2장 규모로 28대를 감당합니다. 장비 증설 시 추가 GPU 부담이
  선형으로 늘지 않습니다.
- 정렬 성공 이력을 **Recipe 단위(장비 무관)로 공유**하도록 설계했습니다. 신규 장비를 추가해도
  기존 학습 자산을 그대로 씁니다.
- 알람 종류를 추가하는 확장 경로(예: 측정 연속 실패 시 자동 중단)를 기존 루프 수정 없이
  얹을 수 있는 구조로 분리했습니다.

### 3.5 현재 상태 및 남은 관문

| 영역 | 상태 |
|------|------|
| VLM 인프라 배포·운영 | ✅ 운영 중 |
| GUI 자동화 + 화면 증거 캡처 | ✅ 검증 완료 |
| CV 정렬 정확도 평가 환경 | ✅ 활성 (오피스 실데이터 검증 대기) |
| 실시간 루프(감지·접속·보정·녹화·알림) | ✅ 개발 완료 |
| 실장비 반자동 보정 | ✅ 개통 · 🟡 첫 실알람 완주 대기 |
| 실패 회복 기록 계층 | ✅ 구현 완료 · 🟡 첫 오피스 기록 대기 |
| 지식 자산화(녹화 → 절차서) | ✅ 녹화 확보 · 🟡 추출 미실행 |
| 현업 합동 평가 | 🟡 예정 |

**남은 주요 관문**

1. **개통과 완주는 다릅니다.** 실보정 경로는 열렸으나 실제 Align Fail 알람에서 끝까지 완주한
   사례가 아직 없습니다. 첫 완주는 엔지니어 입회하에 관찰합니다.
2. **정확도의 현장 검증 갭.** 정렬 정확도 수치는 오프라인 평가 기준입니다. 확정 전까지는
   보수적 기준으로 운영합니다.
3. **성공 이미지 적재가 선행 조건.** 성공사례 기반 보정의 효과는 Recipe별 성공 이미지 축적이
   전제입니다.
4. **재등록이 필요한 Recipe.** 남은 개선 여지의 상당 부분이 알고리즘이 아닌 Align Key 재등록
   몫으로 확인됐습니다. 현업 협의가 필요합니다.
5. **엔지니어 PC 배포 방식.** 대상 PC에 개발 도구가 없어 더블클릭 실행 형태의 배포 방식 결정이
   남아 있습니다.
