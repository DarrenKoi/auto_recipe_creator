# 06. 오피스 별도 확인 기술 — Headless 장비 제어 · Recipe 외부 수정/주입

> 목적: 저장소 밖에서(오피스) 별도로 진행·확인한 두 가지 기술을 정리합니다. 둘 다 지금의
> GUI 기반 자동화가 가진 구조적 한계를 걷어 내는 기반 기술입니다.

> 최종 갱신: 2026-10-30. 두 기술 모두 **오피스에서 가능성을 확인한 단계**이며, 실시간 대응
> 루프(workflow_3)에 연결하는 작업은 다음 단계입니다. 정량 수치는 아직 집계 전이라 적지 않았습니다.

## 1. Headless 장비 제어 — RCS 화면 없이 마우스·키보드 제어

### 무엇을 확인했나

- **RCS를 화면에 띄우지 않고(headless) 장비의 마우스·키보드를 제어**할 수 있음을 확인했습니다.
- 장비 화면은 **background로 계속 전달**받습니다. 따라서 VLM이 화면을 보고 상황을 인지하는
  지금의 방식은 그대로 유지됩니다. 바뀌는 것은 "입력을 어떻게 넣느냐"뿐입니다.

### 왜 중요한가 — 지금 방식의 한계

지금의 GUI 자동화는 Agent가 RCS 창을 실제 모니터에 띄워 놓고, 그 화면을 캡처해 VLM이
읽은 뒤 **로컬 마우스·키보드를 직접 움직여** 조작합니다. 이 구조 때문에 다음 문제가
계속 따라왔고, 이를 막는 장치를 하나씩 덧대 왔습니다.

| 지금 방식의 문제 | 그동안 덧댄 대응 | Headless 제어 시 |
|------|------|------|
| 가동 중 Agent가 PC 화면·커서를 점유 | 엔지니어는 같은 PC를 쓰지 않도록 운영 | 같은 PC에서 엔지니어 작업 병행 기대(루프 연결 후 확인) |
| 다른 창이 장비 창을 가리면 잘못된 화면을 캡처 | 가림 감지 게이트, 가려지면 대기 후 재확인 | 화면을 background로 받으므로 가림 문제가 줄어들 것으로 기대 |
| 로컬 커서와 장비 쪽 커서가 어긋남(drift) | 커서 동기화 점검 도구, 축별 허용치 | 로컬 커서를 거치지 않음 |
| 원격 입력 지연으로 클릭 입력이 반영되지 않음 | 클릭 전 대기·누름 유지 시간 상수 | 입력 지연과 필요한 대기 시간을 다시 측정 예정 |
| 화면 해상도·DPI 배율에 따라 좌표 보정 필요 | 창 크기/캡처 크기 비율로 좌표 환산 | 장비 좌표계로 직접 지정 가능성(확인 예정) |

### 다음 단계

1. 실시간 루프(workflow_3)의 입력 계층을 headless 경로로 바꿀 수 있게 교체 지점을 하나로
   모읍니다. 화면 판독(VLM)·좌표 결정(CV)·확인(OCR)의 역할 분리는 그대로 둡니다.
2. 같은 알람 대응을 기존 방식과 headless 방식으로 각각 돌려 결과와 소요 시간을 비교합니다.
3. 상시 운영 PC에 headless 방식으로 올리고, 단일 장비 pilot에 적용합니다.

## 2. CD-SEM Recipe 구조 분석과 외부 수정·주입

### 무엇을 확인했나

- CD-SEM 장비를 **reverse engineering**하여 **recipe 파일 구조**를 파악했습니다.
- 파악한 구조를 바탕으로 **장비 밖에서 recipe를 수정하고, 이를 장비에 다시 주입**하는 방법을
  확보했습니다.
- 이 방식은 **Thickness 장비에서 현재 진행 중인 방식과 같은 접근**입니다. 즉 장비군이 달라도
  "구조 파악 → 외부 수정 → 주입"이라는 같은 틀로 적용할 수 있음을 CD-SEM에서도 확인한 것입니다.

### 왜 중요한가

- **GUI를 거치지 않는 recipe 편집 경로**가 생깁니다. 지금은 recipe를 바꾸려면 사람이(또는
  Agent가) 장비 화면 메뉴를 하나씩 눌러야 합니다. 외부 수정·주입이 되면 화면 조작 없이 파일
  단위로 변경할 수 있습니다.
- **Align Key 재등록 과제와 연결**됩니다. 03 문서의 오프라인 벤치에서 재순위 반영 후 남은
  실패의 약 87%는 정답이 후보 목록에 없는 경우였고, 이를 바탕으로 재등록을 추진하고 있습니다.
  재등록 대상 recipe 목록은 이미 자동으로 뽑고 있으므로, Align Key 관련 항목과 적용 절차를
  확인한 뒤 재등록 작업까지 연계할 수 있습니다.
- **2027년 목표(VLM이 Recipe Tuning을 직접 수행)의 실행 수단**이 됩니다. VLM·CV가 판단한
  값을 화면 조작이 아니라 recipe 수정으로 반영하는 길이 열립니다.

### 다음 단계와 주의점

1. recipe 구조 중 Align Key 관련 항목(등록 이미지·위치·배율 등)의 범위를 정리합니다.
2. 수정한 recipe를 주입하기 전에 **원본 백업 → 변경 내용 대조 → 담당 엔지니어 승인**을
   거치는 절차를 먼저 정합니다. recipe 변경은 측정 결과에 직접 영향을 주므로, Align Fail 보정과
   같은 단계적 활성화(관찰 → 사람 승인 → 단일 장비 → 확대)를 그대로 따릅니다.
3. Thickness 장비 쪽 진행 방식과 절차·도구를 맞춰 두 장비군이 같은 틀을 공유하게 합니다.

## 3. 두 기술이 합쳐지면

| 구분 | 지금 | 두 기술 적용 후 |
|------|------|------|
| 화면 인지 | 실제 모니터에 띄운 RCS 창을 캡처 | background로 전달받은 화면을 VLM이 인지 |
| 장비 조작 | 로컬 마우스·키보드로 화면을 직접 조작 | headless 입력 |
| Recipe 변경 | 장비 화면 메뉴를 사람이 조작 | 외부에서 수정 후 주입 |
| 운영 PC | Agent 가동 중 점유 | 엔지니어와 공유 |

정리하면 **Agent가 "화면 앞에 앉은 사람"을 흉내 내던 방식에서, 화면은 보되 입력과 recipe
변경은 장비에 직접 넣는 방식**으로 옮겨 갈 기반을 확보했습니다.
