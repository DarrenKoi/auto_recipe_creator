## 1. 사례 요약

### 한 줄 요약

R3 연구소 팹의 CD-SEM 계측 장비 28대에서 주 400건씩 발생하는 **Align Fail(정렬 실패)** 을,
사람이 알람을 보고 원격 접속해 5분씩 수동으로 고치던 방식에서 **AI가 감지·접속·재정렬까지
무인으로 수행하고 최종 확정만 사람이 누르는 방식**으로 바꾼 사례입니다.

### Story

계측 장비는 웨이퍼를 측정하기 전에 Recipe에 등록된 기준 이미지(Align Key)를 실제 웨이퍼
화면에서 찾아 좌표를 맞춥니다. 공정 변동으로 등록 이미지와 실제 화면이 조금씩 달라지면 장비는
정렬에 실패하고 **그 자리에서 멈춥니다**. Split Lot이 많은 연구소 팹에서는 이 실패가 주 400건에
이릅니다.

멈춘 장비를 다시 움직이려면 Line 구성원이 알람을 눈으로 확인하고, RCS(Remote Control System)를
실행해 로그인하고, 장비 목록에서 해당 장비를 찾아 접속하고, 멈춘 화면에서 Align Key 위치를
육안으로 찾아 재조정한 뒤 확정을 눌러야 합니다. 1건당 평균 5분, 그 5분은 전부 장비 idle
시간입니다. 야간과 주말에는 다음 근무자가 볼 때까지 장비가 그대로 멈춰 있습니다.

이 일을 자동화하지 못했던 이유는 두 가지였습니다. 첫째, 계측 클라이언트 화면이 표준 UI
컴포넌트로 만들어져 있지 않아 **일반 RPA·UI 자동화 도구가 버튼을 인식하지 못합니다**. 둘째,
Align Key는 매번 조금씩 다르게 찍히므로 **고정 좌표·고정 템플릿 스크립트로는 풀리지 않습니다**.
"화면의 의미를 이해하는 능력"과 "픽셀 단위 정밀도"가 동시에 필요한 일이라 규칙 기반
자동화의 사각지대였습니다.

우리는 이 두 벽을 **AI와 CV의 역할 분리**로 넘었습니다. 화면을 이해하는 소형 VLM(Vision
Language Model)이 "어디를 볼지"를 결정하고, OCR이 "정말 그 버튼이 맞는지"를 확인하고, 컴퓨터
비전 매칭 엔진이 "정확히 몇 픽셀인지"를 정량적으로 결정합니다. VLM의 답이 낮은 CV 점수를
덮어쓰지 못하게 하고, 확인되지 않은 클릭은 절대 나가지 않게 했습니다.

그 결과 **알람 감지 → 담당자 사전 고지 → RCS 자동 접속 → 상시 녹화 → 촬영 모드 판독 → 성공
사례 기반 자동 재정렬 → 결과 알림 → 자동 종료 → 대응 기록 1줄 적재**가 사람 없이 한 루프로
돕니다. 마지막 확정(OK)만 엔지니어가 누릅니다. 되돌릴 수 없는 조작이기 때문입니다.

### 핵심 포인트와 AI의 역할

| 구분 | 내용 |
|------|------|
| **문제** | 주 400건 × 5분 = **주 약 33시간의 장비 idle** 이 사람의 반응 속도에 묶여 있었고, 야간·주말은 사실상 미대응. 표준 UI가 아니라 기존 자동화 도구로는 손댈 수 없었음 |
| **해결** | 사내 HCP에 자체 배포한 소형 VLM(화면 좌표 인식) + OCR(클릭 확인) + CV 매칭 엔진(정밀 좌표)의 **역할 분리 구조**로 감지~재정렬 무인 루프 구축. 되돌릴 수 없는 확정만 사람에게 남긴 **반자동(Supervised Autonomy)** 설계 |
| **성과** | 정렬 위치 1순위 적중률 **0.318 → 0.764** (오프라인 벤치, 등록 이미지 1장 → 성공 사례 종합) `[검증]`. 장비 목록·버튼 인식 정확도 **1.000** `[검증]`. 실알람 **3건 완주, 1건당 대응 시간 5분 → 1분 미만** 실측 `[검증]`. 이를 주 400건에 적용하면 **주 약 27시간 장비 시간 회수, 주 WAFER 약 100장 추가 측정** 환산 `[목표]`. 2026-08 실장비 반자동 보정 개통, 2026-09 현업 배치 시작 |

**AI가 맡은 것 / 맡지 않은 것을 명확히 나눈 것**이 이 사례의 핵심입니다.

- AI(VLM)가 맡음: 화면에서 UI 요소 위치 찾기, 라이브 SEM 화면 영역 검출, 촬영 모드(저배율/고배율)
  판독, 정렬 후보 영역 식별, 모호한 상황 설명.
- AI(OCR)가 맡음: 클릭하려는 자리의 라벨을 읽어 "의도한 대상이 맞는지" 확인. 확인 안 되면 클릭 금지.
- CV 엔진이 맡음: 기준 이미지와 실제 화면의 유사도 점수, 최종 재정렬 좌표(픽셀).
- 사람이 맡음: 최종 확정(OK), 자동 판단이 서지 않는 예외(모드 불명·위치 모호·타인 점유)의 처리.

## 2. 사례 상세

### 2.1 해결하려는 업무 문제와 현업 필요성

- **대상 업무**: R3 CD-SEM 계측 장비 28대의 Align Fail(Smart Alarm 코드 9006) 대응.
- **발생 빈도**: 주 평균 약 400건. 공정 변동으로 등록 Align Key와 실제 웨이퍼 이미지가 달라져
  생기는 **구조적으로 되풀이되는 현상**입니다. 연구소 팹은 Split Lot이 많아 빈도가 더 높습니다.
- **현업 필요성**: 장비 1대가 멈추면 그 Lot 전체의 측정이 밀립니다. 대응은 정형화된 절차지만
  화면 판단이 필요해 위임이 어렵고, 숙련 인력이 반복 작업에 시간을 씁니다. 실패 시점의 화면이
  남지 않아 "어떤 Recipe가 만성적으로 실패하는지" 사후 분석도 불가능했습니다.

### 2.2 기존 방식의 비효율·반복·편차·장애 요인

| 단계 | 기존 수행 방식 | 비효율 요인 |
|------|----------------|-------------|
| 감지 | 구성원이 알람 화면을 눈으로 확인 | 사람의 확인 주기에 의존, 야간·주말 지연 |
| 접속 | RCS 실행·로그인·장비 목록 탐색·접속 | 매 건 반복되는 단순 조작 |
| 판단 | 멈춘 화면에서 Align Key 육안 탐색(배율 변경 포함) | 숙련도 편차, 헷갈리는 Key는 사람도 오판 |
| 보정 | 화면 재조정 후 확정 | 위치 정밀도가 사람 손에 좌우 |
| 기록 | 없음 | 원인·재발 Recipe 축적 불가 |

이 5분 전체가 장비 idle이며, 주 400건이면 **주 약 33시간**입니다.

### 2.3 AI 적용을 위해 거친 주요 과정과 새로운 시도

프로젝트는 2026년 1월 요구사항 정의에서 시작해 4단계로 진행했습니다.

**① VLM 인프라 자체 확보 (2026-02~03)**
외부 API에 기대지 않고 사내 HCP(Hybrid Cloud Platform)에 오픈소스 소형 모델을 직접 배포했습니다.
화면 이해 VLM 3종(MAI-UI, UI-Venus, UI-TARS)과 OCR 2종(PaddleOCR-VL, GOT-OCR)을 설치해 비교
평가하고, Flask 통합 API 한 곳으로 라우팅했습니다. 실제 업무 화면 벤치로 **이긴 모델만 남겨
2종 상시 운영**으로 정리했습니다. 모델 교체를 감이 아닌 측정으로 결정하는 체계를 함께 갖췄습니다.

**② GUI 자동화 가능성 증명 (2026-03~05, workflow_1)**
단일 GUI 조작형 모델에 클릭까지 맡겨 봤지만 좌표가 어긋나고 반복할수록 오류가 늘었습니다. 그래서
**판단을 2단계로 나눴습니다**: 전체 화면에서 대략 영역을 찾고(coarse), 그 영역만 잘라 확대해
정밀 클릭점을 정하고(fine), 클릭 전 그 자리의 라벨을 OCR로 읽어 확인(confirm)합니다. 표준
컴포넌트 인식 없이도 로그인·탭 이동·장비 선택·화면 캡처·창 닫기를 안정적으로 수행할 수 있음을
오피스 실장비에서 확인했습니다.

**③ 정렬 정확도 확보 — 오프라인 A/B 벤치 (2026-05~07, workflow_2)**
Recipe 200개의 등록 이미지와 과거 Align Fail 이미지를 내려받아 실장비를 건드리지 않는 평가
환경을 만들었습니다. 정답 좌표는 사람 라벨이 아니라 등록 당시 조건 정보로 산출하고, 성공 이미지로
기준을 만들 때 평가 대상은 빼는 교차검증을 적용했습니다. 여기서 검증된 방식만 운영 루프에
포팅한다는 규율을 지켰습니다. 시도한 아이디어 8가지 중 2가지(성공 사례 종합, 촬영 모드별 재순위)만
채택했고, 나머지 6가지(관심 영역 축소, 개별 보관 방식, 윤곽선 채널, 이중 종합, 십자선 제거 등)는
데이터로 기각했습니다.

**④ 실시간 통합 루프 (2026-06~, workflow_3)**
위 셋을 하나로 묶어 알람 감지부터 기록까지 무인으로 도는 루프를 구축했습니다. 2026-08 실장비
반자동 보정을 개통했고, 8~9월에는 실패 회복 과정을 기록하는 관측 계층(Recovery Episode)과 판정
로직을 별도 계층(workflow_4)으로 분리했습니다.

**새로운 시도 3가지**

1. **성공 사례 종합(consensus) 기준 이미지**: 처음 등록한 이미지 1장 대신 최근 정렬 성공 이미지
   여러 장을 위치 맞춰 합성해 "지금의 웨이퍼 외관을 따라가는" 기준을 만들었습니다. 이것 하나로
   1순위 적중률이 2배 이상 올랐습니다. 같은 Recipe면 장비가 달라도 성공 이력을 공유합니다.
2. **촬영 모드별 심판 전환**: 저배율(OM)과 고배율(SEM)에서 서로 다른 재순위 심판이 이긴다는 것을
   A/B로 발견했습니다. 처음엔 심판들을 투표로 섞었는데 성적이 떨어졌습니다. 한 심판이 특정 국면을
   지배할 때는 "종합"이 아니라 "전환"이 옳다는 것을 데이터로 확인하고 구성을 바꿨습니다.
3. **암묵지 자산화 경로**: 알람이 없어도 엔지니어의 수동 조작을 화면만 관측해 녹화하고, 이를
   조작 타임라인 → 한국어 절차서로 바꾸는 경로를 만들었습니다. 입력 후킹은 하지 않고 화면만 보도록
   동의 범위를 코드에 고정했습니다.

### 2.4 적용 과정의 난이도·제약·극복 방식

| 난이도·제약 | 극복 방식 |
|-------------|-----------|
| 계측 클라이언트가 표준 UI가 아니라 pywinauto 등 자동화 도구가 컨트롤을 인식 못함 | 화면 이미지 → VLM 좌표 → OCR 확인 → 클릭의 이미지 기반 제어로 전환 |
| 단일 VLM은 클릭 좌표가 어긋나고 반복 시 오류 증가 | coarse → fine 2단계 + OCR confirm 게이트. 확인 안 되면 클릭하지 않는 fail-closed 원칙 |
| VLM 서버 시스템 메모리 16GB 제약, 재시작 시 재설치 3~4시간 | 진짜 제약은 GPU가 아니라 프로세스 수임을 확인. 안 쓰는 모델은 내리는 운영 원칙, 5종 → 2종 상시 운영. 실시간 루프는 판정 대부분을 CV로 처리해 VLM 호출 최소화 |
| Align Key는 픽셀 동일성을 가정할 수 없음(공정 변동) | 구조·기하 기반 매칭 + 여러 매칭 방식 종합(Ensemble/RRF) + 성공 사례 consensus. 임계값은 성공·실패 점수 분포로 통계적 보정 |
| 고배율 SEM은 화면 대부분이 반복 패턴이라 진짜 위치와 헷갈리는 가짜 후보가 많음 | 잔여 실패 87%가 "정답이 후보에 아예 없는" 경우임을 분해로 확인. 알고리즘으로 풀리지 않는 몫은 **Align Key 재등록 권고 Recipe 목록**으로 현업에 전달 |
| 개발은 Mac, 실행은 오피스 Windows. 개발 PC에서 실장비·RCS를 볼 수 없음 | 협력자 주입 설계로 실장비 없이 검증 가능한 테스트 1,207개 확보. 재생(replay) 절차로 알람 없이 사이클 강제 실행. 오피스 실행은 콘솔 digest 한 줄로 결과 회수 |
| 실장비 클릭은 오동작 시 측정에 영향 | 점검 모드(비파괴) → 반자동(확정은 사람) → 단일 장비 pilot → 확대의 단계적 게이트. 뒷정리(녹화 종료·창 닫기·팝업 정리)는 어떤 예외에서도 보장 |
| 다른 엔지니어가 장비를 점유 중일 수 있음 | 점유 3상태 판별, 화면 공유 요청 후 관전 녹화, 쿨다운 후 재시도. 엔지니어 개입 감지 시 자동화가 물러남 |
| 개통 후 보정 단계가 한 번도 실행되지 않고 있었음(화면 영역 캘리브레이션 요구) | 점검 모드에서 검증된 라이브 화면 영역 검출을 보정 경로에도 적용해 병목 제거. 같은 검출에서 촬영 모드도 읽어 "모든 화면을 SEM으로 가정"하던 조용한 오류 제거 |

### 2.5 소요 기간과 추진 속도

| 시기 | 단계 | 산출 |
|------|------|------|

### 2.6 조직·회사에 미친 실질적 영향과 확산 가능성

- **장비 가동 시간 회수**: 1건당 5분 → 1분 미만(실알람 3건 실측). 주 400건에 적용하면 주 약 27시간,
  WAFER 약 100장/주 추가 측정 환산 `[목표]`.
- **엔지니어 역할 전환**: 감지~보정 전 과정 수행 → **확정과 예외 판단만** 수행.
- **야간·주말 대응 균질화**: 사람의 근무 시간에 묶여 있던 감지·대응이 24시간 동일해집니다.
- **데이터 자산 신설**: 실패 시점 화면 증거, 대응 전 구간 녹화, 대응 1건 = 기록 1줄(Recovery
  Episode), 재등록 권고 Recipe 목록. 개선 순서를 감이 아닌 실패 분포로 정합니다.
- **자체 AI 운영 역량**: 외부 API 의존 없이 사내 HCP에서 화면 이해 AI를 배포·벤치·교체하는 체계.
- **확산 가능성**:
  - 소형 모델 조합이라 GPU 1~2장 규모로 28대를 감당하고, 장비 증설 시 GPU 부담이 선형으로 늘지 않음.
  - 성공 이력이 Recipe 단위(장비 무관)로 공유되어 신규 장비 추가 시 기존 자산을 그대로 사용.
  - 알람 종류를 추가하는 확장 경로를 기존 루프 수정 없이 얹는 구조(예: 측정 연속 실패 시 자동
    중단 job이 이미 같은 구조 위에 구현됨).
  - "표준 UI가 아닌 레거시 클라이언트의 이미지 기반 자동화" 패턴 자체가 다른 장비·시스템에 재사용
    가능. 2027년에는 Recipe Tuning 자동화로 확장 예정.

  게이트마다 근거를 남기고 통과 여부를 판단합니다.
- **되돌릴 수 있는 설계**: 재순위·탐색 엔진·성공 사례 기준 등 주요 변경마다 kill switch가 있어
  회귀 시 즉시 이전 동작으로 복귀합니다.
- **문서화**: 진행 보고서 6편, 설계 스펙·ADR, 운영 Runbook, 이슈 트래커가 저장소에 함께 관리됩니다.

  출력과 진행 보고서를 추가할 수 있습니다.

### 3.6 업무 난이도와 혁신의 의미

- 일반 RPA가 원리상 불가능한 대상(비표준 UI + 매번 달라지는 정답)을 AI로 열었습니다.
- "AI에 다 맡기지 않는다"는 원칙으로 신뢰도를 확보했습니다. VLM은 이해, OCR은 확인, CV는 좌표,
  사람은 확정. 이 분리가 거대 모델 없이 GPU 1~2장으로 28대를 감당하게 한 이유이기도 합니다.
- 시도한 개선안의 대부분을 데이터로 **기각**했고, 남은 개선 여지의 87%가 알고리즘이 아닌 Align Key
  재등록 몫임을 밝혀 현업 협업 과제로 전환했습니다. 기술로 풀 것과 사람이 풀 것을 가른 것 자체가
  성과입니다.

## 4. SKMS 기본 정신 측면 서술

> 각 정신의 정의는 팀이 공식 SKMS 문구로 한 번 대조해 주십시오. 아래는 사례와의 연결점입니다.

- **안정과 성장**: 실장비 클릭은 오동작 시 측정에 영향을 줍니다. 그래서 점검 모드(비파괴) →
  반자동(확정은 사람) → 단일 장비 pilot → 확대의 단계적 게이트를 두고, 어떤 예외에서도 뒷정리를
  보장하고, 확인되지 않은 클릭은 나가지 않게 했습니다. 안정을 해치지 않는 방식으로만 자동화 범위를
  넓혀 왔습니다.
- **Commitment**: 2026년 1월 요구사항 정의부터 9월까지 7.5개월간 1,409건의 변경을 이어 왔습니다.
  "개통과 완주는 다르다"고 스스로 적어 두고 첫 실알람 완주를 다음 관문으로 명시했으며, 실알람 3건
  완주를 확인한 뒤 현업 배치로 넘어갔습니다.
- **패기**: 처음 접근한 단일 GUI 조작 모델이 실패했을 때 포기하지 않고 판단을 2단계로 쪼개는
  구조로 돌파했습니다. 보정 단계가 한 번도 실행되지 않고 있었다는 불편한 사실을 발견했을 때도
  덮지 않고 원인을 찾아 제거했습니다.
- **SUPEX**: 정렬 정확도 개선안 8가지를 모두 A/B로 검증하고, 이긴 것만 남겼습니다. "이 정도면
  됐다"가 아니라 남은 실패를 원인별로 분해해 87%가 어디에 있는지까지 확인했습니다. 모델 교체도
  감이 아니라 벤치로 결정합니다.
- **Teamwork**: 개발은 Mac, 실행은 오피스 Windows라는 분리된 환경에서 협력자 주입 설계와 digest
  한 줄 회수 방식으로 협업 리듬을 만들었습니다. 알고리즘으로 풀리지 않는 Recipe는 재등록 권고
  목록으로 현업 엔지니어에게 넘겨, 자동화 팀과 현업이 함께 푸는 과제로 정의했습니다. 엔지니어가
  개입하면 자동화가 물러나도록 설계한 것도 사람과 AI의 협업 규칙입니다.
- **솔선수범**: 외부 솔루션을 기다리지 않고 오픈소스 소형 모델을 사내 HCP에 직접 배포해 기반기술센터가
  스스로 서비스하는 역량을 만들었습니다. 다른 장비·시스템 자동화가 따라 쓸 수 있는 패턴(이미지 기반
  제어, 역할 분리, 단계적 게이트)을 먼저 만들어 문서로 남겼습니다.

## 5. Operation Improvement with AI 서술

### 5.1 기존 프로세스의 불편함

| 유형 | 내용 |

### 5.2 AI로 인한 변화 지점

| AI 기능 | 적용 지점 |
|---------|-----------|
| **탐지** | 10초 주기 알람 폴링에서 Align Fail(9006)만 선별하고 신규 발생 시점에 1회 발동. 화면에서 라이브 SEM 영역 검출. 엔지니어 개입(측정 품질 표·카운터·창 닫힘) 감지. 타인 점유 팝업 감지 |

### 5.3 개선 효과

- **처리 시간**: 1건당 5분 → 1분 미만(실알람 3건 실측), 주 400건 기준 약 27시간 장비 시간 회수 환산.
- **정확도**: 정렬 위치 1순위 적중률 0.318 → 0.764(2.4배), UI 요소 인식 1.000 `[검증]`.
- **가용성**: 야간·주말 무인 대응, RCS 부재 시 자동 재실행·재로그인.
- **품질**: 확인 안 된 클릭 금지, 모드 불명 시 보류, 오측 감지 시 즉시 중단으로 잘못된 보정이
  측정에 흘러가는 경로 차단.
- **지식**: 실패 화면·녹화·기록 1줄·재등록 목록이 자동 축적되어 다음 개선의 근거가 됨.
- **사람의 역할**: 반복 조작에서 벗어나 **확정과 예외 판단**에 집중.
