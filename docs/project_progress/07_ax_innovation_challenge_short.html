1. 사례 요약

R3 연구소 팹 CD-SEM 26대의 Wafer In-line 측정 시 Align Fail(정렬 실패)이 주 400~500건 발생합니다. 현업 담당자가 RCS(Remote Control System, 장비 원격 제어 프로그램) 모니터를 24시간 감시하다 멈춘 장비에 접속해 1건 5분씩 고치던 일을 AI Agent가 감지·접속·재정렬·기록까지 무인으로 수행하도록 바꾼 사례입니다. 감지에서 위치 재조정까지 걸리는 시간은 1분 미만으로 줄었습니다.

문제. 계측 장비는 측정 전에 Recipe(측정 설정)에 등록된 기준 이미지(Align Key)를 실제 웨이퍼 화면에서 찾아 좌표를 맞춥니다. 공정 변동으로 등록 이미지와 실제 화면이 조금씩 달라지면 장비는 정렬에 실패하고 그 자리에서 멈춥니다. Split Lot이 많은 연구소 팹에서는 이 실패가 전체 측정의 약 5%에 이릅니다. 멈춘 장비를 다시 움직이는 절차는 정형화되어 있지만 전부 현업 담당자 손을 탑니다. Fab 인라인 구성원과 엔지니어가 RCS 모니터를 24시간 교대로 감시하다 멈춘 장비를 발견하면 접속해, 멈춘 화면에서 Align Key를 배율을 바꿔가며 육안으로 찾아 재조정합니다. 1건당 평균 5분, 그 5분은 전부 장비 idle입니다. 주 400건이면 주 약 33시간의 계측 장비 시간이 현업 담당자의 반응 속도에 묶여 있었습니다. 실패 화면도 남지 않아 어떤 Recipe가 만성적으로 실패하는지 근거로 분석할 수 없었습니다.

그동안 자동화하지 못한 이유는 둘입니다. 계측 클라이언트 화면이 표준 UI 컴포넌트가 아니라 일반 RPA·UI 자동화 도구가 버튼을 인식하지 못하고, Align Key는 매번 조금씩 다르게 찍혀 고정 좌표·고정 템플릿으로는 풀리지 않습니다. 화면의 의미를 이해하는 능력과 픽셀 단위 정밀도가 동시에 필요한, 규칙 기반 자동화의 사각지대였습니다.

해결. 열쇠는 AI에 다 맡기지 않고 역할을 나눈 것입니다. 처음에는 화면을 이해하는 VLM(Vision Language Model) 하나에 클릭까지 맡겼지만 좌표가 어긋나고 반복할수록 오류가 늘었습니다. 그래서 VLM은 "어디를 볼지"(UI 요소 위치, 라이브 화면 영역, 촬영 모드), OCR은 "정말 그 버튼인지"(라벨을 읽어 대조하고 확인이 안 되면 클릭하지 않음), CV(Computer Vision) 매칭 엔진은 "정확히 몇 픽셀인지"(기준 이미지와 라이브 화면의 유사도와 재정렬 좌표)를 맡도록 나누고, 뒤 단계가 앞 단계의 답을 검증하게 연결했습니다. 현업 담당자는 예외 판단과, 지금 단계에서는 최종 확정(OK)을 맡습니다. VLM의 답이 낮은 CV 점수를 덮어쓰지 못하고 확인에 실패한 클릭은 나가지 않는다는 원칙을 코드에 고정했습니다. 화면 이해는 사내 HCP(모델 운영 플랫폼)에 자체 배포한 소형 오픈소스 모델이 맡고 반복 정밀 판정은 CV가 맡으므로, 거대 모델이나 외부 API 없이 GPU 1~2장 규모로 26대를 모니터링합니다.

그 결과 알람 감지(10초 폴링) → 담당자 사전 고지 → RCS 자동 접속 → 상시 녹화 → 화면·촬영 모드 판독 → 성공 사례 기반 자동 재정렬 → 확정 → 완료 감시·자동 종료 → 대응 기록 1줄 적재가 한 루프로 돕니다. 보정이 불가능하거나 다른 엔지니어가 장비를 쓰고 있으면 원인과 요구 행동을 담아 알리고 물러납니다. 정확도는 실장비를 건드리지 않는 오프라인 벤치(Recipe 200개)에서 A/B로 확보했고, 데이터로 이긴 개선안 2가지만 운영에 반영했습니다. 그 뒤 남은 실패의 약 87%는 정답이 후보에 아예 없는 유형이라 알고리즘이 아니라 Align Key 재등록이라는 현업 과제로 정의했습니다.

성과. 건당 대응 시간이 5분에서 1분 미만으로 줄어 1건에 4분의 장비 시간이 돌아옵니다(실알람 3건 실측 [검증]). 주 400건이면 약 27시간/주이고, 웨이퍼 1장 측정에 15분이 든다고 보면 매주 약 100장을 더 측정할 수 있습니다. 이를 장비로 환산하면 약 0.2대 분이며, 1대 약 20억 원으로 추산하면 Capex 약 4~5억 원 절감에 해당합니다 [목표]. 현업 담당자는 24시간 모니터를 감시하다 접속해 육안으로 찾는 일에서 벗어나 예외 판단만 맡고, 대응 1건마다 화면 증거와 기록 1줄이 남아 만성 실패 Recipe 를 근거로 골라낼 수 있습니다.

2.1 업무 문제와 기존 방식의 한계

대상 업무. R3 CD-SEM 26대의 Align Fail(Smart Alarm 9006) 대응입니다. 정렬이 실패하면 장비는 진행을 멈추고 현업 담당자가 조치할 때까지 홀드됩니다. R3는 연구소 팹이라 Lot Split과 공정 Variation이 많아 등록 이미지와 실제 웨이퍼 이미지가 달라지는 일이 구조적으로 되풀이됩니다.

현업 필요성. 장비 홀드는 뒤에 선 Lot 전체를 기다리게 해 계측 WIP과 연구소 팹의 개발 속도를 지연시킵니다. Fab 인라인 구성원과 MI 엔지니어가 RCS 모니터를 24시간 교대로 감시하는 데 묶여 있고, 화면을 보고 판단하는 단계가 있어 숙련자의 시간이 반복 작업에 들어갑니다. 실패 시점 화면이 남지 않아 어떤 Recipe의 Align Key를 재등록해야 하는지 근거로 판단하기 어려웠습니다.

기존 방식의 비효율. 감지는 현업 담당자의 감시 주기에 의존해 야간·교대 인계 구간에 지연되고, 접속은 매 건 같은 조작을 반복하지만 비표준 UI라 기존 자동화 도구가 붙지 않습니다. Align Key 육안 탐색과 재조정 정밀도는 숙련도에 좌우되며 반복 패턴이 많은 고배율 화면은 현업 담당자도 오판합니다. 기록이 없어 개선 우선순위를 감으로 정했습니다.

2.2 AI 적용 과정과 구현한 기능

2026년 1월 요구사항 정의에서 시작해 네 단계로 진행했습니다.

① 화면 이해 AI 확보(02~03월, 운영 구성 확정 08월). 외부 API에 기대지 않고 Hugging Face 오픈웨이트 VLM 3종(MAI-UI, UI-Venus, UI-TARS)과 OCR 2종(PaddleOCR-VL, GOT-OCR)을 사내 HCP에 설치하고 통합 API 한 곳으로 라우팅해 벤치 결과로 바꿔 끼울 수 있게 했습니다. 장비 제조사가 소수 엔지니어용으로 만든 화면은 버튼이 오밀조밀해 현업 담당자도 조작이 어려운데, 실제 업무 화면 비교에서 소형 모델 MAI-UI가 가장 높은 성공률을 보였습니다(좌표 인식+클릭 500회 99% [검증]). VLM 1종 + OCR 1종 상시 운영으로 정리했습니다.

② 장비 원격 제어(RCS) 자동화(03~05월). 단일 모델이 한 번에 좌표를 찍는 방식은 확률적으로 실패했습니다. 전체 화면에서 대략 영역을 찾고(coarse), 잘라 확대해 정밀 클릭점을 정하고(fine), 클릭 전 그 자리의 라벨을 OCR로 읽어 확인(confirm)하는 3단계로 바꿨습니다. RCS 실행·로그인·탭 이동·장비 선택·화면 캡처·창 닫기를 이 방식으로 자동화해 오피스 실장비에서 안정적으로 수행함을 확인했습니다.

③ 정렬 정확도 확보: 오프라인 A/B 벤치(05~07월). Recipe 200개의 등록 이미지와 과거 실패 이미지로 실장비를 건드리지 않는 평가 환경을 만들고, 여기서 이긴 방식만 운영에 반영했습니다. 채택한 것은 둘입니다. 성공 사례 종합(consensus) 기준 이미지는 등록 1장 대신 최근 정렬 성공 이미지 여러 장을 합성한 것으로, 같은 Recipe면 장비가 달라도 공유하며 rank-1을 31.8%에서 76.4%로 올렸습니다. 촬영 모드별 후보 재평가는 저배율(OM)과 고배율(SEM)에서 이기는 심판이 달라 모드에 따라 전환하는 방식으로 SEM rank-1을 약 7.3%p 더 올렸습니다.

④ 실시간 통합 루프(06월~). Align Fail 알람을 사내 data-hub에 적재하고 h-api를 10초 간격으로 조회하는 수신 기반을 만든 뒤 ①~③을 묶어 감지부터 기록까지 무인으로 도는 루프를 구축했고, 08월 실장비 보정을 개통했습니다. 구현한 기능은 다음과 같습니다.

기능 구현 내용
알람 감지·사전 고지 10초 주기로 알람을 조회해 Align Fail만 선별, 신규 발생 시 1회 발동. 담당자에게 "AI 가 대응 시작" 큐브 알림

2.3 난이도와 극복

대응 시간. 시스템이 알람을 감지한 시점부터 AI가 장비 화면에서 정렬 위치를 다시 맞춘 시점까지입니다. 현업 담당자가 하던 감시·접속·탐색·재조정이 1분 안으로 들어왔습니다. 3건은 표본이 작아 운영 성공률로 일반화하지 않고 26대 배치에서 건별로 계속 기록합니다.

정렬 정확도. 멈춘 화면에서 AI가 고른 위치가 실제 정답과 맞는지를 과거 실패 화면 수백 장으로 채점했습니다. 처음에는 Recipe에 등록된 기준 이미지 1장과 단순 비교했는데, 공정 변동으로 실제 화면이 등록 이미지와 달라져 첫 시도 성공률이 31.8%에 그쳤습니다. 그래서 최근 정렬에 성공한 화면 여러 장을 취합해 기준 이미지를 만드는 방식(consensus) 을 도입했습니다. 지금 웨이퍼의 실제 모습을 따라가는 기준이라 첫 시도 성공률이 76.4%로 약 2.4배 올랐고, AI가 낸 후보 안에 정답이 든 비율도 43.4%에서 87.6%로 올랐습니다. 같은 Recipe면 장비가 달라도 성공 사례를 공유합니다. 고배율 화면은 반복 패턴이 많아 더 까다로우므로 촬영 모드를 화면에서 읽어 모드별로 다른 판정 방식을 쓰도록 했습니다. 이 수치는 오프라인 평가값이며 현장 자동 복구 성공률은 배치 후 기록으로 따로 집계합니다.

화면 조작 신뢰도. 단일 모델이 한 번에 버튼 좌표를 찍게 하면 자주 빗나갔습니다. 대략 영역을 찾고 잘라 확대해 정밀 좌표를 정한 뒤 OCR로 라벨을 확인하는 3단계로 바꿔 500회 반복 시험에서 99% 성공했습니다. 확인이 안 되면 클릭하지 않습니다.

환산. 건당 4분 × 주 400건 = 약 27시간의 장비 시간이 돌아옵니다. 웨이퍼 1장 측정 15분 기준 매주 약 100장을 더 측정할 수 있고, 장비로 환산하면 약 0.2대, 1대 약 20억 원으로 추산하면 Capex 약 4~5억 원에 해당합니다. 배치 후에는 대응 기록으로 실제 회수 시간을 집계해 실측으로 바꿉니다.

4.1 패기 — 일과 싸워서 이기는 힘

"패기 있는 구성원은 스스로 동기부여하여 문제를 제기하고, 높은 목표에 도전하며, 기존의 틀을 깨는 과감한 실행을 한다. 그 과정에서 필요한 역량을 개발하기 위해 노력하며, 타 구성원과 함께 적극적으로 소통함으로써 더 높은 성과를 낸다." (SKMS 전문, VWBE 문화. 사내 공식 판본 대조는 제출 전 확인)

  • 오래 현업 담당자가 하던 일을 자동화 과제로 정의했습니다. 주 400~500건, 건당 5분, 24시간 교대 감시라는 부담을 먼저 수치로 세웠습니다. 계측 화면이 표준 UI가 아니라 자동화 도구가 안 붙는다는 사실을 안 되는 이유가 아니라 풀어야 할 문제로 삼았고, 목표를 알림 자동화 같은 부분 개선이 아니라 감지·접속·재정렬·기록까지 도는 무인 루프로 잡았습니다.
  • 맞는 AI를 직접 찾았습니다. 외부 솔루션을 기다리지 않고 오픈웨이트 모델 5종을 사내 HCP에 설치해 실제 장비 화면으로 비교했고, 벤치 결과로 VLM 1종 + OCR 1종을 골라 상시 운영합니다.
  • AI로 안 되는 영역은 다른 기술로 채웠습니다. VLM은 화면을 이해하지만 정렬에 필요한 픽셀 정밀도가 약합니다. 그 영역을 억지로 맡기지 않고 CV 매칭 엔진을 붙였고, 등록 이미지 1장과 단순 비교하던 방식이 안 통하자 최근 성공 사례를 취합하는 기준(consensus)을 고안해 첫 시도 성공률을 2.4배 올렸습니다.
  • 시행착오를 평가로 바꿨습니다. 단일 모델 클릭이 빗나가자 대략 → 정밀 → OCR 확인의 3단계로 고쳤고, 정렬 개선안은 오프라인 평가로 하나씩 채택·기각했습니다. AI로도 못 찾는 실패는 Align Key 재등록이라는 현업 과제로 정의해 AI가 못 푸는 몫을 숨기지 않았습니다.
  • 장비에 붙여도 되는 수준까지 밀어붙였습니다. 확인 안 된 클릭은 나가지 않는 원칙, 실장비 없이 도는 자동 테스트 1,207개, 점검 모드 → 반자동 → 현업 합동 시험 → 26대 배치의 단계적 게이트로 실알람 3건을 완주했습니다.

4.2 Teamwork — 다른 팀이 같은 팀처럼

"회사는 조직화된 힘을 통해 가용자원을 효과적으로 활용하여 최대한의 가치를 창출하는 공동체이다." (SKMS 전문)

  • 기반기술전략 AX Part와 R&D DMI NAND MI기술이 같은 팀처럼 일했습니다. AX 쪽이 기능을 고치면 현업이 곧바로 장비에서 시험하고, 미진한 부분을 다시 고쳐 같은 조건에서 재시험하는 사이클이 7.5개월 내내 돌았습니다. 투입 인원은 각 1명입니다.
  • 현업 엔지니어가 시험 환경을 만들어 줬습니다. 시험용 웨이퍼와 Recipe로 장비 사용 인가를 받아 Align Fail이 실제로 나는 재현 환경을 구축했고, 덕분에 실알람을 기다리지 않고 기능을 확인할 수 있었습니다.
  • 현업의 장비 지식이 AI의 판단 규칙이 됐습니다. 저배율과 고배율에서 Align Key가 보이는 방식이 다르다는 장비 특성을 반영해 촬영 모드별로 판정 방식을 나눴고, 측정 진행 카운터가 실패 중에도 올라간다는 현장 확인으로 완료 판정 기준을 바꿨습니다. 재등록이 필요한 Recipe의 판단 기준도 현업과 함께 정했습니다.
  • 두 조직의 자원을 하나의 목표에 조직화했습니다. AX Part의 AI 개발·운영 역량과 MI의 장비 지식·시험 환경이 합쳐져 2명이 7.5개월에 감지에서 기록까지 도는 루프를 만들고 26대 실전 배치를 준비하고 있습니다.

4.3 Operation Improvement with AI

기존 프로세스의 불편함. 매 건 같은 순서를 현업 담당자가 반복하는 수작업, 같은 Recipe의 같은 실패를 매번 다른 담당자가 처음부터 판단하는 중복 확인, Align Key 탐색과 재조정 정밀도가 개인 경험에 좌우되는 숙련도 의존, 24시간 감시 주기에 묶인 처리 지연, 잘못된 위치를 확정하고도 추적할 기록이 없는 오류 가능성이 있었습니다.

AI·자동화 기능 적용 지점 무엇이 달라지나
탐지 알람을 10초마다 조회해 Align Fail만 골라 발동. 접속 후 화면에서 라이브 영역·촬영 모드·타인 점유를 읽음 24시간 모니터 감시가 자동화되고 화면 상태를 시스템이 먼저 읽음
자동 대응 RCS 접속 → 녹화 → 최근 성공 사례 기준으로 위치 계산 → 재정렬 → 확정 → 측정 재개 감시 → 종료 감지~재조정 5분 → 1분 미만
판단 지원 헷갈리는 Align Key Recipe를 재등록 검토 후보로 제시, 대응 기록의 실패 분포 집계 "무엇을 먼저 고칠지"를 감이 아니라 데이터로
이상치 필터 버튼을 못 찾거나 라벨이 다르거나 모드를 못 읽으면 클릭·보정 보류. 보정 뒤 오측이 보이면 후속 측정 중단 불확실한 조작은 하지 않음
예외 알림 AI가 진행 못하면 원인·요구 행동을 담아 담당자에게 큐브 알림. 설정 문제와 재등록 검토를 구분 담당자는 예외만 판단, 다음 행동의 근거 확보
기록·자산화 대응 1건 = 기록 1줄, 실패 화면·녹화 보존. 수동 조작 녹화 → 절차서 변환 경로 개인 경험이 기록으로 남고 개선 근거가 쌓임
