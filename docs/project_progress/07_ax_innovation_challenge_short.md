## 1. 사례 요약

R3 연구소 팹의 CD-SEM 26대에서는 Align Fail(정렬 실패)이 **주 400~500건** 발생합니다. 사람이 RCS(Remote Control System, 장비 원격 제어 프로그램) 모니터를 24시간 감시하다 멈춘 장비에 접속해 **1건 5분**씩 고치던 일을 **AI Agent가 감지·접속·재정렬·기록까지 무인으로 수행**하도록 바꾼 사례입니다. 감지에서 위치 재조정까지 걸리는 시간은 **1분 미만**으로 줄었습니다.

**문제.** 계측 장비는 측정 전에 Recipe(측정 설정)에 등록된 기준 이미지(Align Key)를 실제 웨이퍼 화면에서 찾아 좌표를 맞춥니다. 공정 변동으로 등록 이미지와 실제 화면이 조금씩 달라지면 장비는 정렬에 실패하고 **그 자리에서 멈춥니다**. Split Lot이 많은 연구소 팹에서는 이 실패가 전체 측정의 약 5%에 이릅니다. 멈춘 장비를 다시 움직이는 절차는 정형화되어 있지만 전부 사람 손을 탑니다. Fab 인라인 구성원과 엔지니어가 RCS 모니터를 24시간 교대로 감시하다 멈춘 장비를 발견하면 접속해, 멈춘 화면에서 Align Key를 배율을 바꿔가며 육안으로 찾아 재조정합니다. 1건당 평균 5분, 그 5분은 전부 장비 idle입니다. 주 400건이면 **주 약 33시간**의 계측 장비 시간이 사람의 반응 속도에 묶여 있었습니다. 실패 화면도 남지 않아 어떤 Recipe가 만성적으로 실패하는지 근거로 분석할 수 없었습니다.

그동안 자동화하지 못한 이유는 둘입니다. 계측 클라이언트 화면이 표준 UI 컴포넌트가 아니라 **일반 RPA·UI 자동화 도구가 버튼을 인식하지 못하고**, Align Key는 매번 조금씩 다르게 찍혀 **고정 좌표·고정 템플릿으로는 풀리지 않습니다**. 화면의 의미를 이해하는 능력과 픽셀 단위 정밀도가 동시에 필요한, 규칙 기반 자동화의 사각지대였습니다.

![그림 1. Before / After 흐름 비교](img/07/fig1_before_after.png){: .fig-l }

**해결.** 열쇠는 AI에 다 맡기지 않고 역할을 나눈 것입니다. 처음에는 화면을 이해하는 VLM(Vision Language Model) 하나에 클릭까지 맡겼지만 좌표가 어긋나고 반복할수록 오류가 늘었습니다. 그래서 **VLM은 "어디를 볼지"**(UI 요소 위치, 라이브 화면 영역, 촬영 모드), **OCR은 "정말 그 버튼인지"**(라벨을 읽어 대조하고 확인이 안 되면 클릭하지 않음), **CV(Computer Vision) 매칭 엔진은 "정확히 몇 픽셀인지"**(기준 이미지와 라이브 화면의 유사도와 재정렬 좌표)를 맡도록 나누고, 뒤 단계가 앞 단계의 답을 검증하게 연결했습니다. 사람은 예외 판단과, 지금 단계에서는 최종 확정(OK)을 맡습니다. VLM의 답이 낮은 CV 점수를 덮어쓰지 못하고 확인에 실패한 클릭은 나가지 않는다는 원칙을 코드에 고정했습니다. 화면 이해는 사내 HCP(모델 운영 플랫폼)에 자체 배포한 소형 오픈소스 모델이 맡고 반복 정밀 판정은 CV가 맡으므로, 거대 모델이나 외부 API 없이 GPU 1~2장 규모로 26대를 모니터링합니다.

그 결과 **알람 감지(10초 폴링) → 담당자 사전 고지 → RCS 자동 접속 → 상시 녹화 → 화면·촬영 모드 판독 → 성공 사례 기반 자동 재정렬 → 확정 → 완료 감시·자동 종료 → 대응 기록 1줄 적재**가 한 루프로 돕니다. 보정이 불가능하거나 다른 엔지니어가 장비를 쓰고 있으면 원인과 요구 행동을 담아 알리고 물러납니다. 정확도는 실장비를 건드리지 않는 오프라인 벤치(Recipe 200개)에서 A/B로 확보했고, 데이터로 이긴 개선안 2가지만 운영에 반영했습니다. 그 뒤 남은 실패의 약 87%는 정답이 후보에 아예 없는 유형이라 알고리즘이 아니라 **Align Key 재등록**이라는 현업 과제로 정의했습니다.

**성과.** 건당 대응 시간이 5분에서 1분 미만으로 줄어 1건에 4분의 장비 시간이 돌아옵니다(실알람 3건 실측 `[검증]`). 주 400건이면 **약 27시간/주**이고, 웨이퍼 1장 측정에 15분이 든다고 보면 **매주 약 100장을 더 측정**할 수 있습니다. 이를 장비로 환산하면 **약 0.2대 분**이며, 1대 약 20억 원으로 추산하면 **Capex 약 4~5억 원 절감**에 해당합니다 `[목표]`. 사람은 24시간 모니터를 감시하다 접속해 육안으로 찾는 일에서 벗어나 예외 판단만 맡고, 대응 1건마다 화면 증거와 기록 1줄이 남아 만성 실패 Recipe 를 근거로 골라낼 수 있습니다.

| 항목 | Before | After |
|------|--------|-------|
| 1건당 대응 시간(감지 → 위치 재조정) | 5분 | **1분 미만** `[검증]` |
| 주당 장비 idle(400건) | 약 33시간 | **약 6.7시간** (약 27시간 회수) `[목표]` |
| 추가 측정량 · 장비 환산 | - | **WAFER 약 100장/주** · **장비 약 0.2대 = Capex 약 4~5억 원** `[목표]` |
| 24시간 대응 체계 | 인라인·엔지니어가 교대로 모니터 감시·접속·육안 탐색 | 감지·접속·재조정 자동, 담당자는 예외 판단 |
| 실패 기록 | 없음 | 대응 1건 = 기록 1줄 + 화면 증거 + 녹화 |

2026-08 실장비 보정을 개통했고, 2026-09 실알람 3건 완주와 현업 합동 시험을 거쳐 지금은 전용 PC를 확보해 R3 26대 실전 배치를 준비하고 있습니다.

## 2. 사례 상세

### 2.1 업무 문제와 기존 방식의 한계

**대상 업무.** R3 CD-SEM 26대의 Align Fail(Smart Alarm 9006) 대응입니다. 정렬이 실패하면 장비는 진행을 멈추고 사람이 조치할 때까지 홀드됩니다. R3는 연구소 팹이라 Lot Split과 공정 Variation이 많아 등록 이미지와 실제 웨이퍼 이미지가 달라지는 일이 구조적으로 되풀이됩니다. 한두 번 고쳐서 없어지는 문제가 아닙니다.

**현업 필요성.** 장비 홀드는 뒤에 선 Lot 전체를 기다리게 해 계측 WIP과 연구소 팹의 개발 속도를 지연시킵니다. Fab 인라인 구성원과 MI 엔지니어가 24시간 대응에 묶여 있고, 화면을 보고 판단하는 단계가 있어 숙련자의 시간이 반복 작업에 들어갑니다. 실패 시점 화면이 남지 않아 어떤 Recipe의 Align Key를 재등록해야 하는지 근거로 판단하기 어려웠습니다.

**기존 방식의 비효율.** 감지는 사람의 확인 주기에 의존해 야간·교대 인계 구간에 지연되고, 접속은 매 건 같은 조작을 반복하지만 비표준 UI라 기존 자동화 도구가 붙지 않습니다. Align Key 육안 탐색과 재조정 정밀도는 숙련도에 좌우되며 반복 패턴이 많은 고배율 화면은 사람도 오판합니다. 기록이 없어 개선 우선순위를 감으로 정했습니다.

### 2.2 AI 적용 과정과 새로운 시도

2026년 1월 요구사항 정의에서 시작해 네 단계로 진행했습니다.

**① 화면 이해 AI 확보(02~03월, 운영 구성 확정 08월).** 외부 API에 기대지 않고 Hugging Face 오픈웨이트 VLM 3종(MAI-UI, UI-Venus, UI-TARS)과 OCR 2종(PaddleOCR-VL, GOT-OCR)을 사내 HCP에 설치하고 통합 API 한 곳으로 라우팅해 바꿔 끼울 수 있게 했습니다. 장비 제조사가 소수 엔지니어용으로 만든 화면은 버튼이 오밀조밀해 사람도 조작이 어려운데, 스마트폰 화면 자동화용 소형 모델 MAI-UI가 가장 높은 성공률을 보였습니다(좌표 인식+클릭 500회 99% `[검증]`). 벤치 결과로 VLM 1종 + OCR 1종 상시 운영으로 정리했습니다.

**② 장비 원격 제어(RCS) 자동화 증명(03~05월).** 단일 모델이 한 번에 좌표를 찍는 방식은 확률적으로 실패했습니다. 전체 화면에서 대략 영역을 찾고(coarse), 잘라 확대해 정밀 클릭점을 정하고(fine), 클릭 전 그 자리의 라벨을 OCR로 읽어 확인(confirm)하는 3단계로 바꿨습니다. 로그인·탭 이동·장비 선택·캡처·창 닫기를 오피스 실장비에서 안정적으로 수행함을 확인했습니다.

**③ 정렬 정확도 확보: 오프라인 A/B 벤치(05~07월).** Recipe 200개의 등록 이미지와 과거 실패 이미지로 실장비를 건드리지 않는 평가 환경을 만들고, 여기서 이긴 방식만 운영에 반영했습니다. 채택한 것은 둘입니다. **성공 사례 종합(consensus) 기준 이미지**는 등록 1장 대신 최근 정렬 성공 이미지 여러 장을 합성한 것으로 rank-1을 31.8%에서 76.4%로 올렸고, **촬영 모드별 후보 재평가**는 저배율(OM)과 고배율(SEM)에서 이기는 심판이 달라 투표로 섞지 않고 모드에 따라 전환해 SEM rank-1을 약 7.3%p 더 올렸습니다. 효과가 작은 대안은 데이터로 제외했습니다.

**④ 실시간 통합 루프(06월~).** Align Fail 알람을 사내 data-hub에 적재하고 h-api를 10초 간격으로 조회하는 수신 기반을 만든 뒤, ①~③을 묶어 감지부터 기록까지 무인으로 도는 루프를 구축하고 08월 실장비 보정을 개통했습니다. 08~09월에는 알람 1건 = 기록 1줄로 남기는 계층(Recovery Episode)을 더했습니다. 접속 즉시 화면을 상시 녹화해 실패 **증거**·재등록 **판단 근거**·수동 조작의 **암묵지 자산화**·다음 Agent의 **학습 원천**으로 씁니다(키 입력은 수집하지 않음).

### 2.3 난이도·제약과 극복

가장 어려웠던 지점은 화면이 계속 바뀌는 장비를 상대로 AI가 오해 없이 정확히 누르게 하는 일이었습니다. CD-SEM 라이브 영상의 변화를 UI 변화나 사람의 조작으로 오인하면 잘못된 곳을 누릅니다. 해법은 VLM이 UI와 라이브 영상 영역을 먼저 구분하고 CV가 그 안에서 픽셀 단위로 계산하는 역할 순서였습니다.

| 난이도·제약 | 극복 방식 |
|-------------|-----------|
| 비표준 UI + 빽빽한 버튼: 자동화 도구가 컨트롤을 못 잡고 단일 VLM 인식은 확률적 실패 | 화면 이미지 → VLM 좌표(coarse → fine) → OCR 확인 → 클릭. 확인 안 되면 클릭하지 않는 fail-closed |
| Align Key는 픽셀 동일성을 가정할 수 없고, 고배율 SEM은 반복 패턴이라 가짜 후보가 많음 | 구조·기하 매칭 + 성공 사례 consensus + 모드별 재순위. 잔여 실패의 약 87%가 "정답이 후보에 없는" 유형임을 확인 → Align Key 재등록 권고 목록으로 현업과 검토 |
| VLM 서버 메모리 16GB로 동시 구동 모델 수 제한 | 안 쓰는 모델은 내리는 원칙(5종 → 2종). 판정 대부분을 CV로 처리해 VLM 호출 최소화 |
| 개발은 Mac, 실행은 오피스 Windows. 실장비 클릭은 오동작 시 측정에 영향 | 장비·API를 대체한 시험 환경과 재생 절차로 실장비 없이 반복. 점검 모드 → 반자동 → 현업 합동 시험 → 26대 배치의 단계적 게이트 |
| 다른 엔지니어가 장비를 점유하거나 도중에 개입할 수 있음 | 점유 3상태 판별, 화면 공유 요청 후 관전 녹화, 개입 감지 시 자동화 양보, 쿨다운 후 재시도 |

**AI와 엔지니어가 같은 장비를 다룰 때의 규칙.** 현업과 합동 평가를 하자 AI 혼자 도는 환경에서는 보이지 않던 충돌이 드러났고, 다섯 규칙을 사람 우선 원칙으로 합의했습니다. ① **주도권은 사람에게**(점유 중이면 관전 녹화만) ② **개입이 감지되면 양보**(시간 초과를 성공으로 단정하지 않음) ③ **조작 환경 분리**(전용 PC·AI용 ID, 클릭 전 창 전면화) ④ **긴급 중단 단축키** ⑤ **RCS 부재 시 자동 복구**. 규칙은 확정됐고 전용 PC 환경 적용과 실전 검증이 남아 있습니다.

## 4. SKMS 기본 정신 · Operation Improvement 측면 서술

### 4.1 패기 — 일과 싸워서 이기는 힘

> "패기 있는 구성원은 **스스로 동기부여하여 문제를 제기하고, 높은 목표에 도전하며, 기존의 틀을 깨는 과감한 실행**을 한다. 그 과정에서 **필요한 역량을 개발**하기 위해 노력하며, 타 구성원과 함께 적극적으로 소통함으로써 더 높은 성과를 낸다." (SKMS 전문, VWBE 문화. 사내 공식 판본 대조는 제출 전 확인)

- **반복 업무를 자동화 과제로 정의했습니다.** 주 400~500건, 건당 5분, 24시간 교대라는 부담을 먼저 수치로 세우고, 계측 화면이 표준 컨트롤이 아니라는 사실을 안 되는 이유가 아니라 풀어야 할 문제로 다시 정의했습니다. 목표는 알림 자동화 같은 부분 개선이 아니라 감지·재조정·기록까지 도는 무인 루프였습니다.
- **적절한 AI를 직접 찾고, VLM만으로 안 되는 영역은 CV로 보완했습니다.** 외부 솔루션을 기다리지 않고 오픈웨이트 모델 5종을 사내 HCP에 설치해 실제 업무 화면으로 비교했습니다. VLM이 약한 픽셀 정밀도는 억지로 맡기지 않고 CV 매칭 엔진을 붙여, 벽을 만났을 때 목표를 낮추지 않고 도구를 더했습니다.
- **시행착오를 평가로 바꿨습니다.** 단일 모델 클릭의 실패를 coarse → fine + OCR 확인으로 고쳤고, 정렬 개선안은 오프라인 A/B로 하나씩 채택·기각했습니다. 재순위를 투표로 섞으면 성능이 낮아진다는 것을 확인하고 모드별 전환으로 바꿨습니다.
- **장비에 붙여도 되는 수준으로 만들었습니다.** 확인되지 않은 클릭은 나가지 않는 fail-closed, 예외 시에도 뒷정리, 자동 테스트 1,207개, 주요 변경마다 되돌릴 수 있는 설정을 갖췄습니다. 사람과 AI의 충돌 문제를 만나자 전용 PC와 AI용 ID를 확보했습니다.

### 4.2 Teamwork — 다른 팀이 같은 팀처럼

> "회사는 **조직화된 힘**을 통해 가용자원을 효과적으로 활용하여 최대한의 가치를 창출하는 공동체이다." (SKMS 전문)

- **기반기술전략 AX Part와 R&D DMI NAND MI기술이 같은 팀처럼 일했습니다.** AX 쪽이 기능을 고치면 현업이 곧바로 장비에서 시험하고, 미진한 부분을 다시 고쳐 같은 조건에서 재시험하는 사이클이 프로젝트 내내 돌았습니다. 개발자가 실장비 화면을 볼 수 없는 분리(Mac 개발, 오피스 Windows 실행)를 실행 로그·화면 증거를 주고받는 소통 리듬으로 이었습니다.
- **현업 엔지니어가 시험 환경을 만들어 줬습니다.** 시험용 웨이퍼와 Recipe로 장비 사용 인가를 받아 Align Fail이 실제로 나는 재현 환경을 구축했고, 덕분에 실알람을 기다리지 않고 기능을 확인할 수 있었습니다.
- **현업의 암묵지가 판단 규칙으로 들어갔습니다.** 측정 카운터가 실패 중에도 증가한다는 현장 확인으로 완료 판정을 품질 신호 우선으로 바꿨고, OM/SEM의 실패 양상 차이를 반영해 모드별 후보 평가 방식을 정했으며, 재순위로 풀리지 않는 후보 누락은 재등록 검토 후보로 정리해 현업 과제로 함께 정의했습니다.
- **사람과 AI가 함께 일하는 규칙을 함께 합의했습니다.** 주도권·양보·개입 시 후퇴·긴급 중단·자동 복구 다섯 규칙을 두 팀이 사람 우선 원칙으로 합의해 설계에 반영했습니다. 두 조직의 자원이 하나의 목표에 조직화된 덕분에 2명이 7.5개월에 감지에서 기록까지 도는 루프를 만들었습니다.

### 4.3 Operation Improvement with AI

**기존 프로세스의 불편함.** 매 건 같은 순서를 사람이 반복하는 **수작업**, 같은 Recipe의 같은 실패를 매번 다른 사람이 처음부터 판단하는 **중복 확인**, Align Key 탐색과 재조정 정밀도가 개인 경험에 좌우되는 **숙련도 의존**, 사람의 확인 주기에 묶인 **처리 지연**, 잘못된 위치를 확정하고도 추적할 기록이 없는 **오류 가능성**이 있었습니다.

**개선 효과.** 처리 시간은 5분 → 1분 미만(주 약 27시간 회수, WAFER 약 100장/주 `[목표]`), 정확도는 rank-1 31.8% → 76.4%·좌표 인식+클릭 99% `[검증]`입니다. 정형 절차의 실행을 자동화하고 경험에 의존하던 판단 기준(모드별 기준 이미지, 완료 판정 순서)과 예외 조건을 코드·규칙으로 **표준화**했으며, 성공 이력의 장비 무관 재사용과 재등록 후보 도출로 **재작업 감소**의 기반을, 야간·교대에도 감지·접속·재조정이 자동으로 도는 구조로 **현업 부담 완화**의 기반을 마련했습니다(효과 측정은 배치 후). VLM 좌표 → OCR 확인 → 클릭 패턴, 모델 벤치·교체 체계, 공존 원칙은 Recipe Tuning·Auto Recipe Creation 등 후속 업무에 그대로 **확산**됩니다. 이 사례의 Operation Improvement는 사람이 하던 일에서 AI가 맡을 몫(반복 조작·1차 판정)과 사람이 맡아야 할 몫(예외 판단)을 갈랐다는 데 있습니다.
