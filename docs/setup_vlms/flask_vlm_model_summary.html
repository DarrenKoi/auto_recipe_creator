Flask VLM Setup Snapshot

5 Models Your Team Can Read at a Glance

이 페이지는 docs/setup_vlms 문서와 poc/work2/flask_vlm.py 기준으로, 현재 Flask VLM 문맥에서 같이 운영하는 5개 모델을 빠르게 비교한 요약본이다. 핵심은 무엇을 잘하는지와 어디에 가장 잘 맞는지다.

기본 화면 분석 ui-venus가 screen_analysis와 main_tabs 기본값이다.
기본 OCR paddleocr-vl-1.5가 현재 기본 OCR service 로 잡혀 있다.
범위 이 문서는 Flask-hosted / Flask-integrated 5개 모델에 집중한다. direct company LLM 항목은 제외했다.

Model Cards

GUI Core

UI-Venus-1.5-8B

Qwen3-VL 계열 / 현재 기본 screen analysis, main tabs
service slug: ui-venus
Best Fit RCS 화면처럼 복합 GUI 를 분석하고, grounding 과 navigation 을 함께 안정적으로 보고 싶을 때.

What It Can Do

  • 스크린샷에서 GUI grounding과 위치 기반 해석을 수행한다.
  • mobile + web + browser 문맥을 하나의 GUI agent 흐름으로 다룬다.
  • 화면 구조를 보고 다음 navigation 방향을 정하는 용도에 잘 맞는다.

Strength Points

  • unified, end-to-end GUI agent 성격이 강해서 범용 화면 분석에 균형이 좋다.
  • 문서상 grounding + cross-platform navigation 완성도가 핵심 강점으로 정리되어 있다.
  • 현재 저장소에서도 기본 선택지라서 팀 공용 기준점으로 쓰기 쉽다.
GUI Sidecar

MAI-UI-8B

Qwen3-VL 계열 / zoom-in sidecar benchmark role
service slug: mai-ui
Best Fit 실제 모바일 환경, 사용자 상호작용, 도구 호출, device-cloud 협업 같은 운영형 GUI agent 관점이 중요할 때.

What It Can Do

  • mobile-centric GUI navigation 을 중심으로 동작을 해석한다.
  • agent-user interaction 과 MCP tool call 문맥을 모델 설명에 직접 포함한다.
  • device 와 cloud 가 나뉜 실제 배포 구조를 염두에 둔 GUI 흐름 검토에 맞는다.

Strength Points

  • real-world centric 성격이 강해서 운영 시나리오 해석이 선명하다.
  • 동적 환경 대응과 협업형 agent 구조를 전면에 둔 점이 차별점이다.
  • 현재 registry 상 sidecar 포지션이라 보조 비교 모델로 두기 좋다.
Reasoning Agent

UI-TARS-1.5-7B

Qwen2.5-VL 계열 / primary GUI benchmark candidate
service slug: ui-tars
Best Fit 단순 화면 읽기보다 reasoning-heavy computer use, browser use, phone use 흐름까지 폭넓게 보고 싶을 때.

What It Can Do

  • computer use, browser use, phone use, game / virtual world 까지 넓게 다룬다.
  • 스크린샷 기반 행동 판단을 넘어서 thought-before-action 스타일 reasoning 을 밀어 준다.
  • 좀 더 일반적인 멀티모달 agent 성향을 실험할 때 적합하다.

Strength Points

  • 범용성이 가장 넓고 reasoning color 가 가장 강하다.
  • inference-time scaling 을 강조해 깊이 있는 agent 실험에 어울린다.
  • 다만 runtime 민감도가 높아 배포 난도가 다른 두 GUI 모델보다 크다는 점도 같이 기억해야 한다.
OCR Default

PaddleOCR-VL-1.5

OCR family / 현재 기본 OCR pipeline service
service slug: paddleocr-vl-1.5
Best Fit 팀 공용 OCR 경로를 기존 GPU 서버와 기존 vLLM wrapper 안에 가장 자연스럽게 편입해야 할 때.

What It Can Do

  • 이미지에서 OCR text 추출을 수행하는 전용 OCR VLM 역할을 맡는다.
  • 기존 Flask VLM 서비스 구조 안에서 기본 OCR endpoint 로 연결하기 쉽다.
  • 문서 기준으로 vLLM 경로에 바로 편입 가능한 OCR 모델이다.

Strength Points

  • 기존 vLLM wrapper 재사용이 가능해서 운영 단순성이 높다.
  • 현재 Linux 클라우드 기준 별도 Paddle 패키지 없이도 정리된 배포 경로가 있다.
  • 그래서 이 저장소에서는 default OCR 로 두기 가장 실무적이다.
OCR Fallback

GOT-OCR-2.0-hf

OCR fallback / transformers direct inference path
service slug: got-ocr
Best Fit OCR 전용 검증을 별도 runtime 으로 분리하고 싶거나, 기본 OCR 외에 독립 fallback 경로를 확보하고 싶을 때.

What It Can Do

  • 이미지 기반 OCR 추론을 수행한다.
  • transformers 직접 추론 경로로 smoke test 와 전용 wrapper 검토가 가능하다.
  • 팀 공용 API 전에 로컬 또는 전용 Python runtime 으로 먼저 검증하는 흐름에 맞는다.

Strength Points

  • 현재 클라우드 런타임에서 큰 업그레이드 없이 바로 테스트 가능한 점이 실무 강점이다.
  • GPU, dtype, runtime 을 모델 전용으로 고정해 분리 검증하기 쉽다.
  • 다만 문서 기준 vLLM supported model 경로는 아니므로, 운영 경로는 PaddleOCR 보다 덜 단순하다.

Call From Local PC

권장 호출 방식: 동료 PC 에서는 repo helper 없이 requests.post(...) 로 Flask proxy 를 직접 호출하면 가장 단순하다.

실행 위치: 로컬 PC 에서 바로 Python 스크립트로 실행하면 된다. repo import 는 필요 없다.

사전 점검: 먼저 uv run python poc/work2/connection_check.py 로 서비스가 살아 있는지 확인한다.

요청 형식: 이미지 파일을 base64 로 바꾼 뒤, JSON dict 안에 model, messages, image_url 를 넣어 POST 하면 된다.

이미지 권장 형식: 가능하면 .webp 이미지를 보내면 현재 repo 운영 원칙과 맞다.

공통 패턴: 아래 코드에서 url, model, prompt 만 바꾸면 5개 모델을 같은 방식으로 호출할 수 있다.

import base64
from pathlib import Path

import requests

img_b64 = base64.b64encode(
    Path("/ABS/PATH/TO/sample.webp").read_bytes()
).decode("utf-8")

payload = {
    "model": "ui-venus-1.5-8b",
    "messages": [
        {"role": "system", "content": "Respond only with JSON."},
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "Analyze this screen in JSON."},
                {
                    "type": "image_url",
                    "image_url": {
                        "url": f"data:image/webp;base64,{img_b64}"
                    },
                },
            ],
        },
    ],
    "temperature": 0.0,
    "max_tokens": 1024,
}

response = requests.post(
    "http://itc-1stop-solution-gpu-image-webapp.aipp02.skhynix.com/api/vlm_serve/ui-venus/v1/chat/completions",
    json=payload,
    timeout=120,
)
response.raise_for_status()
data = response.json()
print(data["choices"][0]["message"]["content"])
