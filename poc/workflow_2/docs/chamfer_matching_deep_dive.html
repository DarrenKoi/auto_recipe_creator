1. 기원: 왜 "Chamfer" 인가

Chamfer 는 영어로 모서리를 비스듬히 깎은 면을 뜻한다. 가구 다리, 금속 가공에서 직각 모서리를 45° 사선으로 깎는 작업을 "chamfering" 이라고 한다.

역사적 흐름

연도저자기여
1966 Rosenfeld & Pfaltz 최초의 distance transform 알고리즘. 직각 격자에서 유클리드 거리를 정수 근사하는 방법 제안 → 이때 정수 비율로 모서리를 "깎는다"는 의미에서 chamfer distance 용어 등장.
1986 Borgefors Distance transform 의 효율적 계산법 정리 ("Distance Transformations in Digital Images", CVGIP). 5-7-11 chamfer mask 도입.
1988 Borgefors Chamfer matching 정식 발표 ("Hierarchical chamfer matching: A parametric edge matching algorithm", IEEE PAMI). edge map 위에서 거리 평균을 최소화하는 매칭 프레임워크.
2007 Shotton et al. Oriented chamfer 도입. edge 방향 정보까지 활용하여 false positive 감소.
2010 Liu et al. Fast Directional Chamfer Matching (FDCM). 방향별 거리 변환을 sub-linear 시간에 계산.
이름의 핵심 직관: 진짜 유클리드 거리는 √2 ≈ 1.414 같은 무리수가 필요하지만, 당시 컴퓨터는 정수 연산이 훨씬 빨랐다. 그래서 가로/세로=3, 대각선=4 처럼 정수 비율로 거리를 근사 — 정사각형의 직각 모서리를 사선으로 "깎아낸" 모양이 되어 chamfer distance 라고 부른 것.

2. Distance Transform 의 정의

이진 이미지 B 에서 "object 픽셀 집합" O 가 주어졌을 때, 거리 변환 DT 는:

DT(p) = min { dist(p, q) | q ∈ O }

즉 각 픽셀에서 가장 가까운 object 픽셀까지의 거리. Chamfer matching 에서는 object 가 edge 픽셀이다. 직관적 예시를 보자.

4. Two-pass 알고리즘

Chamfer distance 의 거리 변환은 이미지를 단 2번만 스캔해서 모든 픽셀의 거리를 계산할 수 있다. 이게 1980년대에 chamfer 가 인기였던 핵심 이유.

Forward pass (좌→우, 위→아래)

# 의사 코드
DT = where(edge, 0, infinity)

# Forward pass
for y in range(H):
    for x in range(W):
        for (dy, dx, w) in [(-1,-1,4), (-1,0,3), (-1,1,4), (0,-1,3)]:
            ny, nx = y+dy, x+dx
            if 0 <= ny < H and 0 <= nx < W:
                DT[y, x] = min(DT[y, x], DT[ny, nx] + w)

# Backward pass
for y in reversed(range(H)):
    for x in reversed(range(W)):
        for (dy, dx, w) in [(0,1,3), (1,-1,4), (1,0,3), (1,1,4)]:
            ny, nx = y+dy, x+dx
            if 0 <= ny < H and 0 <= nx < W:
                DT[y, x] = min(DT[y, x], DT[ny, nx] + w)
왜 2번이면 충분한가? Forward pass 가 끝나면 모든 픽셀은 "왼쪽 위 어딘가의 edge 까지의 최단 경로"를 갖는다. Backward pass 가 "오른쪽 아래 어딘가의 edge"까지를 채워준다. Edge 까지의 최단 경로는 반드시 이 두 방향 중 하나에 속하므로 2 pass 가 항상 정답.

5. Chamfer Matching 수식과 직관

거리 변환은 도구일 뿐. 매칭은 다음 한 줄로 정의된다:

dchamfer(T, F; x, y) = (1/|T|) · Σp ∈ T DTF(p + (x, y))

여기서 T 는 템플릿의 edge 좌표 집합, DTF 는 프레임의 거리 변환, (x, y) 는 슬라이딩 오프셋. 평균 거리를 모든 위치에서 계산해 최솟값을 찾는다.

왜 거리의 "합"이 아니라 "평균" 인가?

템플릿마다 edge 픽셀 수가 다르므로, 합으로 비교하면 큰 템플릿이 항상 불리하다. edge 개수 |T| 로 나눠 평균을 내면 "한 edge 픽셀당 frame edge 까지의 평균 거리"가 되어 서로 다른 템플릿 간 비교도 가능하다.

OpenCV 트릭: matchTemplate(TM_CCORR)

Python 루프로 모든 (x, y) 에서 합을 구하면 느리다. matchTemplate 으로 한 줄에 끝낼 수 있다 — 다만 입력을 살짝 바꿔야 한다: 

# 프레임의 distance transform 을 "이미지" 로,
# 템플릿의 edge mask (0/1) 를 "템플릿" 으로.
result = cv2.matchTemplate(frame_dt, template_mask, cv2.TM_CCORR)
# result[y, x] = Σ frame_dt[y+i, x+j] * template_mask[i, j]
#              = Σ_{edge pixels of T} frame_dt at offset (x, y)

mean_dt = result.min() / edge_count_in_template
score = exp(-mean_dt / tau)   # 0~1 점수
TM_CCORR 의 정체: "cross-correlation" 인데 두 입력의 곱의 합이다. template 이 binary mask (0/1) 이면 곱셈은 "edge 위치만 고르기" 가 되어 실질적으로 edge 위치에서의 distance transform 값을 합산하는 효과. 영리한 트릭.

점수 정규화: exp(-mean_dt / τ)

raw mean_dt 는 픽셀 단위 거리 (범위가 열려 있음). 0~1 로 정규화하려고 지수 감쇠 사용. τ 는 "허용 오차" 의 단위:

τ 가 클수록 더 큰 거리에도 관대 — 우리는 τ=10 (DT_TAU_PX) 를 사용

6. 변종: Hierarchical, Truncated, Oriented

Hierarchical Chamfer (Borgefors 1988 원논문)

높은 해상도에서 전체 영역을 매칭하는 건 느리다. Image pyramid 로 저해상도에서 대략적으로 찾고, 점점 정밀하게 좁히는 방식.

각 단계에서 후보가 좁아져 총 계산량이 O(N²) 에서 O(N log N) 수준으로 감소.

Truncated Chamfer — outlier robustness

Edge 가 한두 개 크게 빗나가면 평균 거리가 망가진다. 해결: 거리에 상한선을 두자.

DT'(p) = min(DT(p), threshold)

매칭하지 못한 edge 는 threshold 만큼만 페널티를 받는다. 이 변형은 occlusion (부분 가림) 에 매우 강해진다.

Oriented Chamfer Matching (Shotton 2007)

단순 chamfer 는 edge 의 위치만 본다. 하지만 같은 위치라도 edge 방향이 다르면 다른 패턴. Oriented chamfer 는 edge 방향(0~π)을 N 개 bin 으로 양자화하고, 각 방향별로 별도의 DT 를 만든다:

doriented(T, F) = (1/|T|) · Σp ∈ T DTF, θ(p)(p)

방향이 일치하지 않으면 매칭이 깨지므로 false positive 가 크게 줄어든다.

현재 우리 코드는 oriented chamfer 를 쓰지 않는다. 대신 ORB 가 keypoint 의 orientation 을 따로 검증하므로 같은 효과를 얻는다. 만약 ORB 를 쓸 수 없는 환경 (예: 저텍스처) 이라면 oriented chamfer 가 좋은 후속 카드.

7. 우리 코드에서의 구현

전처리 (line 107-124)

gray    = _to_grayscale(image)
eq      = cv2.createCLAHE(2.0, (8,8)).apply(gray)   # 국소 대비 정규화
blurred = cv2.GaussianBlur(eq, (0,0), sigmaX=1.0)   # 노이즈 제거
edges   = cv2.Canny(blurred, 60, 160)               # edge 추출

inverted = cv2.bitwise_not(edges)  # edge=0, background=255
dt       = cv2.distanceTransform(inverted, cv2.DIST_L2, maskSize=5)
왜 invert 하나? distanceTransform 은 "값이 0 인 픽셀까지의 거리" 를 계산한다. Canny 는 edge=255, background=0 으로 출력하므로 그대로 넣으면 background 까지의 거리가 나온다. Invert 해서 edge=0 으로 만들면 우리가 원하는 "edge 까지의 거리" 가 된다.

Multi-scale 매칭 (line 201-219)

for scale in (0.7, 0.85, 1.0, 1.2, 1.4):
    # 1) 템플릿 edge map 을 scale 배율로 resize
    edges_scaled = cv2.resize(template.edge_map, ..., INTER_NEAREST)
    template_mask = (edges_scaled > 0).astype(np.float32)
    edge_count = template_mask.sum()

    # 2) CCORR 로 모든 (x, y) 에서 거리합 계산

8. 약점과 실패 사례

약점 1: 비슷한 윤곽이 많은 영역에서 false positive
Chamfer 는 윤곽이 비슷한 곳이면 점수가 높게 나온다. 격자 형태가 반복되는 패턴 (예: SEM 의 die array)에서는 거의 모든 곳에서 점수가 비슷해진다 → ORB 검증이 필요한 이유.
약점 2: 회전에 약함
Multi-scale 은 처리하지만 회전은 처리하지 않는다. 30° 회전된 frame 이면 매칭 실패. 필요시 회전 각도도 탐색에 포함시키거나 ORB 의 homography 로 보정.
약점 3: Edge 가 너무 적은 템플릿
Edge 픽셀이 30개 이하이면 mean_dt 가 통계적으로 불안정. 1~2개 outlier 만으로 점수 급변. Borgefors 의 원래 권장: edge_count ≥ 100.
약점 4: Edge map 자체의 품질에 의존
Canny threshold (60, 160) 가 잘못되면 모든 게 무너진다. Threshold 자동 추정 (Otsu, median-based) 을 검토할 가치.
