1. 정의: XOR 후 1 비트 세기

같은 길이의 두 비트 문자열 A, B 에 대해:

hamming(A, B) = popcount(A XOR B)

XOR 은 "같으면 0, 다르면 1" 이므로, XOR 결과에서 1 인 비트의 개수가 곧 다른 위치의 개수가 된다. popcount 는 "population count" 로, 1 비트 개수를 세는 연산.

2. 손으로 따라가는 예시

8-bit 두 descriptor 를 비교해보자:

A = 1011 0101
B = 1001 1100
XOR = 0010 1001

빨강(다름) = 3개   →   hamming(A, B) = 3

256-bit descriptor (ORB 의 실제 크기) 라면 hamming distance 범위는 0 (완전 동일) ~ 256 (모든 비트 반대).

두 descriptor 의 hamming 분포

실제 매칭에서 hamming 분포 — 좋은 매칭은 좌측 (0~40) 에 몰리고 랜덤은 중앙 (128) 에 모임

3. 왜 ORB 가 hamming 을 쓰나

거리를 재는 방법은 여러 가지가 있다. 이진 descriptor 에 대해 각 방식이 어떤 차이를 만드는지 보자:

측정법수식이진 descriptor 적용 시속도
L1 (Manhattan) Σ \|ai − bi\| = hamming 과 정확히 같음 (float 연산) 느림
L2 (Euclidean) √Σ (ai − bi)² = √hamming (역시 float) 매우 느림
Hamming popcount(A XOR B) 정수 비트 연산 1회로 끝 매우 빠름
핵심 관찰: 이진 벡터에서는 L1, L2, hamming 이 본질적으로 같은 정보를 담는다. 단지 표현 방식과 계산 비용이 다를 뿐. 그래서 ORB 는 가장 빠른 hamming 을 선택했다.

4. CPU 명령어 2개로 끝나는 비결

현대 CPU 는 hamming distance 를 딱 2 cycle 에 계산할 수 있다: 

uint64_t a = ...;          // descriptor A 의 64-bit chunk
uint64_t b = ...;          // descriptor B 의 64-bit chunk
int distance = __builtin_popcountll(a ^ b);
//             └── POPCNT instruction (Intel/AMD CPU 내장)

256-bit descriptor 전체 계산

ORB 는 descriptor 가 256 비트이므로 64-bit chunk 가 4개: 

// 4 chunks × (XOR + POPCNT) = 8 cycles total
int hamming256(const uint8_t* a, const uint8_t* b) {
    int dist = 0;
    for (int i = 0; i < 4; i++) {
        uint64_t* pa = (uint64_t*)(a + i * 8);
        uint64_t* pb = (uint64_t*)(b + i * 8);
        dist += __builtin_popcountll(*pa ^ *pb);
    }
    return dist;
}

SIFT (128-float L2) 와 속도 비교

알고리즘한 쌍 비교 비용이론적 cycle
SIFT (128 float L2) 128 × (sub + mul + add) ~512 cycles
ORB (256 bit hamming) 4 × (XOR + POPCNT) ~8 cycles
약 64배 빠르다. Template 200개 × frame 500개 = 10만번 매칭이지만, hamming 덕분에 1ms 미만에 끝난다.

5. SEM 매칭에서의 의미

align_key_matcher.py:249 의 한 줄: 

bf = cv2.BFMatcher(cv2.NORM_HAMMING, crossCheck=False)
raw_matches = bf.knnMatch(des_t, des_f, k=2)

NORM_HAMMING 플래그가 BFMatcher 에게 "이진 descriptor 다, hamming 으로 비교하라" 고 알려준다. 그 다음 knnMatch(..., k=2) 가 각 template descriptor 에 대해 hamming 이 가장 작은 frame descriptor 2개를 반환한다.

6. Lowe ratio 와의 연결

align_key_matcher.py:257 의 Lowe ratio test 도 hamming distance 위에서 동작: 

good = [m for m, n in raw_matches if m.distance < 0.75 * n.distance]
#                     └──┬──┘              └──┬──┘
#                  1등 매칭의            2등 매칭의
#                  hamming distance      hamming distance
해석: "1등이 2등보다 25% 이상 가까우면 채택". hamming 단위가 정수라 직관적이다 — 예: m=18, n=92 → 18 < 0.75 × 92 = 69 → 통과. 하지만 m=40, n=50 → 40 < 0.75 × 50 = 37.5 → 탈락 (애매한 매칭).

7. 수학적 성질 (metric)

Hamming distance 는 진짜 거리 (metric) 의 네 조건을 모두 만족한다:

조건내용Hamming 만족?
비음수성d(x, y) ≥ 0✓ (count 는 0 이상)
동일성d(x, x) = 0✓ (XOR=0)
대칭성d(x, y) = d(y, x)✓ (XOR 은 대칭)
삼각부등식d(x, z) ≤ d(x, y) + d(y, z)✓
왜 중요한가? 거리 metric 이면 k-NN, k-means, BallTree, KD-tree 같은 공간 분할 자료구조를 그대로 쓸 수 있다. OpenCV 의 BFMatcher 가 단순 brute force 이지만, 더 큰 데이터셋에서는 LSH (Locality-Sensitive Hashing) 같은 인덱스가 hamming 위에서 잘 동작.

8. 다른 응용 분야

오류 정정 코드 (Hamming code)

7-bit 코드 안에 4 데이터 + 3 패리티 비트를 배치해서 1 비트 오류 검출 및 정정. 수신된 코드와 모든 valid 코드 사이의 hamming 을 계산해 최소 거리의 코드로 복구. 이 알고리즘 (1950) 이 hamming distance 이름의 유래.

DNA 시퀀스 비교

A, T, G, C 네 글자를 2 비트 (00, 01, 10, 11) 로 인코딩하면 두 DNA 가닥의 차이를 hamming 으로 측정 가능 — 변이(SNP) 수 직접 계산. genomics 의 가장 기본 도구.

SimHash / 문서 중복 검출

Google 이 web 인덱싱에서 사용. 각 문서를 64-bit fingerprint 로 hash → hamming 이 3 이하면 "거의 같은 문서". 수십억 문서를 빠르게 dedup.

Perceptual hashing (pHash)

이미지를 64-bit hash 로 압축 → 비슷한 이미지는 hamming 이 작음. "이 이미지가 데이터셋의 사진과 비슷한가?" 검색에 사용. ORB 와 유사한 발상.

Locality-Sensitive Hashing (LSH)

고차원 벡터를 비트로 quantize 후 hamming 으로 근사 nearest neighbor 검색. 이미지 검색, 추천 시스템, 음악 매칭에서 사용.

9. 역사: Richard Hamming 과 1950

Richard W. Hamming (1915-1998) 는 Bell Labs 에서 일하던 수학자. 1947년 어느 주말, 그가 천공 카드로 입력한 프로그램이 패리티 오류로 자동 abort 되어 주말 작업이 무산되었다. 그는 화가 나서 생각했다:

"기계가 오류를 검출할 수 있다면, 왜 정정도 못하지?"

그 후 3년간 연구해 1950 년 발표한 논문 "Error detecting and error correcting codes" (Bell System Technical Journal) 에서 hamming code 와 그 핵심 도구인 hamming distance 를 정의.

Hamming distance 가 단순 정수 카운트인데도 metric 이고, 비트 연산으로 빠르게 계산되며, 거리 기반 알고리즘에 그대로 적용된다는 점이 70년이 지난 지금도 ORB, SimHash 등에서 계속 활용되는 이유다.

여담: POPCNT 명령어는 1960년대 IBM 7030 (Stretch) 에 처음 도입되었다. NSA 가 암호 해독에서 비트 카운트를 자주 써서 하드웨어 가속을 요청했다는 일화가 있다. 현대 x86 (Intel Nehalem 2008+, AMD Barcelona 2007+) 에 표준 명령어로 들어왔고, ARM 도 NEON SIMD 에 vcnt 로 포함. 70년 된 옛 아이디어가 SEM 매칭의 속도를 만든 셈.

10. 한 줄 요약

Hamming distance = popcount(A XOR B). 두 이진 문자열의 다른 비트 개수를 세는 단순한 측정이, CPU 가 2 cycle 로 계산할 수 있는 비트 연산이라는 점에서 이진 descriptor 매칭의 표준이 되었다. ORB 가 SIFT 보다 60배 빠른 이유의 절반 이상이 hamming 덕분.
