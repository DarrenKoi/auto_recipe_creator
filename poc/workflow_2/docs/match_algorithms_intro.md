# Align Key 매칭 알고리즘 입문 — Chamfer · ORB · NMS · MI

> 대상: `poc/workflow_2/` 의 align key 매칭에 쓰이는 네 가지 핵심 알고리즘
> 목적: (1) 본인 학습용, (2) 상사 질문 대응용 설명 자료
> 작성일: 2026-05-29

---

## 0. 먼저 — 왜 "그냥 이미지 비교"로는 안 되는가

가장 먼저 받을 질문이 이것입니다. **"두 이미지가 같은 위치인지, 그냥 겹쳐보고 얼마나 똑같은지 보면 되지 않나?"**

겹쳐서 픽셀이 얼마나 같은지를 재는 고전적 방법이 **NCC**(정규화 상관)나 **SSIM**(구조적 유사도)입니다.
그런데 우리 문제에서는 이게 **1차 지표로 쓰면 안 됩니다.**

이유:

- 레시피에 등록된 align key 이미지(`from_rcp`)와 실제 측정 화면(`from_msr`)은
  **공정 변화 · 초점 · 밝기 · 대비 · 배율이 다릅니다.**
- 애초에 이 차이 때문에 align fail이 난 것이기도 합니다.
- 그래서 "같은 위치"라도 픽셀 값이 똑같지 않습니다 → **픽셀 동일성을 가정할 수 없습니다.**

따라서 우리는 **픽셀 값 자체가 아니라, 모양(edge) · 구조 · 통계적 관계**를 보는 알고리즘을 씁니다.
아래 네 가지가 그 도구입니다. 한 줄로 정리하면:

```
Chamfer  : 모양(edge)이 얼마나 맞나로 후보 점수내기   → 탐색기
NMS      : 겹쳐서 나온 후보들 중복 정리 → top-N 추리기  → 정리기
ORB+RANSAC: 특징점으로 위치를 정밀하게 맞춰보기         → 검증기
MI       : 밝기 분포의 관계로 같은 구조인지 재확인        → 검증기
```

핵심 원칙(프로젝트 전역): **최종 좌표는 CV(영상처리)가 결정하고, AI 영상모델(VLM)은 "어느 영역인지" 식별에만 쓴다.**

## 1. Chamfer Matching — 모양(edge) 기반 점수내기

### 한 문장
"두 이미지를 윤곽선(edge)만 남긴 뒤, 한쪽 윤곽선이 다른 쪽 윤곽선에 평균적으로 얼마나 가까운지"를 재는 방법.

### 직관
밝기·대비가 달라도 **물체의 윤곽(모양)은 잘 안 변합니다.** 그래서 픽셀 값 대신 윤곽선만 비교합니다.

작동 순서:

1. 두 이미지를 edge 이미지로 변환 (예: Canny edge detection).
2. 대상 이미지에 **distance transform**을 적용 — 각 픽셀에 "가장 가까운 edge까지의 거리"를 채워 넣습니다.
   (edge 위는 0, 멀어질수록 값이 큼 → 일종의 "거리 지도")
3. template(찾으려는 align key)의 edge 점들을 이 거리 지도 위에 올려놓고,
   각 edge 점이 밟은 거리 값들의 **평균**을 냅니다.
4. **평균 거리가 작을수록 = 모양이 잘 맞음.** template을 위치를 옮겨가며 계산하면, 위치별 점수 지도(score map)가 나옵니다.

### 비유
종이에 그린 별 모양 스티커(template)를, 별 윤곽이 인쇄된 종이(target) 위에서 이리저리 움직이며
"스티커 선이 인쇄된 선 위에 가장 잘 포개지는 자리"를 찾는 것과 같습니다.

### 장점 / 단점
| 장점 | 단점 |
|---|---|
| 밝기·대비 변화에 강함 (edge만 봄) | edge 검출 품질에 의존 (초점 흐리면 약함) |
| 약간의 형태 차이도 허용 (거리 기반) | 반복 패턴에서는 여러 곳이 비슷하게 맞음 |
| 계산이 비교적 가벼움 | 회전·배율은 별도 처리 필요 (여러 scale을 돌려봄) |

### 우리 프로젝트에서
align key 후보의 **1차 점수를 매기는 주 탐색기**. 여러 배율(scale)을 돌려 score map을 만들고,
가장 점수 높은 자리를 후보로 봅니다.

## 2. ORB (+ RANSAC) — 특징점으로 정밀하게 맞추기

### 한 문장
이미지에서 **눈에 띄는 점(코너 등 특징점)**을 뽑아 두 이미지 사이에서 짝지은 뒤, 그 짝들이 기하학적으로
일관되게 맞는지로 위치를 정밀 확정하는 방법.

### 직관
사람이 두 사진을 비교할 때 "이 모서리랑 저 모서리가 같은 점이네" 하고 대응시키는 것과 같습니다.

ORB = **O**riented FAST + **R**otated **B**RIEF, 두 부품의 조합입니다.

- **FAST**: 코너처럼 "주변과 확 다른 점"을 빠르게 찾아냅니다 (keypoint 검출).
- **BRIEF**: 각 keypoint 주변을 짧은 이진 코드(descriptor)로 요약합니다.
  → 코드끼리 빠르게 비교(Hamming 거리)해서 어느 점과 어느 점이 같은지 짝지을 수 있습니다.
- "Oriented / Rotated"는 **회전이 있어도** 같은 점을 알아보도록 방향을 보정한다는 뜻입니다.

그리고 **RANSAC**:

- 짝지은 대응점 중에는 **틀린 짝(outlier)**이 섞여 있습니다.
- RANSAC은 일부 대응만 무작위로 골라 "이 변환이면 몇 개의 대응이 들어맞나"를 반복 검사해,
  **가장 많은 대응이 일관되게 설명되는 기하 변환**을 찾고 나머지(틀린 짝)는 버립니다.
- 살아남은 올바른 대응 수(**inlier 수**)가 곧 "이 매칭이 얼마나 믿을 만한가"의 척도가 됩니다.

### 비유
두 장의 밤하늘 사진에서 같은 별자리를 찾는 것. 몇 개 별을 짝지어보고(ORB),
"이렇게 회전·이동하면 대부분의 별이 겹친다"는 규칙을 찾으면(RANSAC) 나머지 잘못 짝지은 별은 무시합니다.

### 장점 / 단점
| 장점 | 단점 |
|---|---|
| 회전·배율 변화에 강건 | 무늬가 적거나 밋밋한 영역은 keypoint가 안 나옴 |
| 위치를 정밀하게 확정 | 픽셀 drift가 심하면 descriptor가 안 맞음 |
| 빠르고 무료 (SIFT/SURF 특허 회피) | 반복 패턴에서 틀린 짝이 많아짐 |

### 우리 프로젝트에서
Chamfer가 찾은 후보를 **정밀 확정·검증**하는 단계. inlier 수가 적으면 신뢰도가 낮다고 판단합니다.
keypoint가 부족한 mark에는 AKAZE 같은 대체 검출기를 fallback으로 둡니다.

## 3. NMS (Non-Maximum Suppression) — 겹친 후보 정리하기

### 한 문장
점수 지도에서 거의 같은 자리를 가리키는 후보가 여러 개 나올 때, **가장 점수 높은 것만 남기고
바로 옆 중복은 억제**해서 깔끔한 top-N 후보 목록을 만드는 방법.

### 직관
Chamfer score map에서 한 봉우리(peak) 주변의 픽셀들도 점수가 높습니다. 그대로 두면
"거의 같은 위치"가 1등, 2등, 3등을 다 차지해버려 진짜 서로 다른 후보를 못 봅니다.

작동 순서:

1. 후보들을 점수 높은 순으로 정렬.
2. 1등을 채택.
3. 1등에서 **일정 거리 안에 있는 후보들은 제거(억제)** — 같은 봉우리의 중복이므로.
4. 남은 것 중 최고점을 다시 채택 → 반복.
5. 결과: **서로 떨어진, 진짜 구별되는 top-N 후보 목록.**

### 왜 중요한가 (상사 질문 포인트)
best 하나만 보면 **"2등이 1등과 거의 같은 점수"인 헷갈리는 상황을 놓칩니다.**
NMS로 distinct한 후보를 나열해야 "이 align key가 화면 안에서 유일하게 식별되는가"를 판단할 수 있습니다.
1등과 2등 점수 차이가 작으면 → "헷갈림(not distinctive)" → 함부로 채택하지 않고 보류합니다.

### 우리 프로젝트에서
Chamfer score map → NMS → top-N 후보. 이 후보들이 다음 단계(ORB/MI 검증)의 입력이 됩니다.
**틀린 1등을 무턱대고 채택하는 것을 막는 안전장치.**

## 4. MI (Mutual Information) — 밝기 분포의 "관계"로 검증

### 한 문장
두 이미지의 밝기 값이 **얼마나 일관된 관계를 갖는지**를 통계적으로 재는 지표. 값이 직접 같지 않아도,
"한쪽이 밝으면 다른 쪽은 항상 일정하게 어둡다" 같은 규칙만 있으면 높게 나옵니다.

### 직관
NCC는 "값이 같은가"를 묻지만, MI는 **"값들 사이에 예측 가능한 관계가 있는가"**를 묻습니다.
그래서 밝기·대비가 통째로 달라져도(=우리 문제의 핵심 어려움) 같은 구조면 높은 점수가 나옵니다.

원리 (개념만):

- 두 이미지를 겹쳐놓고 **joint histogram**(어떤 밝기쌍이 얼마나 자주 같이 나오는지)을 만듭니다.
- 이 분포가 **한 곳에 모여 있을수록**(= 관계가 뚜렷할수록) MI가 큽니다.
- 무관하게 흩어져 있으면 MI가 작습니다.
- 수식: `MI = H(A) + H(B) − H(A,B)` (H는 엔트로피=불확실성). 같이 보면 불확실성이 줄어드는 만큼이 MI.

### 비유
의료영상에서 MRI와 CT는 같은 장기라도 밝기 표현이 전혀 다릅니다. 그래도 "같은 위치"를 정합할 때
MI를 표준으로 씁니다 — 밝기가 달라도 **구조의 대응 관계**가 있으면 잡아내기 때문입니다.
우리의 rcp vs msr 상황과 정확히 같은 종류의 문제입니다.

### 장점 / 단점
| 장점 | 단점 |
|---|---|
| 밝기·대비 차이에 매우 강건 (multimodal 정합 표준) | 계산이 무거움 (joint histogram) |
| 픽셀 값이 달라도 구조 대응을 잡음 | 반복 패턴에서 false positive 가능 |
| `scikit-image`로 바로 사용 (모델 가중치 불필요) | 전체 화면에 돌리면 너무 느림 |

### 우리 프로젝트에서
**1차 탐색기가 아니라 후보 검증·재순위(reranking) 용.** 전체 화면에 dense하게 돌리면 너무 비싸므로,
NMS로 추린 **top-N 후보 crop에만** 적용해 동점 후보의 순위를 가립니다. 밝기 drift 대응이 강점.

## 5. 전체 파이프라인 — 어떻게 한 줄로 이어지나

```
 from_rcp (등록 align key)              from_msr (측정 화면)
     │                                       │
     │  edge 변환 + template 추출             │  crosshair 제거(inpaint) 등 전처리
     ▼                                       ▼
 ┌─────────────────────────────────────────────────────┐
 │ 1) Chamfer  : 모양 매칭으로 score map 생성 (여러 scale)│   ← 탐색기
 │ 2) NMS      : 겹친 봉우리 정리 → top-N 후보            │   ← 정리기
 │ 3) ORB+RANSAC / MI : 후보별 정밀 검증·재순위           │   ← 검증기
 └─────────────────────────────────────────────────────┘
     │
     ▼
 distinctive 한가? (1등 vs 2등 점수차 충분?)
     ├─ 예 → corrected_xy 채택 (CV가 결정한 최종 좌표)
     └─ 아니오 → 보류 (not_distinctive) — 틀린 좌표를 넘기지 않음
     │
     ▼
 (선택) VLM feasibility 게이트: "왼쪽(rcp)과 오른쪽(msr)이 같은 구조인가?"
        → 영역 식별·판단에만 사용, 좌표는 절대 결정하지 않음
```

**역할 분담 요약:**

| 단계 | 알고리즘 | 역할 |
|---|---|---|
| 탐색 | Chamfer | 모양으로 후보 점수내기 |
| 정리 | NMS | 중복 제거, top-N 추리기 |
| 검증 | ORB + RANSAC | 특징점으로 위치 정밀 확정 |
| 검증 | MI | 밝기 달라도 구조 대응 재확인 |
| 보조 | VLM | "어느 영역인지" 식별만 (좌표 결정 X) |

## 6. 상사 예상 질문 & 답변

**Q. 그냥 두 이미지 겹쳐서 똑같은지 보면 안 되나? (NCC/SSIM)**
A. 등록 이미지와 측정 이미지는 공정·초점·밝기·배율이 달라 픽셀이 동일하지 않습니다. 픽셀 값 비교(NCC/SSIM)를
1차 지표로 쓰면 같은 위치도 다르게 판정됩니다. 그래서 모양(Chamfer)·구조(ORB)·밝기 관계(MI) 기반으로 갑니다.

**Q. 왜 알고리즘을 여러 개 쓰나? 하나로 안 되나?**
A. 각자 약점이 있습니다. Chamfer는 빠르지만 반복 패턴에 약하고, ORB는 정밀하지만 무늬 적은 영역에서 실패하고,
MI는 강건하지만 느립니다. **싸고 빠른 것으로 후보를 추리고(Chamfer→NMS), 비싼 검증은 후보에만 적용(ORB/MI)**
하는 구조로 정확도와 비용을 동시에 잡습니다.

**Q. 딥러닝(AI)으로 하면 더 좋지 않나?**
A. 학습 기반 매칭(LoFTR, SuperGlue 등)도 후보군에 있습니다. 다만 모델 배포·운영 비용이 크므로,
**고전 CV로 한계를 먼저 확인한 뒤** 필요할 때 도입하는 것이 안전합니다. 또한 VLM(AI 영상모델)은 좌표를
직접 결정하지 않고 "어느 영역인지" 식별에만 씁니다 — AI 답변이 낮은 CV 점수를 뒤집지 못하게 합니다.

**Q. 최종 좌표는 무엇이 결정하나?**
A. **항상 CV(Chamfer/ORB)가 결정**합니다. MI는 동점 후보 순위 가리기, VLM은 영역 식별·타당성 판단까지만.
확신이 없으면 "보류"하고 다음 단계로 넘기지 않습니다 — 틀린 좌표를 장비 조작에 쓰는 것이 가장 위험하기 때문입니다.

**Q. 지금 잘 안 되는 이유는?**
A. 등록·측정 이미지의 차이가 커서 같은 위치가 다른 곳으로 잡히는 경우가 있습니다. 그래서 무작정 알고리즘을
더 붙이지 않고, **(1) 등록 key가 애초에 유일한지 측정 → (2) 왜 그 좌표가 뽑혔는지 계량 → (3) 후보 비교·검증**
순서의 복구 계획으로 원인부터 좁혀가는 중입니다. (`align_point_correction_recovery_plan.md`)
