1. 무슨 문제를 푸는가?

RCS 스크린샷(captured_img_from_rcs/<tag>/<tag>_rcs.jpg) 안에는 wafer 의 live SEM 영상을 보여주는 큰 사각형 하나가 있습니다. 이후의 모든 동작 — align mark 클릭, zoom, "이 프레임은 너무 흐려서 클릭하면 안 됨" 판단 — 은 전부 그 사각형의 정확한 픽셀 좌표를 필요로 합니다. box 가 20px 어긋나면 뒤따르는 모든 클릭이 20px 어긋납니다.

그래서 이 스크립트의 단 하나의 임무는 live SEM box 의 외곽선을 정밀하게 그리는 것입니다. 방식은 2-pass(2단계)입니다.

슬로건은 "VLM 이 제안하고, CV 가 확정한다" 입니다. AI 는 화면을 이해하고, classical CV 는 edge 를 측정합니다.

2. 이미지는 숫자 격자일 뿐입니다

grayscale 이미지는 밝기 값의 2D 표(matrix)입니다: 0 = 검정, 255 = 흰색입니다. 600×800 이미지는 600행 × 800열의 숫자입니다. 아래의 모든 것은 이 격자에 대한 산수이며 마법은 없습니다. 

        col0  col1  col2 ...
row 0 [  43    41    40  ... ]
row 1 [  42    45   210  ... ]   <- 210 은 밝은 픽셀입니다
row 2 [  44    40   215  ... ]
gray = cv2.cvtColor(bgr, cv2.COLOR_BGR2GRAY)   # numpy array, shape (height, width)
# gray[y, x] = y행 x열의 밝기

3. "edge(경계)" 란 무엇인가?

edge 는 밝기가 갑자기 변하는 곳입니다. SEM box 의 테두리가 곧 edge 입니다: 한쪽은 어두운 wafer 영상, 다른 쪽은 밝은 UI 프레임입니다. 숫자가 점프합니다. 

box 의 왼쪽 테두리를 가로지르는 스캔라인의 밝기:

  220 218 219 | 40 42 41 39 ...
              ^ 경계: 219 -> 40 큰 점프

평평한 영역은 거의 변하지 않습니다(40 41 40 42). edge 는 크게 변합니다(219 -> 40). CV 는 이웃 픽셀 간의 큰 변화를 찾아 edge 를 검출합니다.

4. Gradient 와 Sobel operator (핵심 도구)

한 픽셀에서의 "변화량"을 gradient 라고 합니다. 이미지판 기울기(slope, 미분)입니다: 어떤 방향으로 한 걸음 움직일 때 밝기가 얼마나 빠르게 오르내리는지를 뜻합니다.

Gradient무엇을 재는가어떤 edge 를 밝히는가
grad_x — x(좌↔우) 방향 변화옆으로 갈 때 밝기 변화 속도세로(vertical) edge (좌/우 벽)
grad_y — y(상↕하) 방향 변화아래로 갈 때 밝기 변화 속도가로(horizontal) edge (상/하 벽)
왜 교차될까요? 세로 벽은 왼쪽이 밝고 오른쪽이 어둡습니다 — 변화는 가로로 가로지를 때 일어납니다. 그래서 세로 edge 는 가로 변화(grad_x)로 검출합니다. 가로 edge 는 반대입니다. 입문자가 꼭 헷갈리니 두 번 읽으시길 권합니다.

세로 edge 는 grad_x 로 찾습니다: 밝기가 평평하다가 벽에서 점프하므로 변화(gradient)가 바로 거기서 치솟습니다.

grad_x = np.abs(cv2.Sobel(gray, cv2.CV_32F, 1, 0, ksize=3))   # (1,0)=d/dx -> 세로 edge
grad_y = np.abs(cv2.Sobel(gray, cv2.CV_32F, 0, 1, ksize=3))   # (0,1)=d/dy -> 가로 edge
  • (1,0) 은 x 방향 미분, (0,1) 은 y 방향 미분입니다.
  • CV_32F 는 부동소수점입니다(기울기는 음수일 수 있습니다 — 어두움→밝음 vs 밝음→어두움).
  • np.abs(...) 는 변화의 크기만 보고 부호는 무시합니다. 이후 큰 값 = 강한 edge, ~0 = 평평입니다.

결과적으로 grad_y 는 box 의 상/하 테두리가 빛나는 격자(긴 가로 edge)가 되고, grad_x 는 좌/우 테두리가 빛나는 격자가 됩니다.

5. Pass 1 — VLM 이 대략 사각형을 줍니다

CV 가 경계에 snap 하려면 대략 어디를 봐야 하는지 먼저 알아야 합니다. 그것이 VLM 의 일입니다 (_run_sem_box_detection, 프롬프트는 vlm_sem_monitor_box.py 의 것을 재사용합니다). VLM 은 사람처럼 상단의 Optics/OM 라벨을 찾고, 노이즈 낀 회색 live-video 질감을 알아보고, 위에 겹친 floating control panel 을 인지한 뒤 사각형을 반환합니다.

중요 디테일: VLM 은 box 를 픽셀이 아니라 0–1000 격자로 반환합니다 — 이미지를 가로·세로 1000 단위로 상상합니다. 실제 픽셀로 변환합니다: 
bbox_1000 = normalize_bbox_1000(parsed["panel_bbox"])      # 0-1000 box 검증
bbox_px   = bbox_1000_to_pixels(bbox_1000, width, height)  # 실제 픽셀 좌표로 스케일

이것이 VLM box 가 "대략적"인 이유입니다: 1920px 폭 스크린샷에서 1 격자 단위 ≈ 2px 이고 모델은 눈대중 edge 로 반올림하므로 보통 5–15px 어긋납니다. "어디를 볼지"에는 충분하지만 클릭 기준으로는 부족합니다. 그 간극을 Pass 2 가 메웁니다.

6. Pass 2 — 각 변을 실제 edge 로 snap

_snap_box_to_edges 함수입니다. 네 변을 각각 독립적으로 다듬습니다. top(위) 변을 예로 들겠습니다.

6a. search band — 짧은 목줄

band_y = max(EDGE_SNAP_BAND_MIN_PX, int(round(box_h * EDGE_SNAP_BAND_RATIO)))
# EDGE_SNAP_BAND_RATIO = 0.06  -> box 높이의 +/-6% 안에서 탐색, 최소 +/-6px

VLM 이 top 을 150행이라 했고 box 높이가 600px 라면, 150 ± 36 행만 봅니다. 이 band 가 안전 목줄입니다: CV 는 VLM 을 수십 px 보정할 수 있지만 엉뚱한 edge 로 도망갈 수는 없습니다.

6b. projection 기법 — edge 를 따라 합산

band 안에서 어느 행이 진짜 경계일까요? 경계는 긴 가로 선이므로 바로 그 행에서는 box 폭 전체에 걸쳐 grad_y 가 강합니다. 노이즈는 흩어진 단일 픽셀에서만 강합니다. 그래서 각 후보 행마다 box 폭에 걸쳐 grad_y 를 더합니다: 

strength = grad_y[lo:hi, left:right].sum(axis=1)   # 후보 행마다 합계 하나
return lo + int(np.argmax(strength))               # 합이 가장 큰 행 = 경계

일관된 경계는 거대한 합을 쌓고, 비일관 노이즈는 평균으로 묻힙니다. np.argmax 는 peak 의 인덱스를 반환할 뿐입니다.

합산이 통하는 이유(핵심 통찰): 진짜 경계는 coherent(일관)합니다 — 길이 전체에 걸쳐 강합니다. 무작위 질감은 incoherent합니다 — 여기저기 강하지만 합하면 평균으로 묻힙니다. 후보 선을 따라 합산하면 진짜 경계는 증폭되고 노이즈는 억제됩니다. 이 스크립트에서 가장 중요한 한 가지 아이디어입니다.

6c. 나머지 세 변 — 같은 아이디어를 회전

bottom 은 동일하며 VLM 의 bottom 행을 중심으로 합니다. left & right 는 세로 선을 원하므로 grad_x 를 쓰고 높이 방향으로 합산(axis=0)해 각 후보 열(column)을 채점합니다:

strength = grad_x[top:bottom, lo:hi].sum(axis=0)   # 후보 열마다 합계 하나
return lo + int(np.argmax(strength))

6d. crossing guard — 불가능한 box 방지

band 에 진짜 edge 가 없으면(완전 흐린 프레임) argmax 는 그래도 무언가를 반환하고, snap 된 bottom 이 top 보다 위로 갈 수 있습니다 — 뒤집힌 box 입니다. 이를 방지합니다:

if new_bottom <= new_top:                  # 뒤집힘 -> snap 불신
    new_top, new_bottom = top, bottom      # VLM 값으로 폴백
if new_right <= new_left:
    new_left, new_right = left, right

CV 가 명백히 혼란스러우면 쓰레기를 내놓느니 VLM 의 대략 box 를 믿습니다.

7. sharpness / blur 측정

일부 캡처는 완전히 흐려서 클릭하면 안 됩니다(대신 zoom-out/이동합니다). "초점 맞음" vs "뭉개짐"을 말해줄 숫자가 필요합니다. 표준적 싼 기법이 variance of the Laplacian입니다.

  • Laplacian 은 2차 미분 필터입니다 — 모든 방향의 미세 디테일/edge 에 반응합니다. 선명하면 큰 값이 많고, 흐리면 어디서나 작습니다.
  • Variance(분산) 은 값들이 얼마나 퍼졌는지입니다. 선명하면 넓게 퍼지고(높은 분산), 흐리면 전부 0 근처라 작은 분산입니다.
roi = gray[top:bottom, left:right]                 # SEM box 내부만
return float(cv2.Laplacian(roi, cv2.CV_64F).var()) # focus 숫자 하나

테두리 주변의 또렷한 UI 텍스트에 속지 않도록 snap 된 box 내부에서 계산합니다. 그 다음:

blurry = sharpness < SHARPNESS_BLUR_THRESHOLD  (= 60.0, 콜드스타트 추정값)
보정이 필요합니다: 60 은 추정값입니다. 실제 선명/흐린 캡처로 돌려 로그된 sharpness 값을 보고 두 군집 사이로 임계값을 정합니다.

최상위 필드 (실행 성적표)

필드의미읽는 법

이 숫자들로 시스템을 개선하는 법

  • blur 임계값 보정: 모든 sharpness 값을 모아 진짜 흐린 이미지를 눈으로 가린 뒤, SHARPNESS_BLUR_THRESHOLD 를 선명/흐림 군집 사이에 둡니다.
  • VLM 미검출 찾기: vlm_detected: false 인 row 는 프롬프트 실패 프레임이니 열어서 무엇이 특이한지 봅니다.
  • snap 실패 찾기: cv_bbox == vlm_bbox 로 정확히 같은 row 는 crossing-guard 가 snap 을 거부한 것입니다(대개 흐린 것들). sharpness 와 교차 확인합니다.
  • 다듬은 양 측정: vlm_bbox 와 cv_bbox 의 픽셀 차이는 CV 가 한 일의 양입니다. 항상 ~0 이면 VLM 이 이미 타이트한 것(또는 band 가 작은 것)이고, 크면 VLM 이 헐겁고 CV 가 정밀도를 책임지는 것입니다.

9. 아직 틀릴 수 있는 곳 (개선 여지)

  1. projection 은 직선·축정렬 경계를 가정합니다. control panel 이 box edge 위에 앉으면 band 안에서 그것의 edge 가 box edge 를 이깁니다.
  2. 각 변을 독립적으로 snap 합니다 — 합리적 종횡비 사각형을 강제하는 제약이 없고, snap 은 정수 행/열(sub-pixel 없음)입니다.
  3. band 가 고정 6% 입니다. VLM 이 6% 넘게 어긋나면 진짜 edge 가 band 밖이라 snap 이 닿지 못합니다.
  4. 흐린 / VLM 미검출 프레임은 나쁜 시작 box 를 주고 CV 가 노이즈에 충실히 snap 합니다.

다음 후보입니다: 변마다 단일 argmax 행 대신 Hough/RANSAC 직선 fitting, 네 변 사각형 일관성 제약, sub-pixel edge localization, 강한 edge 가 없으면 넓어지는 적응형 band.
