PaddleOCR Usage Guide For Workflow 2

Researched on 2026-05-28. This page summarizes when PaddleOCR should help the CD-SEM automation flow, why it has failed in full-screen GUI usage, and how to use it as a reliable OCR gate.

Use PaddleOCR as OCR evidence, not as the final GUI actor.

Practical Role Split

Deterministic CV Align-key shape matching, SEM target score, ROI constraints, crosshair and movement validation.
UI VLM Propose GUI regions, dialogs, buttons, and list rows. It gives candidates, not final truth.
PaddleOCR Read text from constrained crops, confirm unique phrases, extract table-like evidence, and save debug text.

Why It Has Been Failing

The repo currently exposes paddleocr-vl-1.5 through an OpenAI-compatible vLLM proxy. Official PaddleOCR guidance distinguishes the full PaddleOCR-VL pipeline from direct VLM-component inference. The full pipeline includes layout analysis and element recognition; direct chat-completions usage is a narrower task-prompted VLM path.

Workflow evidence points to the same conclusion: full RCS screenshots cause hallucinated or noisy text, while small dialog crops are much more stable. PaddleOCR-VL is strong on document-like elements, not on unconstrained multi-panel GUI screenshots.

Do not feed the whole RCS screen to PaddleOCR and then click from the result. Crop first, validate text, and keep a no-click path when OCR is uncertain.

Decision Matrix

Situation Use? Mode Rule
Wait Input dialog confirmation Yes OCR: on dialog crop Confirm long text such as alignment mark, not just OK.
Typed text verification Yes OCR: on field crop Use as a post-action visibility gate.
Tool row verification Sometimes Spotting: on row strip Let VLM propose the row first; use OCR only as optional verification.
Parameter table extraction Yes Table Recognition: Best for table-like panels, reports, and recipe data.
Align-key SEM matching No OpenCV/Chamfer/ORB It is a shape and edge matching problem, not OCR.
Final click coordinate from full screen No Guarded VLM/CV plus OCR gate PaddleOCR can confirm text but must not be the click authority.

Recommended Pattern

  1. Observe the screen.
  2. Use UI VLM or deterministic CV to propose a region.
  3. Crop the smallest useful region.
  4. Run PaddleOCR with a short task prompt.
  5. Normalize and validate the result.
  6. Only then continue with a guarded click or movement.
  7. On OCR failure, save artifacts and do not click.

Prompt Choices

Need Prompt Notes
Plain crop textOCR:Best default for dialog and field confirmation.
Text plus boxesSpotting:Parse defensively and bounds-check boxes.
Rows and columnsTable Recognition:Use for parameter panes or reports.
FormulaFormula Recognition:Only for formula-like document content.
ChartChart Recognition:Only for chart-like document content.

Use temperature=0.0. For small GUI crops, cap max_tokens around 128 to 512 unless the panel is truly long.

Repo Integration

from poc.workflow_1.prompts import build_ocr_assist_prompt
from poc.workflow_1.vlm_client import Workflow1VLMClient

client = Workflow1VLMClient(
    service_slug="paddleocr-vl-1.5",
    timeout_sec=120.0,
    log_name="workflow_2_ocr",
)

system_message, user_text = build_ocr_assist_prompt(width=0, height=0)
response = client.chat_with_image_b64(
    image_b64=crop_b64,
    system_message=system_message,
    user_text=user_text,
    image_mime="image/webp",
    temperature=0.0,
    max_tokens=256,
)

For Spotting:, use poc.workflow_1.ocr_spotting.parse_spotting_items() before trusting any bbox.

Experiments To Run

  • Compare whole-screen OCR against dialog/panel/row crops and keep the smallest stable crop.
  • Compare OCR: and Spotting: on the same crop.
  • Test token caps of 128, 256, and 512.
  • Save raw response, crop image, parsed result, overlay, and final verdict for replay.
  • Use negative examples where the popup or target row is absent to prove the no-click path.
