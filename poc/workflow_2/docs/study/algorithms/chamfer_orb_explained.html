1. 왜 두 알고리즘을 합치는가

SEM 으로 같은 align key 패턴을 다시 찍어도 픽셀이 완전히 같지는 않다. 공정 drift, 빔 조건 변화, focus/contrast 차이로 밝기와 디테일이 미묘하게 흔들린다. 즉 단순 NCC/SSIM 같은 픽셀 동일성 기반 매칭은 1차 지표로 쓸 수 없다.

그래서 두 가지 다른 관점으로 매칭한다:

관점알고리즘강점약점
구조 (shape) Chamfer matching 밝기 변화에 강함, 어디 있는지 빠르게 찾음 비슷한 윤곽이면 잘못 붙을 수 있음
특징 (local descriptor) ORB + RANSAC 회전/스케일/부분 가림에 강함, 기하 검증 저-텍스처 영역에선 keypoint 부족

Chamfer 가 "여기 같다" 라고 가리키면, ORB 가 "정말 같은 패턴인가?" 검증한다.

핵심 직관: Chamfer 는 localizer (어디?), ORB 는 verifier (정말 맞나?). 두 점수를 0.6 × chamfer + 0.4 × orb 로 가중합해 최종 score 를 만든다. align_key_matcher.py:47-48 의 가중치 결정 근거.

2. 파이프라인 전체 그림

템플릿은 1회만 전처리, 프레임은 매번 전처리 → Chamfer → ORB → 합성

3. 전처리: Edge map & Distance Transform

두 알고리즘 모두 edge 위에서 동작한다. 픽셀 밝기가 아니라 "어디에 윤곽선이 있나" 만 보기 때문에 brightness drift 에 둔감하다. 

# align_key_matcher.py:107-124
def preprocess_for_matching(image):
    gray    = _to_grayscale(image)
    eq      = CLAHE.apply(gray)         # 국소 대비 정규화
    blurred = GaussianBlur(eq, σ=1.0)   # 잔류 노이즈 제거
    edges   = Canny(blurred, 60, 160)   # 윤곽선 추출

    inverted = bitwise_not(edges)        # edge=0, 나머지=255
    dt       = distanceTransform(inverted, L2)  # 각 픽셀에서
                                                # 가장 가까운 edge 까지의 거리
    return edges, dt

Distance Transform 의 직관

DT 는 각 픽셀에 "가장 가까운 edge 까지 거리" 를 기록한 부드러운 점수 지도

왜 edge 끼리 직접 비교하지 않나? Edge map 끼리 XOR 하면 1픽셀만 어긋나도 점수가 망가진다. DT 위에서 합산하면 어긋남이 거리의 비례로 들어와 부드럽게 평가된다. 이게 Chamfer matching 의 본질.

4. Chamfer 매칭 — 구조 수준 localizer

템플릿의 edge mask 를 frame_dt 위에서 슬라이딩한다. 각 위치 (x, y) 마다 다음을 계산:

mean_dt(x, y) = Σ template_edges(i, j) · frame_dt(x+i, y+j) / N_edges

여기서 N_edges 는 템플릿의 edge 픽셀 개수. 이 값이 작을수록 매칭이 잘 된 것. 코드에서는 cv2.matchTemplate(frame_dt, mask, TM_CCORR) 한 줄로 모든 위치에 대해 동시에 계산. 

# align_key_matcher.py:155-198
result  = cv2.matchTemplate(frame_dt, template_mask, cv2.TM_CCORR)
min_val, _, min_loc, _ = cv2.minMaxLoc(result)
mean_dt = min_val / edge_count
score   = exp(-mean_dt / DT_TAU_PX)   # 0~1 로 변환

슬라이딩 윈도우 시각화

템플릿 edge 윤곽을 frame_dt 위에서 슬라이딩 → 거리합이 최소인 곳이 매칭 위치

점수화: exp(-mean_dt / τ)

raw mean_dt 는 픽셀 단위 거리라 해석이 어렵다. τ=10 으로 감쇠시켜 0~1 로 정규화:

5. ORB + RANSAC — 특징 수준 verifier

Chamfer 가 "윤곽이 비슷한 곳" 을 찾았다면, ORB 는 "국소적 특징점 패턴까지 진짜 같은가" 를 검증한다. ORB(Oriented FAST + Rotated BRIEF) 는 두 단계로 동작:

  1. Keypoint 검출 — corner/blob 같은 특징적인 픽셀을 찾는다 (FAST 알고리즘).
  2. Descriptor 계산 — 각 keypoint 주변 패치를 256-bit 이진 벡터로 인코딩 (rotated BRIEF).

RANSAC 은 잘못된 매칭을 걸러내고 기하적 일관성으로 "진짜 같은 패턴" 인지 점수화한다

# align_key_matcher.py:227-274
orb        = cv2.ORB_create(nfeatures=2000)
kp_t, des_t = orb.detectAndCompute(template_gray, None)
kp_f, des_f = orb.detectAndCompute(frame_gray, None)

bf       = cv2.BFMatcher(cv2.NORM_HAMMING, crossCheck=False)
raw      = bf.knnMatch(des_t, des_f, k=2)
good     = [m for m, n in raw if m.distance < 0.75 * n.distance]   # Lowe

_H, mask = cv2.findHomography(src_pts, dst_pts, cv2.RANSAC, 5.0)
inlier_ratio = mask.sum() / len(good)
왜 Chamfer 결과 주변만 ORB 로 검사하나? ORB 를 풀 프레임에서 돌리면 (a) 2000개 keypoint 가 곳곳에 분산되어 노이즈가 늘고 (b) RANSAC 의 검색 공간이 커진다. Chamfer 의 best (cx, cy) 를 중심으로 1.6× 템플릿 크기 만 잘라서 ORB 에 넘기면 빠르고 정확하다 (_crop_with_padding at line 299).

6. 합성 점수 & 결정 임계값

score = 0.6 · chamfer_score + 0.4 · orb_inlier_ratio
score 범위decision의미VLM 처리
≥ 0.75 match 레시피 align-key 와 충분히 일치 VLM 호출 불필요
0.55 ~ 0.75 adjust 비슷하지만 미세 조정 필요 VLM 에게 위치 보정 요청
< 0.55 low 매칭 실패 — 다른 위치/패턴 스파이럴 탐색 or align-fail 알림
가중치 0.6 / 0.4 의 의미: Chamfer 가 더 안정적인 신호(공정 drift 견고)이므로 가중치를 더 줬다. ORB 는 텍스처가 부족한 영역에서 0 으로 떨어질 수 있어 단독 신뢰는 위험.

7. 스케일 처리: Case A vs Case B

레시피 align-key 이미지와 현재 SEM 프레임이 항상 같은 해상도(nm/pixel) 인 것은 아니다. 코드는 두 경로로 분기 (align_key_matcher.py:386-401):

A
해상도 메타 있음

양쪽 모두 nm_per_pixel 을 알면 단일 스케일로 정확히 매칭:

scale = template.nm_per_pixel
        / frame.nm_per_pixel
scales = (scale,)   # 한 번만

빠르고 정확함.

B
메타 없음 — Fallback

해상도 미상 시 5단계 multi-scale brute force:

scales = (0.7, 0.85, 1.0, 1.2, 1.4)
# Chamfer 점수가 가장 높은 스케일 채택

느리지만 견고함.

8. 한 줄 요약

Chamfer 가 edge 분포로 "어디에 있나" 를 빠르게 찾고, ORB+RANSAC 이 keypoint 기하로 "정말 같은가" 를 검증한다. 둘을 0.6 · C + 0.4 · O 로 합친 점수가 match / adjust / low 의 결정 신호가 된다.
