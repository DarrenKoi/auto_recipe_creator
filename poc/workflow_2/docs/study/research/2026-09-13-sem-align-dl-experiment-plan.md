# SEM align point 정밀 추정 — DL 실험 기획

> **사용자 검토용 초안 · 2026-09-13**
> 목표는 표식 검출이 아니라 **recipe가 지정한 지점을 SEM에서 몇 픽셀 이내로 찾는 것**이다.
> 이 문서는 실험 기획이다. 모델 학습·장비 조작·운영 배포를 수행하거나 승인한 기록이 아니다.

> **실행 준비:** [수집·폴더 구조·첫 실험 가이드](2026-09-13-sem-align-dl-start-guide.md) · [읽기용 HTML](2026-09-13-sem-align-dl-start-guide.html)

## 1. 먼저 읽을 제안

**기존 consensus를 기준선으로 유지하고, YOLO keypoint와 EfficientLoFTR를 비교한다.** 어느 모델이 이길지는 정하지 않는다. 작은 데이터로 라벨·잔상·좌표 계약을 검증한 후 유망한 방식만 확대한다.

세 가지 질문에 답하는 실험이다.

1. 기존 CV가 놓친 SEM align point를 DL이 추가로 찾는가?
2. 그 정확도는 실제 패턴에서 오는가, crosshair와 제거 흔적에서 오는가?
3. 같은 오답 허용 수준에서 consensus 단독보다 더 많은 이미지를 처리할 수 있는가?

**제약은 확정되어 있다.** 오버레이 없는 원본은 구할 수 없다. Recipe/MSR 이미지와 cond.txt를 활용한다. 수십만 장에 접근할 수 있다는 사용자 설명은 데이터 자산의 가능성이지, 유효한 학습 쌍 수가 집계됐다는 뜻은 아니다. 장비 허용 오차는 “몇 픽셀 이내”이며 정확한 수치는 아직 확정하지 않았다.

## 2. 공통 사전

| 용어 | 이 문서에서의 의미 |
|---|---|
| Reference / recipe 이미지 | Recipe에 등록된 이미지. 성공 MSR이나 consensus를 reference라고 부르지 않는다 |
| MSR 이미지 | 측정 과정에서 저장된 S(정상 step)·E(fail step) 이미지 |
| Live 이미지 | 실제 복구 중 캡처한 현재 SEM 영상. 저장 MSR과 표시 크기·상태가 다를 수 있다 |
| Align key | 정렬에 사용하는 패턴·표식 또는 그 영역 |
| Align point | Recipe가 지정한 기준점에 대응하는 정밀 좌표 |
| Box | 관심 패턴을 지정하는 영역. 그 중심이 align point라는 보장은 없다 |
| Crosshair | 영상의 십자 표시. 정상 성공 위치의 라벨 후보지만, 실패 상태의 표시는 복구 정답이 아니다 |
| Template | 매칭에 사용하는 기준 패치. Recipe crop 또는 consensus template |
| Consensus | 호환되는 과거 정상 S 패치를 정렬·합성한 template. DL 모델이 아니다 |
| 후보 포함률 | 정답 근처가 후보 목록 안에 들어 있는 비율 |
| 좌표 적중률 | 예측점과 정답점의 거리가 정해진 허용 오차 이내인 비율 |
| 복구 성공률 | 실제 장비에서 정렬·측정 재개 등의 성공 근거가 관측된 비율. 오프라인 좌표 적중률과 다르다 |

다른 팀의 “OM 약 99%”는 사용자에 따르면 **align key 위치 검출** 성과다. 우리 SEM 정밀 좌표 성능의 예상치나 목표 근거로 사용하지 않는다.

## 3. 현재 근거와 다시 측정할 것

[기존 평가 문서](../../../../../docs/project_progress/03_workflow_2.md)는 recipe 단일 기준에서 consensus로 바꾼 뒤 후보 포함률 0.434→0.876, rank1 0.318→0.764를 기록한다. 별도 재순위 평가의 0.826과 잔여 실패 중 약 87% 후보 누락도 기록돼 있다. **서로 다른 평가 집합의 숫자를 이어 붙이거나 현재 SEM 실전 성능으로 해석하지 않는다.**

작성 시점에는 다른 작업에서 표시 배율·consensus 입력 계약이 수정 중이다. [표시 scale 계약](../../../../workflow_3/docs/study/align_display_scale_contract_260913.md)을 참고하되, 이 기획은 해당 변경을 수정하거나 검증 완료로 판정하지 않는다. 실험 시작 전에 기준 코드와 데이터를 고정하고 모든 arm을 다시 실행해야 한다.

후보 누락은 현재 후보 생성기의 한계라는 증거다. 이미지에 정보가 없다는 증거는 아니다. 반대로 반복 패턴의 잘못된 주기를 택하는 경우는 대응점이 많이 나와도 실패할 수 있다. 따라서 “CV 실패=DL로 해결 가능”, “반복 패턴=항상 해결 불가”를 모두 가정하지 않는다.

## 4. cond.txt를 정답으로 만드는 규칙

### 4.1 알려진 입력과 찾아야 할 정답을 분리한다

```text
알려진 입력: recipe 영상 + recipe box + recipe 기준점 기하
찾아야 할 값: target MSR의 align point (x, y)
라벨 후보: 성공이 확인된 정상 S의 cond crosshair 좌표
```

[현재 기하 코드](../../../../workflow_3/align/cond_template.py)는 recipe 이미지 중심을 align point로 두고 box 중심과의 offset을 보존한다. Crop 중심을 새 정답으로 바꾸지 않는다. [cond 파서](../../../../workflow_3/align/cond_file.py)의 cond_for_image와 좌표 변환을 사용해 실제 로드 크기로 맞춘다. 단순히 모든 숫자를 10으로 나누는 별도 파서를 만들지 않는다.

라벨에는 원본 크기, cond.Pixel, 배율, crop 원점, resize/padding 변환, recipe 기준점, target 좌표, 라벨 출처·검증 상태를 함께 보존한다. 모델 출력은 원본 target 영상 좌표로 되돌린 뒤 채점한다. 학습 중 좌표를 불필요하게 정수로 반올림하지 않는다.

### 4.2 S와 E를 다르게 취급한다

| 데이터 | 허용하는 사용 | 금지하는 추론 |
|---|---|---|
| 정상 S + 유효 cond | 성공 상태·step 대응을 점검한 뒤 point supervision | S 파일명만으로 몇 픽셀 정밀도의 절대 정답이라고 단정 |
| 실패 E + cond | 실패 분포 분석, 독립 정답이 있는 경우 평가 | 현재 crosshair를 복구 정답으로 복사 |
| E의 사람 검토 좌표 | 확실한 좌표만 별도 품질 등급으로 평가 | 애매한 반복 패턴에 억지로 한 점 지정 |
| 좌표 없는 S/E | 패치 합성 학습 등 무라벨 활용 | 기존 CV 예측을 무검토 정답으로 재사용 |

초기에는 recipe·장비·배율·S/E별 층화 표본을 눈으로 대조한다. 좌표 결측, 해상도 불일치, step 불일치, 박스 밖 기준점, 성공 판정 불확실, 복수 정답 가능을 집계한다. cond의 0.1픽셀 표현은 장비 정렬 정확도가 0.1픽셀이라는 의미가 아니다.

## 5. 오버레이 없는 원본 없이 학습하는 방법

### 5.1 원본과 정제본은 둘 다 보존한다

[기존 clean_image](../../../../workflow_3/align/clean_align_image.py)는 박스·십자선 주변을 TELEA inpainting으로 메운다. 이를 관측된 원본 영상으로 취급하지 않는다. 원본, 제거 mask, 정제 설정, 정제본을 연결해 보관한다. 밝은 SEM 구조까지 임계값으로 일괄 삭제하지 않는다.

Recipe box는 관심 영역을 알려주는 정당한 입력이다. 반면 정상 MSR crosshair와 그 제거 흔적은 정답 위치와 연결돼 있다. 검은 칠·blur·inpainting 중 어느 방법도 그 관계를 자동으로 없애지 않는다. 특히 target 제거 mask를 추가 입력으로 넣으면 교점 자체가 정답을 누설할 수 있다.

### 5.2 단계 A — 실제 패턴으로 정밀 대응을 배우게 한다

표시와 제거 영향 영역을 피한 SEM 패치에서 겹치는 두 view를 만들고, 알려진 이동·배율 등으로 대응 좌표를 생성한다. 변환은 실제 장비에서 가능한 범위로 제한한다. 회전·비등방 변형은 필요성을 확인한 뒤 추가한다.

이 합성 학습은 **여러 점의 기하 정답**을 얻는 방법이다. 실제 recipe↔MSR의 공정 차이를 재현한 실데이터 성공률이 아니다. 오버레이가 없는 작은 패치를 확보할 수 있는 비율도 먼저 측정하며, 표본이 특정 쉬운 패턴에 편중되면 별도 보고한다. 십자선이 영상 전체를 가로지르므로 무영향 패치는 사분면으로 제한될 수 있다. 중심 부근·실제 key 구조가 빠지는 위치 편향과 패치 크기 분포를 함께 측정한다.

### 5.3 단계 B — 실제 recipe↔정상 MSR로 도메인 적응

cond가 주는 target 한 점으로 align point 출력을 감독한다. **한 점 라벨만으로 영상 전체의 dense 대응 관계가 정답이라고 가정하지 않는다.** Correspondence 모델은 합성 쌍의 기하 학습과 실제 쌍의 point loss를 구분해야 하며, 공개 학습 코드를 그대로 실행하는 것만으로 이 연결이 완성되지는 않는다.

원본·정제본·여러 정제 설정과 정답에 무관한 위치의 가림을 비교한다. 추가 가림은 누설을 약화시키는 실험일 뿐 해결의 증명은 아니다. 실제 point 감독을 추가하기 전후에 잔상 의존 검사를 반복한다.

### 5.4 잔상 의존을 확인하는 시험

| 시험 | 의미와 한계 |
|---|---|
| 동일 정상 패치의 선 없음 / 임의 선 합성 / 합성 선 제거 paired 비교 | 같은 패턴과 정답을 고정하고 예측 좌표 이동량을 측정. 실제 원본 전체의 검증을 대체하지 않는다 |
| 동일 실제 쌍의 제거 두께·방법을 변경 | 실제 정답은 고정하고 예측 좌표 변화량을 측정. 모든 방법에 공통된 흔적은 남을 수 있다 |
| 패턴을 약화시키고 표시/흔적만 남긴 진단 입력 | 높은 성능이면 shortcut의 경고. 낮은 성능만으로 shortcut 부재가 증명되지는 않는다 |
| 합성 쌍 모델과 실제 point 미세조정 모델 비교 | 미세조정 후 실제 점수만 상승하고 흔적 민감도가 커지는지 점검 |
| 독립 좌표가 있는 실제 E 평가 | 실패 조건 전이 확인. E 라벨이 불확실하면 정밀 성공률을 산출하지 않는다 |

정답 위치의 십자선을 포함해 전체 영상을 이동시키는 것만으로는 누설이 끊기지 않는다. 표시와 정답이 함께 이동하기 때문이다. Saliency 시각화 한 장도 누설 부재의 증명이 아니다.

손상 영역의 대응점을 제외하는 후처리도 예외가 아니다. Target cond mask를 바꾸었을 때 결과가 그 교점을 따라가는지 별도 대조한다. 주변 대응의 기하 일관성은 필요한 검사지만 반복 격자의 잘못된 주기도 일관될 수 있으므로 정답 보증으로 쓰지 않는다.

## 6. 비교 모델과 회사 사용 조건

| Arm | 입력과 역할 | 먼저 확인할 질문 |
|---|---|---|
| B0 — Recipe + 기존 CV | 등록 영상만으로 현재 성능 측정 | Consensus 없는 경우의 기준은 무엇인가 |
| B1 — 기존 consensus 우선 / recipe 폴백 + CV | 실제 기존 운영 선택 규칙을 재현 | 현재 채택 기준선을 얼마나 개선하는가 |
| D1 — EfficientLoFTR | Recipe↔MSR 대응점에서 align point 계산 | 패턴 대응으로 후보 누락과 정밀 오차를 줄이는가 |
| Y1 — YOLO keypoint | SEM에서 학습한 기준점·다중 후보 추정 | 표식 외형만으로 recipe 기준점을 식별할 수 있는가 |
| Y2 — YOLO 영역 제안 + reference/consensus 정밀 정합 | 검출 영역에서 기준점을 정밀화 | 검출과 정합을 나누면 최종 오차가 줄어드는가 |
| D2 — 유망 DL + consensus | D1/Y2 중 유망군에 consensus를 추가 | 외관 적응 효과가 DL에도 유효한가 |

Y1을 미리 배제하지 않는다. 다만 keypoint 의미가 recipe마다 달라지면 SEM-only 입력으로 해답을 정의하기 어려울 수 있다. 고정 의미의 표식 계열과 recipe 의존 계열을 분리한다. Y1의 box annotation이 필요한 구현에서는 recipe box를 target box로 복사하지 않는다. 정상 MSR에서 대상 영역 라벨을 어떻게 확보할지 확인하고, 없다면 작은 표본부터 추가한다. Point 주변의 임의 고정 박스는 실제 검출 정답과 구분한다.

Y1에는 일반 사전학습 모델을 그대로 써도 우리 align point를 알 수 없으므로 소규모 감독 학습이 필요하다. D1의 사전학습 zero-shot은 연결성 확인용이고, 모델 우열의 최종 비교는 동일한 실제 학습·평가 데이터와 보고된 자원 예산에서 한다. 입력 정보가 다른 Y1과 D1은 단순 동급 순위가 아니라 설계 선택지로 비교한다.

### 라이선스 게이트 — 이름보다 실제 반입 artifact 기준

| 모델/구현 | 확인한 공개 조건 | 이 계획의 취급 |
|---|---|---|
| EfficientLoFTR | 공식 코드 Apache-2.0, 공식 repo에서 연결한 zju-community HF 모델도 Apache-2.0 표시 | 우선 후보. 실제 commit·weight hash·라이선스 고지 보존 |
| YOLO keypoint | 구현·가중치 미선정. Ultralytics 구현은 AGPL-3.0/Enterprise 경로 | 회사 요구에 맞는 사용 조건 확인 전 실행 후보 확정 안 함. 기획 비교군에는 유지 |
| XFeat | 저장소 Apache-2.0, weights도 제공 | 작은 비교 모델 후보. 가중치 적용 조건을 확인한 뒤 사용 |
| DISK + LightGlue | LightGlue 코드·가중치 Apache-2.0 명시, DISK도 같은 라이선스로 안내 | 후속 대안. 제한적인 SuperPoint 구성과 혼동 금지 |
| RoMa v1 | 코드 MIT, DINOv2 Apache-2.0; RoMa 가중치 적용 범위 별도 확인 | 초기 범위를 늘리지 않고 후속 비교로 보류 |

오픈소스 공개와 무조건적인 회사 사용 허용은 동의어가 아니다. 코드·가중치·backbone·실제로 사용하는 의존성·학습 데이터 조건을 기록한다. 무료 상업 사용이 필수라면 유료 계약이 필요한 구성은 후보에서 제외하고 그 사실을 보고한다. YOLO를 새 구현으로 바꿀 경우 모델명·라이선스·추가 개발 비용을 함께 다시 판단한다. 모델과 데이터는 사내에서 학습·추론하며 외부 서비스에 SEM을 업로드하지 않는다.

## 7. Consensus와 함께 쓰는 설계

**Consensus는 ‘어떤 외관을 기준으로 삼는가’, DL은 ‘어떻게 대응 위치를 찾는가’에 대한 선택이다. 둘은 대체 관계로 고정되지 않는다.**

```text
Recipe 기하 + 과거 검증된 정상 S
                 ↓
      기존 consensus 품질·호환성 검사
         통과: consensus / 실패: recipe
                 ↓
       기존 CV 결과와 DL 결과를 별도 산출
                 ↓
     원본 좌표 환산 · 신뢰도 보정 · 불일치 확인
                 ↓
         오프라인 채점 → 후속 shadow
```

초기에는 결과를 별도로 비교한다. 무조건 점수 평균·다수결을 하지 않는다. CV와 DL의 raw score는 척도가 다르며, 같은 잔상으로 둘 다 틀리면 합의도 독립 증거가 아니다.

추천 순서는 D1(recipe) → D2(동일 모델에 기존 consensus 선택 규칙 적용)이다. Recipe의 기하와 consensus의 좌표 anchor를 명시적으로 연결하고 offset을 두 번 더하지 않는다. 영상 resize·crop·표시 배율을 통과한 최종 좌표가 같은 target 픽셀계인지 확인한다.

그 뒤 검증 집합에서만 “CV 불확실 시 DL 추가 조회” 같은 라우팅을 평가한다. **B1이 이미 맞히던 샘플에서 생긴 회귀와 B1 실패에서의 신규 적중을 함께 센다.** DL 후보를 기존 Chamfer 점수로 재평가해 모두 버리면 추가 후보 효과가 사라질 수 있으므로, 독립 결과 arm과 점수 보존 arm을 구분한다.

Consensus 재료는 평가 target 시점보다 과거인 검증된 S만 사용한다. Target 자신·같은 이벤트의 사후 결과·미래 S는 제외한다. LOO만으로 시간 누설이 해결됐다고 보지 않는다. DL 예측으로 정렬한 이미지를 자동으로 “성공 S”에 넣거나 학습 정답으로 누적하지 않는다. 실제 장비 성공 근거와 별도 품질 절차를 거쳐야 한다.

이 시간 필터는 실험에서 구현·검증할 요구사항이며 현재 evaluator가 보장한다는 뜻이 아니다. 수집 event_id·manifest에서 실제 촬영/측정 순서를 복원할 수 있는지 감사한다. 다운로드 시각과 파일 mtime을 촬영 시각으로 간주하지 않는다. 순서를 증명할 수 없으면 해당 샘플의 시간 순서 consensus 평가는 제외하거나, 앞으로 수집할 이벤트의 출처·시각을 기록한 뒤 수행한다. 시간 정보가 없는 LOO 결과는 별도 탐색 결과로만 표시한다.

## 8. 진행 순서와 중단 기준

기간은 데이터 반입·라벨 품질·GPU 확인 전에는 약속하지 않는다. 다음 산출물이 준비됐을 때만 다음 단계로 넘어간다.

| 단계 | 할 일 | 산출물 / 다음 단계 조건 |
|---|---|---|
| 0. 기준 고정 | 다른 작업 완료 후 코드 revision, 데이터 snapshot, scale/consensus 설정을 고정. 과거 감사의 offset·scale band·평가 대상 선정 문제가 현재 코드에서 해결됐는지 확인 | B0/B1 재측정. 채점 좌표·대상 집합을 왜곡하는 미해결 결함은 수정/제외 결정 후 실행. 과거 golden과 분리된 기준선 |
| 1. 데이터·라벨 감사 | 중복, 고유 recipe, S/E, SEM 배율, 좌표 유효율, MSR box 보유율, box/point 의미, 측정 시각 복원 가능성 확인 | 사용할 학습 쌍과 제외 사유. 불확실한 좌표는 학습에서 제외 |
| 2. 독립 평가 구성 | recipe/패턴 계열 group split, 과거→미래 평가, 장비 holdout | 고정 train/validation/test manifest와 라벨 품질 등급 |
| 3. 작은 비교 | B0/B1, D1 사전학습, Y1 소규모 학습, 합성 패치 정밀 평가 | 정밀 적중률·잔상 민감도·실패 사례. 라이선스 미확정 모델은 실행 제외 |
| 4. 유망군 적응 | 합성 correspondence → 실제 point 감독, 필요 시 Y2 | 동일 budget 비교. 실제 성능 개선과 shortcut 증가를 구분 |
| 5. Consensus 결합 | 동일 모델의 recipe/consensus 비교, fallback 및 혼합 라우팅 | B1 대비 순개선, 회귀, coverage-risk 곡선 |
| 6. 잠근 test 평가 | 임계값·모델 고정 후 test를 한 번 평가 | 95% 신뢰구간과 장비·recipe별 실패 분석 |
| 7. 사내 shadow | 별도 실행 승인 후 live를 관측만 하고 좌표·지연·보류 기록 | Offline→live 차이 확인. 장비 조작·복구 성공 주장은 별도 검증 |

초기 표본 수 제안은 고유 recipe/패턴 계열 50~100개, 유효한 실제 쌍 500~2,000개다. 이는 확보 약속이나 통계적 충분성 기준이 아닌 탐색 규모다. 실제 다양성과 군집별 표본 수에 따라 조정하고, 데이터가 적으면 결론의 범위를 좁힌다. 처음부터 수십만 장을 모두 학습하지 않는다.

중단·재설계 조건은 좌표 라벨 오차가 요구 정밀도와 비슷함, 합성에서는 맞지만 실제에서는 개선 없음, 잔상 변화에 따라 예측이 이동함, 확신하는 큰 오답 증가, 또는 허용 조건의 모델 부재다. 일부 실패는 더 큰 모델이 아니라 재등록·추가 문맥·엔지니어 판단으로 넘긴다.

## 9. 평가 기준 — 정답 개수와 처리 가능한 비율을 함께 본다

기본 오차는 원본 target 영상에서의 유클리드 거리다.

```text
error_px = sqrt((pred_x - gt_x)^2 + (pred_y - gt_y)^2)
```

1·2·3·5픽셀 이내 적중률을 모두 보고한다. 최종 통과 기준 t와 큰 오차 기준 E_large는 장비 요구에 맞춰 test 공개 전에 정한다. 저장 영상의 3픽셀과 2배 표시 live의 3픽셀은 같은 오차가 아니므로, 저장 원본 기준 오차와 실제 live 표시 오차를 구분한다. 물리 단위 변환은 보정 정보 없이 추정하지 않는다.

| 지표 | 목적 |
|---|---|
| 전체 정밀 적중률 | 보류도 미처리로 포함한 전체 성과. 보류를 분모에서 몰래 제외하지 않는다 |
| 채택한 결과의 오답률 + 채택률 | 같은 위험 수준에서 처리 범위가 늘었는지 판단 |
| 큰 오차 발생률 | 평균 오차가 가리는 위험한 실패 확인 |
| 기존 B1 실패의 신규 적중 / B1 정답의 신규 실패 | DL의 순효과 확인 |
| 후보 recall@8/@24 | 후보를 내는 arm에서 원인 분석. 최종 정밀 적중률을 대체하지 않는다 |
| Recipe별·배율별 성능, E-label 품질별 성능 | 쉬운 대량 S가 어려운 실패를 가리지 않도록 분리 |
| p50/p95 지연, 메모리, 전처리 시간 | 사내 실행 환경에서 사용 가능한지 확인 |

임계값은 validation에서 고정한다. 동일 recipe의 이미지를 독립 표본처럼 부풀리지 않고 recipe/패턴 group 단위 paired bootstrap으로 성능 차이의 95% 신뢰구간을 낸다. 표본 부족이면 신뢰구간이 넓다는 사실을 그대로 보고한다.

일반화 평가는 두 갈래로 분리한다. **새 recipe/패턴 계열**은 학습과 완전히 분리한다. **기존 recipe의 미래 이벤트**는 과거 데이터 사용을 허용하되 시간 순서를 지킨다. 같은 class/recipe를 여러 장비가 공유하므로 장비 ID만 다른 동일 recipe가 양쪽에 섞이지 않게 한다. 고정 test는 self-supervised 학습과 합성 패치 추출에서도 제외한다.

유사 패턴 group은 recipe 계보·공정/표식 분류·중복 해시와 엔지니어 확인을 우선 사용한다. Box 크기나 offset만으로 같은 패턴이라고 확정하지 않는다. 비교 대상 모델의 점수로 유리한 split을 만들지 않으며, 분류가 불확실한 계열은 보수적으로 함께 묶거나 별도 보고한다.

기존 golden은 과거 모델·임계값 선택에 반복 사용됐다면 개발·회귀 평가용이다. 이름이 golden이라는 이유로 미사용 최종 test가 되지 않는다. 최종 일반화 판정에는 별도로 확보해 잠근 신규 holdout을 사용한다. 신규 test 확보가 어렵다면 탐색 결과만 보고하고 독립 최종 검증은 미완료로 남긴다.

## 10. 기대 효과와 보장할 수 없는 것

| 기대하는 효과 — 가설 | 확인 방법 | 한계 |
|---|---|---|
| 학습 특징이 CV가 놓친 패턴을 찾음 | B1 후보 누락에서 신규 적중 | 반복 구조의 다른 주기로 이동할 수 있음 |
| 주변 대응점으로 가려진 기준점 위치를 계산 | 손상 영역 밖 대응의 일관성과 point 오차 | 주변에 충분한 구별 단서가 없으면 불가능 |
| Consensus가 최근 외관을 반영해 DL도 개선 | 동일 모델 recipe vs consensus | 합성 blur·반복 잔상이 DL을 더 방해할 수 있음 |
| YOLO keypoint가 빠르게 직접 좌표 추정 | 표식 계열별 정밀 적중률 | Recipe 의존 기준점과 다중 표식 선택 문제 |
| 신뢰도 보정으로 처리 가능한 샘플 확대 | 같은 오답 허용 수준의 채택률 | 신뢰도 점수만으로 안전을 보장하지 않음 |

90%·95%·99% 등의 목표 성공률을 현재 근거로 예측하지 않는다. “DL의 점수 상승”보다 **실제 정밀 적중 증가와 큰 오답 억제**가 투자 판단 기준이다. 실제 E의 신뢰할 만한 정답이 부족하면 “정상 S에서의 정밀 위치 추정 가능성”까지만 결론낸다.

## 11. 사용자 검토 사항

이 문서를 읽고 우선 다음 항목을 확인하면 실행 계획을 구체화할 수 있다. 답을 받기 전 임의 수치로 장비 합격 기준을 확정하지 않는다.

1. 허용 오차: 어느 해상도·배율 기준으로 몇 픽셀인가? 큰 오답·보류의 허용 수준은 무엇인가?
2. 기준점 의미: 같은 표식이면 항상 같은 물리 지점인가, recipe마다 다른 지점인가?
3. S 라벨 신뢰: 정상 S의 crosshair가 성공 결과를 나타내는 저장 시점인가? 관련 step/성공 상태를 결합할 수 있는가?
4. 실패 라벨: 일부 E에서 엔지니어가 확실한 정답을 지정할 수 있는가? 불가능하면 S 평가의 한계를 수용하는가?
5. 회사 사용: 무료 상업 사용만 허용하는가? 기존 팀의 YOLO 구현·가중치와 사용 조건을 공유받을 수 있는가?
6. 자원: 내부 GPU, 데이터 반입 경로, 작은 표본 검토 담당자를 확보할 수 있는가?

검토 뒤 우선 승인할 범위는 **기준선 고정 + 데이터/라벨 감사 + 소규모 오프라인 비교 설계 확정**이다. 대규모 학습과 장비 적용은 결과를 보고 별도로 결정한다.

## 12. 논의 기록과 근거

Herdr의 Claude pane `wP:p7`에서 읽기 전용 설계 제안과 반론·초안 검토의 두 차례 대화를 진행했다. 모델 학습이나 실데이터 성능 검증을 수행한 것은 아니다.

| 논의 쟁점 | 반론을 거쳐 문서에 반영한 결론 |
|---|---|
| 완벽한 ROI에서도 기존 matcher가 실패하면 YOLO를 중단할 것인가 | ROI+matcher 경로와 직접 keypoint 경로는 다르므로 Y1을 일괄 배제하지 않는다 |
| 정제 S와 E를 구분하는 CNN으로 잔상을 증명할 수 있는가 | 성공/실패 외관 차이가 섞이므로 증명 불가. 같은 패치의 paired 시험으로 대체 |
| 가짜 crosshair 추가가 정답 누설을 완전히 제거하는가 | 원래 흔적은 남으므로 약화 실험으로만 취급 |
| 기존 golden을 최종 test로 사용할 것인가 | 과거 튜닝에 사용했다면 개발/회귀용. 신규 holdout이 필요 |
| Consensus의 시간 순서를 바로 보장할 수 있는가 | 시각 출처를 감사하고 증명 불가 표본은 시간 평가에서 제외 |
| 수치 상승을 미리 예상할 것인가 | 과거 추정 성공률을 채택하지 않고 픽셀 오차·큰 오답·보류율로 판단 |

Claude가 제안한 다수 추가 모델을 모두 초기 arm에 넣지는 않았다. 범위를 B0/B1·D1·Y1 중심으로 유지하고 Y2/D2는 유망군 후속 비교로 정리했다. 최종 모델 선택·오차 기준·회사 사용 가능 여부는 사용자 검토 및 실험 전 확인 사항이다.
