0. 전체 그림: 문제는 하나다

이 파이프라인이 푸는 문제는 딱 하나입니다. "레시피에 등록된 align key 그림(template) 이 지금 장비 화면(frame) 의 어디에 있나?" 답은 좌표 하나 best_xy 입니다.

등장하는 알고리즘 12개는 전부 이 문제를 세 단계로 나눈 자리에 꽂혀 있습니다.

입력
template (찾을 그림) + frame (지금 화면)
↓
① 후보 만들기 (proposer)
전처리 → edge → distance transform → Chamfer ×3 채널 (C1/C2/C3) → 5개 배율 → NMS
↓
② 후보 합치기 (fusion)
RRF 로 세 채널의 순위표를 하나로 → 앞 8개만 통과
↓
③ 후보 다시 줄세우기 (reranker)
NCC → OM 이면 MIND, SEM 이면 ECC
↓
판정
1등 점수를 임계값(0.6053 / 0.4727) 에 대 봄 → match / adjust / low
왜 세 단계로 나누나?

"화면 전체를 픽셀 하나하나 정밀하게 비교" 는 너무 느리고, 정밀한 비교법(NCC, ECC) 은 대충 맞는 자리 근처에서만 의미가 있습니다. 그래서 값싸고 거친 방법(Chamfer) 으로 후보 몇 개를 뽑고, 비싼 방법으로 그 몇 개만 다시 봅니다. 검색엔진이 키워드로 1차 검색하고 상위 결과만 정밀 랭킹하는 것과 같은 구조입니다.

감사 문서의 핵심 결론이 여기서 나옵니다. 남은 실패의 87% 가 "정답이 ① 단계 후보 8개 안에 아예 없음" 이었습니다. ③ 단계 재순위가 아무리 좋아져도 없는 후보를 뽑을 수는 없으니, 고칠 곳은 ① 입니다.

1. 전처리: Grayscale · CLAHE · Gaussian blur

① proposerengine.py:181-238

Grayscale (흑백 변환)

색을 버리고 밝기만 남깁니다. SEM/OM 화면은 원래 거의 흑백이고, edge 검출은 밝기 변화만 보기 때문에 색 채널 3개를 1개로 줄여 계산량을 1/3 로 만듭니다.

CLAHE (국소 대비 평활화)

비유: 사진 앱의 "그림자 밝히기". 화면을 8×8 타일로 쪼개 타일마다 어두운 곳은 밝히고 밝은 곳은 눌러서, 어느 구역이든 구조가 비슷한 대비로 보이게 합니다. "C" 는 Contrast-Limited, 즉 노이즈까지 과하게 키우지 않도록 상한(clip 2.0) 을 둔다는 뜻입니다.

Gaussian blur (가우시안 흐림)

비유: 살짝 초점을 흐리기. 각 픽셀을 주변 픽셀과 평균내서 자잘한 노이즈 점을 지웁니다. sigma 1.0 이면 아주 약하게 흐립니다. edge 검출 전에 하는 이유는 노이즈 점 하나하나가 가짜 edge 로 잡히는 것을 막기 위해서입니다.

원본 (노이즈 포함)
Gaussian blur 후
우리 코드: build_template() 과 live frame 양쪽에 같은 순서(CLAHE clip 2.0 tile 8×8 → sigma 1.0 → Canny 60/160) 로 적용. 값은 전부 고정 상수.

2. Edge 검출: Canny · Scharr

① proposerengine.py:36-47, ensemble.py:16-42

Edge 란? 밝기가 급격히 바뀌는 자리, 즉 물체의 윤곽선입니다. 이 파이프라인은 "그림 자체" 가 아니라 "윤곽선의 모양" 을 비교합니다. 공정이 바뀌어 전체 밝기가 달라져도 윤곽선의 위치는 잘 안 바뀐다는 믿음 때문입니다.

Gradient (기울기) → Scharr

각 픽셀에서 "옆 픽셀과 밝기가 얼마나 다른가" 를 잰 값이 gradient 입니다. 크면 윤곽선일 가능성이 큽니다. Scharr 는 그 차이를 재는 3×3 필터 중 하나로, 방향 정확도가 좋은 버전입니다. gradient 는 크기(얼마나 급한가) 와 방향(어느 쪽으로 밝아지는가) 두 가지를 줍니다. 방향은 5절 C3 에서 씁니다.

Canny

gradient 크기를 그냥 임계값으로 자르면 선이 두껍고 끊깁니다. Canny 는 세 가지를 더 합니다.

  1. 얇게 만들기: gradient 방향으로 봤을 때 가장 큰 픽셀만 남김 (선 두께 1px).
  2. 두 개의 임계값 (60 / 160): 160 이상이면 확실한 edge, 60 미만이면 버림.
  3. 이력 추적(hysteresis): 60~160 사이의 애매한 픽셀은 확실한 edge 에 붙어 있을 때만 살림. 그래서 끊긴 선이 이어집니다.
gradient 크기 (밝을수록 급한 변화)
edge 결과 (흰 픽셀 = edge)
high 를 올리면 흐릿한 원(오른쪽 아래) 의 윤곽이 먼저 사라집니다. 이것이 "공정 drift 로 약한 edge 가 임계값 아래로 내려가면 C1 이 깨진다" 의 뜻입니다.

C2 가 Canny 대신 쓰는 방법: 밀도 맞추기

C2 채널은 고정 임계값 대신 "gradient 가 큰 상위 몇 %" 를 edge 로 삼습니다. frame 에서 Canny 가 만든 edge 비율을 재서 3~15% 사이로 맞추고, template 도 같은 비율로 자릅니다. 약한 edge 가 살아남는 대신, 텍스처가 없는 화면에서는 3% 를 채우려고 노이즈까지 edge 가 됩니다.

감사 지적: Canny 60/160, 밀도 3~15% 가 OM/SEM 구분 없이 고정값. focus·charging·노이즈로 edge 집합이 바뀌면 C1/C2 모두 정답 근처 점수가 내려간다.

3. Distance Transform (거리 변환)

① proposerengine.py:254-287

한 줄: edge 지도에서, 모든 픽셀에 "가장 가까운 edge 까지 몇 픽셀인가" 를 적어 넣은 표.

비유: 지도에서 모든 지점에 "가장 가까운 편의점까지 거리" 를 적어 두는 것. 한 번 만들어 두면 어디에 서 있든 거리를 계산 없이 바로 읽을 수 있습니다.

이게 필요한 이유: 4절 Chamfer 는 template 의 edge 픽셀 수백 개를 화면 위 수만 개 위치에 놓아 보며 "각 edge 가 frame edge 에 얼마나 가까운가" 를 묻습니다. 매번 가장 가까운 edge 를 찾으면 너무 느리지만, 이 표가 있으면 표에서 값을 읽기만 하면 됩니다.

edge (거리 0)가까움멈
우리 코드: frame 의 Canny edge 에 cv2.distanceTransform 을 한 번 만들어 두고, 모든 후보 위치와 모든 배율의 Chamfer 계산이 이 표를 공유합니다.

4. Chamfer Matching (C1 · C2)

① proposerengine.py:337-379, ensemble.py:145-162

한 줄: template 의 윤곽선을 화면 위 어떤 자리에 올려놓았을 때, 윤곽선 픽셀들이 화면의 윤곽선에 평균적으로 얼마나 가까운가.

비유: 투명 필름에 그린 도장 윤곽을 사진 위에서 밀어 보기. 필름의 선이 사진의 선 위에 딱 겹치면 거리가 0 이고, 어긋나면 거리가 커집니다. 모든 자리에서 "평균 거리" 를 재고 가장 작은 자리가 답입니다.

계산은 3절의 표 덕분에 간단합니다.

  1. template edge 픽셀 하나하나를 후보 위치로 옮긴다.
  2. 그 자리의 distance transform 값을 읽는다.
  3. 평균을 낸다 (mean_dt).
  4. 점수로 바꾼다: score = exp(-mean_dt / 10). 평균 거리 0 이면 1.0, 10px 면 0.37, 멀수록 0 에 가까워집니다. "10" 이 감사에 나오는 DT_TAU_PX 입니다.
현재 위치 점수
-

C1 과 C2 의 차이는 edge 를 뽑는 법뿐입니다. C1 은 CLAHE+blur+Canny, C2 는 Scharr 크기 상위 % 입니다. 그 뒤 "옮기고 → 표 읽고 → 평균" 은 완전히 같은 함수입니다.

감사 지적 (핵심): 위 데모에서 "반복 line/space" 를 눌러 보세요. 정답 자리와 한 pitch 옆으로 밀린 자리의 점수가 거의 같습니다. Chamfer 는 "선 위에 선이 있나" 만 보므로 긴 직선을 따라 미끄러져도 점수가 안 변합니다. 실측 truth-forced 분석에서 실패의 67% 가 이런 wrong local peak 였습니다.

5. Directional Chamfer (C3)

① proposerensemble.py:45-110

한 줄: Chamfer 인데, "가까운 edge" 를 셀 때 같은 방향의 edge 만 인정.

비유: 4절의 도장 필름 맞추기에서, 필름의 가로선은 사진의 가로선 위에만 올라가야 인정하고 세로선 위에 올라간 건 무효. 2절에서 얻은 gradient 방향 을 0~180° 8칸(22.5° 씩) 으로 나눠, 칸마다 따로 distance transform 을 만들고 같은 칸끼리만 거리를 잽니다.

polarity(밝→어둠 / 어둠→밝) 를 무시하기 때문에, SEM 에서 흔한 명암 반전에도 강합니다.

감사 지적: line/space 패턴은 어차피 전부 가로·세로선이라 정답과 한 pitch 밀린 자리의 방향 분포가 똑같습니다. 방향을 봐도 구분이 안 됩니다. junction(선이 만나는 모서리) 이 crop 안에 충분히 보일 때만 C1/C2 보다 낫습니다. 또 C3 만 배율 간 NMS(6절) 가 없어 같은 자리가 RRF(7절) 에 여러 표를 넣는 결함이 있습니다.

6. Multi-scale 탐색과 NMS

① proposerengine.py:309-371, correction.py:58-64

Multi-scale (배율 5개)

template 이 등록될 때와 지금 화면의 배율이 다를 수 있습니다. 그래서 template 을 0.70 / 0.85 / 1.00 / 1.20 / 1.40 배로 키우고 줄여 5번 탐색합니다. 실제 비율이 이 밖(예: 0.5 배) 이면 다섯 번 전부 정답을 못 찾습니다. 감사에서 "band 가 고정되고 끝에 걸려도 경고만 한다" 가 이 얘기입니다.

NMS (Non-Maximum Suppression, 비최대 억제)

한 줄: 점수가 높은 자리 근처의 조금 낮은 자리들은 "같은 것을 가리킨다" 고 보고 지움.

비유: 산봉우리 찾기. 정상 바로 옆 1m 아래 지점도 높지만 그건 같은 산이지 다른 산이 아닙니다. 정상 하나만 남기고 반경 안은 지웁니다. 반경은 template 짧은 변의 50% 입니다.

문제: 반복 패턴에서 정답 봉우리가 높은 decoy 봉우리의 반경(50%) 안에 있으면 정답이 억제되어 후보에서 사라집니다. 뒷단 재순위는 사라진 후보를 되살릴 수 없습니다 (감사 4.1-4).

7. RRF (Reciprocal Rank Fusion): 세 채널 투표 합치기

② fusionensemble.py:177-222

한 줄: 세 채널이 각각 낸 "후보 순위표" 를 점수 크기 상관없이 등수만 보고 하나로 합침.

비유: 심사위원 3명이 각자 순위를 매겼는데 점수 기준이 제각각(한 명은 100점 만점, 한 명은 10점 만점). 점수를 그대로 더하면 100점짜리가 지배하니, 대신 1등이면 1/(10+1), 2등이면 1/(10+2)… 로 환산해 더합니다. 여러 심사위원이 상위에 올린 후보가 이깁니다.

세 채널이 같은 자리를 살짝 다른 좌표로 찍을 수 있어서, template 짧은 변의 5% (최소 8px) 안이면 같은 후보로 묶습니다.

공식: fused(c) = Σ_channel 1 / (10 + rank_channel(c)). 순위에 없으면 0.
감사 지적: 합친 24개 중 앞 8개만 다음 단계로 넘깁니다 (top_n=8). 정답이 9~24등이면 여기서 버려집니다. 그리고 넘긴 8개도 다시 C1 Canny Chamfer 로 재채점하므로, C2/C3 만 살린 후보(또는 미래의 학습 후보) 는 여기서 또 밀립니다.

8. NCC (Normalized Cross-Correlation)

③ rerankerengine.py:545-565, 921-931

한 줄: 두 그림 조각이 "같은 모양으로 밝고 어두운가" 를 -1 ~ +1 로 잰 값. 전체 밝기·대비 차이는 무시.

비유: 두 사람의 하루 기분 그래프가 비슷하게 오르내리는가. 한 사람이 늘 더 기분이 좋아도(밝기 차이), 기복이 두 배여도(대비 차이) 오르내리는 타이밍 이 같으면 +1 입니다. 정반대로 움직이면 -1 입니다.

계산: 각 조각에서 평균을 빼고(밝기 제거), 표준편차로 나눈 뒤(대비 제거), 픽셀끼리 곱해 평균냅니다. 여기까지 Chamfer 는 "윤곽선" 만 봤는데, NCC 는 처음으로 회색 원본 픽셀 을 봅니다. 후보 8개 각각에 대해 0.5 × chamfer + 0.5 × max(0, NCC) 로 새 점수를 만듭니다.

감사 지적: 음수 NCC 를 0 으로 자르므로 명암이 반전된(charging 등) 정답은 증거가 통째로 사라집니다. 또 어차피 top-8 안에서만 계산되므로 없는 정답은 못 봅니다.

9. MIND (Modality Independent Neighbourhood Descriptor)

③ reranker · OM 전용mind_rerank.py:35-165

한 줄: 픽셀의 밝기 대신 "이 픽셀이 주변 8방향 이웃과 얼마나 닮았나" 라는 패턴 8개로 그림을 다시 그린 뒤 비교.

비유: 사람을 얼굴색이 아니라 "왼쪽 이웃과 닮았나, 오른쪽 이웃과 닮았나…" 로 묘사하기. 조명이 바뀌어 모두가 어두워져도 "누가 누구와 닮았나" 는 안 변합니다. 원래 의료영상에서 CT 와 MRI 처럼 밝기 규칙이 완전히 다른 두 영상을 맞추려고 만든 방법이라 이름에 "modality independent" 가 붙었습니다.

OM 에서는 NCC 순위(sel) 와 MIND 순위를 다시 RRF(k=8) 로 합쳐 최종 1등을 고릅니다. MIND 점수가 0.10 미만이거나 평평하면 그 후보는 거부합니다. 좌표는 새로 만들지 않고 순서만 바꿉니다.

감사 지적: 반복 lattice 는 정답과 decoy 의 "닮음 지문" 이 같습니다. 그리고 순서만 바꾸므로 proposer 가 놓친 정답은 절대 복구 못 합니다.

10. ECC (Enhanced Correlation Coefficient) 정합

③ reranker · SEM 전용mind_rerank.py:168-206

한 줄: 후보 조각을 template 위에 올려놓고 "조금씩 밀어서 가장 잘 겹치는 자리" 를 반복 계산으로 찾은 뒤, 그때의 겹침 점수(cc) 를 씀.

비유: 투명 필름 두 장을 겹쳐 놓고 손으로 살살 밀며 가장 딱 맞는 자리를 찾기. NCC(8절) 가 "지금 자리에서 얼마나 맞나" 한 번 재는 것이라면, ECC 는 "근처에서 제일 잘 맞는 자리까지 밀어 보고 그때 얼마나 맞나" 를 잽니다. 그래서 후보가 1~2px 어긋나 있어도 공정하게 평가됩니다.

OpenCV 의 findTransformECC 를 translation(평행이동) 만 허용, 최대 100회 반복, 가우시안 5 로 돌립니다. cc < 0.05 이면 거부.

SEM 에서는 NCC 순위를 MIND 와 합치지 않고 ECC cc 순위 단독 으로 바꿉니다. 벤치에서 섞으면 오히려 낮아졌기 때문입니다(route_sw 0.826 > 혼합 0.820). 전부 거부되면 NCC 순위로 돌아갑니다.

감사 지적: 반복 패턴은 wrong phase 에도 높은 local optimum 이 있고, 공정 drift 가 비선형 형태 변화를 만들면 엉뚱한 봉우리로 수렴합니다. 역시 순서만 바꿉니다.

11. 임계값(Youden J) 과 평가 지표

판정 · 벤치engine.py:148-159, align_similarity.py:301-324

임계값 0.6053 / 0.4727 은 어디서 왔나

최종 1등의 점수(0.5×chamfer + 0.5×NCC) 를 보고 match / adjust / low 를 정합니다. 두 숫자는 S 이미지 756장에서 "정답 위치 점수" 와 "오답 위치 점수" 분포를 보고 정했습니다.

  • Youden J (0.6053): 임계값을 움직이며 정답 통과율 + 오답 차단율 이 최대가 되는 지점. 두 분포가 가장 잘 갈리는 컷.
  • recall 0.95 지점 (0.4727): 정답의 95% 가 통과하도록 낮춘 컷. 그래서 "adjust(애매하지만 시도)" 구간의 하한.
감사 지적: OM/SEM 을 섞어서 잰 값을 modality 별 reranker 뒤에도 공통으로 씁니다. 그리고 0.5/0.5 가중치에 결박되어 있어 점수 공식을 바꾸면 반드시 다시 재야 합니다.

LOO (Leave-One-Out)

같은 recipe 의 성공 이미지(S) 가 3장이면, 1장을 시험지로 빼고 나머지 2장으로 template(12절 consensus) 을 만들어 시험지에서 찾아 봅니다. 3장을 돌아가며 반복. 데이터가 적을 때 쓰는 평가법인데, "같은 recipe 의 비슷한 시점 사진" 이라 실제보다 쉬운 시험이라는 것이 감사 3.3 의 지적입니다.

12. 부록: consensus median · inpaint · align_offset

Consensus template (중앙값 합성)

최근 성공 이미지 여러 장에서 align point 주변을 같은 크기로 잘라, 픽셀마다 중앙값 을 취해 한 장으로 만듭니다. 평균 대신 중앙값을 쓰는 이유는 한 장에 튀는 노이즈가 있어도 결과에 안 섞이기 때문입니다. 자르기 전에 crop 끼리 미세하게 정렬(co-register) 하고, 만든 결과가 너무 흐리면(edge 밀도 0.70 / Laplacian 분산 0.50 미만) 버리고 레시피 등록 이미지로 돌아갑니다.

"최근 공정 외형" 을 따라가므로 벤치에서 in_topk 0.434 → 0.876 으로 크게 올랐습니다. 이게 ① proposer 에서 현재 가장 큰 레버입니다.

Inpaint (지우고 메우기)

성공 이미지에는 십자선(crosshair) 이, 레시피 이미지에는 흰 박스가 그려져 있습니다. 이 선들은 실제 회로가 아닌데 edge 로 강하게 잡혀 매칭을 오염시킵니다. cv2.inpaint(TELEA) 는 그 선 자리를 "주변 픽셀로 자연스럽게 메워" 지웁니다. 사진 앱의 "잡티 제거" 와 같습니다.

align_offset_xy

레시피 이미지의 흰 박스는 "여기가 특징적이니 이걸로 찾아라" 는 힌트이고, 실제 align point 는 이미지 중심입니다. 그래서 박스 안쪽을 template 으로 쓰되, 이미지 중심 − 박스 중심 을 따로 저장해 두고 찾은 뒤 배율을 곱해 더합니다. Consensus 는 align point 를 중심으로 자르므로 offset 이 0 입니다.

13. 왜 "aperture problem" 이 핵심 실패인가

Aperture(구멍) problem: 작은 구멍으로 긴 직선을 보면, 선이 선을 따라 움직이는 것은 알아챌 수 없습니다. 구멍 안 모습이 똑같기 때문입니다. 선에 수직 으로 움직이는 것만 보입니다.

SEM align key 는 화면을 80~100% 채우는 line/space 패턴입니다. 위치를 "고정" 해 주는 정보는 선이 만나거나 끝나는 junction 뿐이고, 나머지 긴 직선 구간은 어디에 올려도 점수가 같습니다. 그래서 4절 데모의 "반복 line/space" 처럼 점수 지형이 평평해지고, 한 pitch 밀린 decoy 가 정답과 동점이 됩니다.
