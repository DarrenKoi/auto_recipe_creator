# 평가 방법 입문 (1) — 분류 vs 위치추정

> 시리즈 1번. 선행: [eval_guide_00_overview_glossary_ko](eval_guide_00_overview_glossary_ko.md)
> 이 문서의 한 줄: **"맞다/틀리다"를 세는 것(분류)과 "어디냐"를 재는 것(위치추정)은
> 완전히 다른 평가이고, 우리 생산 과제는 후자다.**

---

## 1. 두 가지 "정답 맞히기"

머신러닝/CV에서 성능을 잴 때 가장 먼저 정해야 하는 건 **"무엇을 맞히는 과제인가"** 이다.
크게 두 종류가 있다.

### (A) Classification (분류) — "어느 칸이냐"

답이 **범주(category)** 다. 예:

- 이 메일은 스팸인가 / 아닌가 (2칸)
- 이 사진은 개 / 고양이 / 새 (3칸)
- 이 측정은 **성공(S) / 실패(E)** 인가 ← 우리 도메인의 예

채점은 단순하다. 맞으면 1, 틀리면 0. **개수를 센다.**

### (B) Localization (위치추정) — "어느 지점이냐"

답이 **이미지 안의 좌표(점)** 다. 예:

- 얼굴 사진에서 눈동자 중심은 (x, y) 어디인가
- 웨이퍼 화면에서 **align key 가 있는 위치는 (x, y) 어디인가** ← 우리 생산 과제

채점이 다르다. "맞다/틀리다"가 칼로 자르듯 떨어지지 않는다. 3픽셀 빗나간 것과
300픽셀 빗나간 것은 둘 다 "틀림"이라고 뭉뚱그리면 안 된다. **거리(distance)** 로 잰다.

> 비유:
> - 분류 = O/X 문제 채점 (맞았어? 틀렸어?)
> - 위치추정 = 다트 채점 (불스아이에서 몇 cm 벗어났어?)

---

## 2. 우리가 *원래* 쓰던 지표 — bACC (그리고 그 한계)

`golden_localization_eval.py` 가 생기기 전, 우리는 `align_similarity.py` /
`align_index_ablation.py` 에서 **bACC(balanced accuracy)** 라는 *분류* 지표를 썼다.
이게 뭔지, 왜 부족했는지 알면 새 스크립트의 존재 이유가 또렷해진다.

### 2-1. accuracy 와 bACC

먼저 그냥 **accuracy(정확도)**:

```
accuracy = 맞힌 개수 / 전체 개수
```

문제: 데이터가 한쪽으로 쏠리면(class imbalance) 정확도가 거짓말을 한다.
S가 95개, E가 5개인데 모델이 "전부 S"라고만 답해도 accuracy = 95%다. E는 하나도 못 잡았는데도.

그래서 **balanced accuracy(bACC)** 를 쓴다. 각 범주를 *따로* 채점하고 평균낸다.

```
sensitivity (S를 S로 맞힌 비율)  = TP / (TP + FN)
specificity (E를 E로 맞힌 비율)  = TN / (TN + FP)
bACC = (sensitivity + specificity) / 2
```

- **TP/TN/FP/FN** 은 분류 채점의 4칸이다(아래 confusion matrix).
- bACC = 0.5 면 "동전 던지기 수준"(무의미), 1.0 이면 완벽.

```
              실제 S        실제 E
예측 S    TP(맞음)     FP(틀림: E를 S라 함)
예측 E    FN(틀림)     TN(맞음)
```

### 2-2. bACC 로는 생산 과제를 못 잰 이유 (3가지)

스크립트 docstring(§1)에 적힌 그대로다. 초보 눈높이로 풀면:

1. **과제 자체가 다르다.**
   bACC 는 "align key 가 *있나 없나*"를 가르는 **분류** 점수다. 그런데 생산에서 진짜 필요한 건
   "key 가 *어디 있나*"라는 **좌표**다. 시험으로 치면, 우리가 풀 문제는 주관식(위치)인데
   객관식(있다/없다) 점수로 실력을 매겨온 셈이다.

2. **recipe 마다 점수 기준선이 다르다 (cross-recipe confound).**
   매처가 내는 절대 점수(예: chamfer 0.62)는 recipe(=등록 이미지 종류)마다 의미가 다르다.
   배율도 다르고 패턴 복잡도도 달라서다. 그런데 bACC 는 **전 recipe 를 하나의 전역 임계값**으로
   S/E 를 가른다. 마치 과목마다 난이도가 다른데 전 과목을 "60점 컷"으로 자르는 것과 같다.
   → 이 "숨은 제3의 원인(recipe 차이)"이 결과를 흐리는 게 **confound** 다(시리즈 3에서 다룸).

3. **E 의 정답을 못 믿는다.**
   bACC 를 잘 내려면 E 도 제대로 채점해야 하는데, E 프레임의 십자선은 *틀린 자리거나 없다*.
   답안지가 오염된 채로 채점하는 격이다.

## 3. 그래서 — "위치추정"을 직접 재기로

위 세 문제의 공통 해법: **정답을 믿을 수 있는 데이터(S)에서, 좌표를 직접 채점하자.**

이게 `golden_localization_eval.py` 의 출발점이다. 핵심 전환:

| | 옛 방식 (bACC) | 새 방식 (golden localization) |
|---|---|---|
| 과제 | 분류 (S/E 있나) | 위치추정 (어디냐) |
| 정답 | S·E 라벨 | S 프레임의 십자선 좌표 |
| 채점 | 전역 임계로 자른 개수 | 예측점↔정답점 **거리** |
| confound | 있음(recipe간 전역 임계) | **없음** (아래 설명) |

### 왜 위치추정은 confound 에서 자유로운가 — 중요한 직관

위치추정의 hit/miss 는 **"한 프레임 안에서, 그 프레임 자신의 십자선까지의 거리"** 로 정해진다.
recipe A의 점수와 recipe B의 점수를 *섞어 하나의 임계로 자르는 일이 없다*. 채점이
**프레임마다 독립적인 이진값**(맞았다/빗나갔다)이라, recipe 간 기준선 차이가 끼어들 틈이 없다.

> 비유: 양궁에서 "과녁 정중앙에서 몇 cm 벗어났나"는 어느 사대(射臺)에서 쏘든 의미가 같다.
> 반면 "이 점수면 합격"의 합격선은 종목마다 달라 비교가 어렵다. 거리는 절대 기준, 임계는 상대 기준.

---

## 4. 한 가지 주의 — 위치추정이라고 거리만 보는 건 아니다

거리(`dist_norm`)는 *연속값*이지만, 생산 현장은 결국 **"한 번에 맞혔나(hit) 아닌가"** 라는
*이진 결정*도 필요하다(장비는 점 하나를 찍어야 하니까). 그래서 새 방식도

- 연속 정밀도: `dist_norm` 의 median / p90
- 이진 명중: `rank1_hit_rate` (거리가 허용오차 안이면 hit)

**둘 다** 본다. 거리로 정밀도를, hit 비율로 실용 성공률을 잡는다. 다음 문서의 주제다.
