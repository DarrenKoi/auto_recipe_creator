# White-box(Align-key box) 레시피 숫자 패턴 참조

## 1. 목적 / 배경

White box(align-key box)를 CV(Chamfer/ORB)로 검출하기 어려운 상황에서,
대안으로 **장비 레시피 raw data를 직접 뒤져 box의 위치·크기 숫자**를 찾으려고 한다.
레시피 raw에는 숫자가 매우 많은데, white box가 가진 **물리적 제약**
( 중앙 위치 · 정사각형 · 전체 면적의 약 10% )이 만드는 **고유한 숫자 지문(signature)**을
미리 정리해 두면, grep / 시각 검사로 후보 숫자를 빠르게 좁힐 수 있다.

> 이 문서는 **참조용**이다. 실제 파서/탐지 스크립트는 샘플 raw 파일이 확보된 뒤에 붙인다.

---

## 2. Box를 숫자로 표현하는 4대 포맷

회전(theta)이 없는 **축 정렬(axis-aligned) 사각형**이므로 **숫자 4개**면 완전히 표현된다.

| 포맷 | 구성 | 의미 | 별칭 |
|---|---|---|---|
| **Corner (모서리)** | `(left, top, right, bottom)` | 좌상단·우하단 두 점 | Pascal VOC |
| **Center+Size** | `(cx, cy, w, h)` | 중심 + 크기 | YOLO 스타일 |
| **Origin+Size** | `(x, y, w, h)` | 좌상단 + 크기 | OpenCV `boundingRect` |
| **정규화** | `[0,1]` 또는 `[0,1000]` | 해상도 독립 비율 | — |

### 2.1 코드베이스 기존 컨벤션 매핑

레시피 값이 들어오면 결국 아래 둘 중 하나로 환산해서 쓰게 된다.

| 컨벤션 | 위치 | 형태 |
|---|---|---|
| `{left, top, right, bottom}` [0,1000] | `poc/workflow_1/util/json_utils.py:124` `normalize_bbox_1000()` | VLM 좌표 내부 표준 |
| `(x, y, w, h)` 픽셀 | `poc/workflow_2/white_box_detectors.py:105` `BoxCandidate` | OpenCV 검출 결과 |
| center `xy` + `template_size (tw,th)` | `poc/workflow_2/align_key_matcher.py:81` `AlignKeyCandidate` | Chamfer 매칭 결과 |

- 픽셀 ↔ [0,1000] 환산: `bbox_1000_to_pixels()` (`json_utils.py:187`), 중심 계산 `bbox_center()`.
- **회전/theta 필드는 어디에도 없음** → 축 정렬 사각형 전제.

## 3. "중앙 + 정사각형 + 10%" 숫자 지문

"전체의 10%"는 두 가지로 해석될 수 있어 **둘 다** 정리한다.

- **면적 10%** : box 넓이 = 0.10 × 이미지 넓이 → 한 변 = √0.10 ≈ **0.316 × L**
- **선형 10%** : 한 변 = 0.10 × L

### 3.1 면적 10% 해석 (변 = 0.316 × L)

| 항목 | 512×512 | 1024×1024 |
|---|---|---|
| 변 길이 (px) | **162** | **324** |
| 반변 (px) | 81 | 162 |
| 중심 (px) | 256, 256 | 512, 512 |
| Corner `l/t/r/b` (px) | 175 / 175 / 337 / 337 | 350 / 350 / 674 / 674 |
| Origin `x,y,w,h` (px) | 175, 175, 162, 162 | 350, 350, 324, 324 |
| 정규화 [0,1] (cx,cy,w,h) | 0.5, 0.5, 0.316, 0.316 | 0.5, 0.5, 0.316, 0.316 |
| 정규화 [0,1000] `l/t/r/b` | 342 / 342 / 658 / 658 | 342 / 342 / 658 / 658 |

### 3.2 선형 10% 해석 (변 = 0.10 × L)

| 항목 | 512×512 | 1024×1024 |
|---|---|---|
| 변 길이 (px) | **51** | **102** |
| 중심 (px) | 256, 256 | 512, 512 |
| Corner `l/t/r/b` (px) | 230 / 230 / 282 / 282 | 461 / 461 / 563 / 563 |
| 정규화 [0,1] (w,h) | 0.10, 0.10 | 0.10, 0.10 |
| 정규화 [0,1000] `l/t/r/b` | 450 / 450 / 550 / 550 | 450 / 450 / 550 / 550 |

> 정규화/[0,1000] 값은 **해상도와 무관하게 동일**하다 — 이게 픽셀 저장과 구분하는 핵심 단서(§5).

## 4. 물리 단위(nm)로 저장된 경우 — SEM 레시피에서 흔함

레시피는 픽셀이 아니라 **stage / FOV 기준 물리 단위(nm·µm) + 배율**로 저장하는 경우가 많다.
픽셀 환산의 키가 되는 값은 코드의 `nm_per_pixel` (`align_key_matcher.py:75`, `sem_panel_locator.py:15`) 이다.

- **중앙** → 패턴/FOV 중심 대비 **offset = (0, 0)** 로 나타남 ← 매우 강한 단서
- box 크기 → **nm 단위 width / height** 로 저장
- 검증: `W_nm / FOV_nm ≈ 0.316`(면적 10%) 또는 `≈ 0.10`(선형 10%) 이면 그게 white box
- 즉 픽셀 `162` 대신 `(0, 0, W_nm, H_nm)` 형태일 수 있음

## 5. Raw data 탐색 휴리스틱 (체크리스트)

숫자가 아무리 많아도 아래 특징으로 후보를 좁힐 수 있다.

1. **같은 값 2개** — 정사각형이라 `w == h`. 연속된 동일 숫자 쌍을 찾는다.
2. **중앙 흔적** — 좌표가 `이미지치수 / 2` (256 또는 512) **이거나**, offset이 `0` / `(0,0)`.
3. **Corner 대칭** — `left + right = L`, `top + bottom = L` (512 또는 1024).
   중앙 정사각형이면 추가로 `left == top`, `right == bottom`.
4. **교차 스케일 검증(가장 확실)** — 같은 align key의 **512 레시피 vs 1024 레시피** 비교:
   - 숫자가 **약 2배** 변함 → **픽셀 저장**
   - 숫자가 **그대로** → **정규화 또는 물리 단위(nm)** 저장
5. **4-tuple + 라벨 근접** — 4개 숫자 묶음 근처에 §7의 라벨 키가 있는지.

## 8. 주의사항

- **좌표계 방향**: 이미지 좌표는 보통 **y-down**, stage/wafer 좌표는 **y-up** → top/bottom이 뒤집힐 수 있음.
- **원점 위치**: 좌상단(0,0) 기준일 수도, **이미지 중앙(0,0)** 기준일 수도 있음(중앙 기준이면 offset 0이 곧 중심).
- **정밀도**: 정수 픽셀이 아니라 **서브픽셀 float**(예: `161.9`, `255.5`)로 저장되는 경우가 흔함.
- **half-width 저장**: 크기를 변 길이가 아니라 **반변(half-size)** 으로 저장하면 81 / 162 같은 절반 값이 보일 수 있음.
