  • 진행: 매처를 교란하는 두 인공 표식(등록 이미지의 흰 박스, 측정 이미지의 십자)을 각각 제거하는 전처리를 만들고, 효과를 같은 잣대로 재는 2×2 비교 실험을 구축.

이전까지의 진행 (지난주, 배경)

↩ 지난주까지 완료한 토대
  1. Workflow 1 (RCS 자동화) — 로그인 → Tool 선택 → Align Fail 감지 → 화면 캡처까지 이미 완성. 이번 주 작업의 입력(실패 시점 캡처)을 안정적으로 공급하는 기반으로 활용.
  2. Workflow 2 마지막 관문 완성 — 보정을 실제 적용하는 OK 버튼 자동 클릭(vlm_wait_input_ok_button.py)과 모든 탐색의 기준점인 SEM 화면 영역(박스) 검출(outline_live_sem_box.py) 완료.
  3. Align Point 보정 착수(난항) — 등록·측정 이미지가 공정 변화로 픽셀 단위로 같지 않아 같은 위치를 못 잡는 문제 확인 → "기능을 더 붙이기 전에 원인부터 계량"하는 단계별 복구 계획 수립. 이번 주 그 진단을 정면으로 실행.

이번 주 상세 — 진행 / 문제 / 해결 (10문장)

▶ 진행 중인 일
  1. 웨이퍼 측정 이미지에서 레시피에 등록된 align 위치를 다시 찾아내는 Align Point 보정의 좌표 정확도를 이번 주 핵심 과제로 다루는 중.
  2. 매처를 교란하는 두 표식 — 등록 이미지의 흰 주석 박스, 측정 이미지의 십자(crosshair) — 를 각각 제거하는 전처리 구현(align_point_correction.py, crosshair_removal_check.py).
  3. 두 전처리가 실제로 지표를 올리는지 같은 잣대로 재는 2×2 비교 실험(on/off 4조합) 구축(align_index_ablation.py).
⚠ 겪고 있는 문제
  1. 매처가 진짜 패턴 대신 표식에 끌려가는 것이 정확도 저하의 핵심 원인 — 흰 박스는 template를 오염, 십자는 강한 직선 edge라 거기에 "치팅" 고정.
  2. 기존 분류 정확도(있음/없음, bACC)만으로는 "좌표를 실제로 맞히는가"를 판정 못 해 생산 과제와의 연결이 약함.
  3. 모든 코드는 합성 데이터로 동작은 검증했으나, 실데이터(오피스) 판정·임계값 튜닝이 남아 효과의 실제 크기 미확정.
✔ 해결을 위해 진행 중
  1. 흰 박스는 고정 디지털 값(히스토그램 섬)으로 검출 후 안쪽만 crop, 실패 시 top-hat+Otsu로 자동 폴백(최악 샘플 1/6 → 6/6).
  2. 십자는 검출 위치를 정답으로 기록 후 inpaint로 지운 화면에서 매칭(생산 실화면=십자 없음에 충실), 제거 품질은 재검출+edge 밀도로 이중 검증.
  3. 정답 신뢰 가능한 S(성공) 전용 위치추정 검증(golden_localization_eval.py)으로 1발 명중률(rank-1 hit)을 거리로 직접 측정.
  4. 다음 단계: 오피스 실데이터 수집 → 2×2 비교·S-전용 검증 실행 → 효과의 주범 분해 후 임계값 튜닝.
