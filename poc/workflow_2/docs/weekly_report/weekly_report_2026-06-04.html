주간 진행 보고

기간: 2026-05-29 ~ 2026-06-04 · 범위: poc/workflow_2/ (Align Point 보정 — 정확도 진단)
지난주 핵심 난제로 식별한 Align Point 보정 정확도를 이번 주에 정면으로 다뤘습니다. 매처가 같은 위치를 못 잡는 두 가지 원인 — ① 등록 이미지의 흰 주석 박스와 ② 측정 이미지의 십자(crosshair) — 를 각각 제거하는 방법을 만들고, "이 두 정리가 실제로 지표를 올리는가"를 같은 잣대로 재는 2×2 비교 실험을 구축했습니다. 나아가 분류 정확도(bACC)의 한계를 넘어 "좌표를 진짜 맞히는가"를 거리로 직접 재는 S(성공) 전용 검증을 준비했습니다. 모든 코드는 합성 데이터로 동작 검증 완료, 실데이터(오피스) 판정은 다음 단계입니다.

① 이번 주 핵심 성과

정리 1 · 완성(합성검증)
흰 주석 박스 제거 — 등록 이미지 쪽
엔지니어가 align 위치를 표시한 흰 박스가 template 에 섞여 매처를 교란합니다. 소프트웨어가 그린 박스는 항상 고정된 디지털 값(255)으로 찍힌다는 점을 이용해 (히스토그램에서 분리된 섬) 박스를 정확히 찾고, 박스 안쪽만 깨끗이 잘라 template 으로 씁니다. 최악 샘플 검출률 1/6 → 6/6으로 개선. (align_point_correction.py)
정리 2 · 완성(합성검증)
십자(crosshair) 제거 — 측정 이미지 쪽
측정 이미지의 십자는 강한 직선 edge라 매처가 거기에 "치팅" 고정됩니다. 게다가 실제 생산 화면엔 십자가 없으므로(우리가 찍을 위치를 찾는 중), 십자를 지운(inpaint) 화면에서 매칭하는 것이 생산에 더 충실합니다. 제거가 제대로 됐는지 재검출 + edge 밀도 검사로 이중 검증합니다. (crosshair_removal_check.py)
검증 도구 · 완성(합성검증)
2×2 비교 실험 — "정말 좋아지나"를 측정
기능을 더 붙이기 전에 두 정리가 실제로 지표를 올리는지 같은 잣대로 검증합니다. 박스 정리·십자 정리를 각각 켜고 끈 네 가지 조합을 비교해, 개선 효과와 어느 변수가 주범인지까지 분해합니다. (align_index_ablation.py)
정확도 검증 · 준비완료(오피스 대기)
S(성공) 전용 위치추정 검증 — 다음 테스트
분류 정확도(있음/없음) 대신 "좌표를 실제로 맞히는가"를 거리로 직접 잽니다. 정답을 믿을 수 있는 성공(S) 데이터에서, recipe 안의 자기 십자를 정답으로 두고 1발 명중률(rank-1 hit)을 측정 — recipe별 편차에 휘둘리지 않는 깨끗한 판정입니다. (golden_localization_eval.py · 오피스 데이터 수집 후 실행)

② 두 가지 정리, 한눈에 — 무엇을 왜 지우나

Align Point 보정은 등록 이미지(레시피)의 align 위치를 측정 이미지(웨이퍼)에서 다시 찾는 작업입니다. 두 이미지 모두에 매칭을 방해하는 인공 표식이 들어 있어, 매처가 진짜 패턴 대신 표식에 끌려가는 것이 정확도 저하의 핵심 원인이라는 가설을 세웠습니다.
표식어느 이미지에왜 문제해결 방법
흰 주석 박스 등록 이미지(rcp template) 엔지니어가 unique area 를 표시한 흰 사각형이 template 에 섞여 매칭 단서를 오염 박스 안쪽만 깨끗이 crop. 고정 디지털 값(히스토그램 섬)을 이용한 photometric 검출 → 안 되면 기존 방식으로 자동 폴백
십자(crosshair) 측정 이미지(msr frame) 강한 직선 edge 라 매처가 lock-on. 생산 실화면엔 없는 표식이라 학습/매칭에 부적합 십자 검출 → 그 위치를 정답으로 기록 → inpaint 로 지운 화면에서 매칭. 제거 품질을 재검출+edge 밀도로 이중 검증

③ 2×2 비교 실험 — 두 정리의 효과를 분리 측정

박스 정리(template)와 십자 정리(frame)를 각각 켜고 끈 네 조합을 같은 지표로 비교
frame = raw (십자 있음, 구)frame = inpaint (십자 제거, 신)
tpl = center (구)OLD 기준선십자 정리만
tpl = box (신)박스 정리만NEW (둘 다)
판정 = NEW − OLD 의 지표 상승폭. 대각선의 두 셀(박스만 / 십자만)이 어느 변수가 효과의 주범인지 분해해 줍니다. 한 정리만 효과가 있다면 다른 하나에 자원을 낭비하지 않도록 합니다.
두 가지 잣대를 봅니다 — (1) align_index_ablation.py: 성공/실패 분리도(bACC), 빠른 1차 스크리닝. (2) golden_localization_eval.py: 실제 좌표 명중 거리, 생산 과제에 직접 대응하는 본 판정.

④ Workflow 2 — 진행 현황

항목상태설명
흰 박스 검출·제거 (photometric)
align_point_correction.py		 완성(합성검증) 고정 디지털 값 히스토그램 섬으로 박스 검출 → 안쪽만 crop. 최악 샘플 1/6→6/6. 검출 실패 시 기존 top-hat+Otsu 로 자동 폴백. 오피스 임계 튜닝 상수 노출.
십자 제거·검증
crosshair_removal_check.py		 완성(합성검증) 검증된 십자 검출기(v2)를 본 파이프라인에 연결(이전엔 구버전 호출 중이던 것 수정). 제거 후 재검출 = 무 + edge 밀도 비 < 1.8로 잔흔/그림자까지 확인.
2×2 분리도 비교
align_index_ablation.py		 완성(합성검증) 네 조합의 S/E 분리도(bACC)+gt-in-topK 를 같은 함수로 측정. OLD vs NEW VERDICT 출력. 실데이터 1차 스크리닝용.
S 전용 위치추정 검증
golden_localization_eval.py		 오피스 대기 정답 신뢰 가능한 S 데이터에서 좌표 명중 거리(rank-1 hit)로 본 판정. recipe 내 자기 십자를 정답으로 써 recipe별 편차(confound)에 면역. align_offset 보정(template 중심 → align point 환산)까지 반영. 골든셋 수집 후 실행.
VLM+CV 백업 (gated escalation) 계획(미구현) 순수 CV 실패 케이스의 안전망. 항상 켜는 병렬이 아니라 저신뢰 신호(박스 미검출· not_distinctive 등)에서만 발동. VLM 은 영역만, 좌표는 CV(원칙 유지). 필요량은 위 실험의 잔여 실패율로 결정 후 구축.
완성(합성검증) 코드+합성데이터 검증, 오피스 미검증 오피스 대기 데이터 수집 후 실행 계획 설계만, 미구현

⑤ 방법론 — "측정 먼저, 기능은 그다음"

이번 주는 새 알고리즘을 무작정 붙이기보다 가설을 세우고 같은 잣대로 검증하는 데 집중했습니다. 그 과정에서 효과 없는 방향(리랭커: MI·contour)을 A/B 로 명확히 기각해 죽은 코드를 정리했고 (reranker_ab_failure_analysis.md), 반복하지 않도록 기록으로 남겼습니다. 분류 지표(bACC)의 cross-recipe 편향을 인지해, 생산 과제에 직접 대응하는 위치추정 거리 지표로 본 판정을 전환한 것이 이번 주의 가장 중요한 판단입니다.
  1. (오피스) 골든셋 수집 — 성공(S) 측정 이미지를 recipe당 8~10장, 웨이퍼/lot/시간 분산해 수집.
  2. 정답 위생 먼저 확인 — 십자 검출률이 낮으면 그 위 수치는 신뢰 불가. 검출기부터 점검.
  3. 본 판정 — golden_localization_eval.py 로 NEW(박스+inpaint)의 1발 명중률을 OLD 대비 측정. 통과하면 정식 채택.
  4. 임계 캘리브레이션 — success_vs_fail_compare.py 로 거짓양성 0 검증 후 fail 데이터 적용.
  5. 잔여 실패율로 VLM 백업 필요량 판단 — 대부분 통과면 tail 안전망(가볍게), 다수 실패면 정식 구축.
