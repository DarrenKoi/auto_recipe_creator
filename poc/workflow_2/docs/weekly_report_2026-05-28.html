주간 진행 보고

기간: 2026-05-22 ~ 2026-05-28 · 범위: poc/workflow_2/ (Align Key 보정)
RCS 자동화(Workflow 1)는 이미 완성된 기반이며, 이번 주 작업은 그 위에서 동작하는 Workflow 2 (Align Key 보정)에 집중했습니다. 보정 자동화의 마지막 두 관문인 OK 버튼 자동 클릭과 SEM 화면 영역(박스) 검출을 완성했고, 이어서 핵심 난제인 Align Point 보정에 착수했습니다. 보정 정확도가 기대만큼 나오지 않아, 무작정 기능을 더 붙이는 대신 "무엇이 왜 실패하는지 먼저 측정하고 가장 단순한 진단부터 단계적으로" 접근하는 복구 계획을 세워 진행 중입니다.

① 이번 주 핵심 성과

WORKFLOW 2 · 완성
OK 버튼 자동 클릭 — 보정의 마지막 확정 단계
align 위치를 다시 잡은 뒤에는 화면의 OK 버튼을 눌러야 보정이 실제로 적용됩니다. 엉뚱한 버튼을 누르면 안 되기 때문에, 시스템이 OK 버튼을 정확히 찾아 누를 수 있는지가 자동화의 마지막 관문이었습니다. 이 기능이 통과해야 "찾기 → 보정 → 확정"이 사람 개입 없이 끊김 없이 이어집니다. (vlm_wait_input_ok_button.py)
WORKFLOW 2 · 완성
SEM 화면 영역 검출 — 모든 탐색의 기준점
align key 탐색은 화면 전체가 아니라 SEM 영상이 표시되는 박스 안에서만 이루어집니다. 그래서 그 박스가 화면 어디에 있는지 먼저 정확히 알아야 엉뚱한 영역을 보지 않고, 박스가 움직이거나 닫혔는지도 감지할 수 있습니다. 장비별 기준 위치를 저장해 두어 이후 모든 탐색·보정의 출발점을 마련했습니다. (outline_live_sem_box.py)
WORKFLOW 2 · 진행 (난항)
Align Point 보정 — 현재 집중 과제
레시피에 등록된 align 위치를 실제 측정 이미지에서 같은 위치로 다시 찾아내는 핵심 단계입니다. 그런데 등록 이미지와 측정 이미지는 공정 변화·초점·배율 차이로 모양이 미묘하게 달라, 현재 같은 위치를 안정적으로 못 잡는 어려움이 있습니다. 단계별 복구 계획을 세워 원인 진단부터 진행 중입니다. (align_point_correction.py)

② Workflow 1 — RCS 자동화 (이전 완료, 기반)

RCS 로그인 → Tool 선택 → Align Fail 감지 → Tool 화면 캡처까지의 자동화는 앞서 완성되어 현재 Workflow 2의 입력(실패 시점 화면 캡처)을 안정적으로 공급하고 있습니다. 이번 주에는 신규 작업 없이 기반으로 활용했습니다. 주요 완료 항목: 클릭 파이프라인(개략→정밀→확인) 재설계, Windows 화면 배율(125/150%) 클릭 오차 보정, 알람당 전체 사이클 자동화 (align_fail_alarm_record.py: 열기→기록→닫기), 타임존/기록 정합.

④ Align Point 보정 — 무엇이 어렵고 어떻게 풀고 있나

문제. 레시피에 등록된 align 위치(엔지니어가 흰 박스로 표시)를 측정 이미지에서 같은 위치로 찾아야 하는데, 두 이미지가 픽셀 단위로 같지 않습니다 — 바로 이 차이가 align fail의 원인이기도 합니다. 그래서 같은 위치가 다른 곳으로 잡히는 경우가 발생합니다.

접근. 알고리즘을 더 붙이기 전에, 가장 싸고 빠른 진단부터 순서대로 적용해 원인을 좁혀 갑니다.
  1. 등록된 align 위치가 그 이미지 안에서 정말 유일한지 먼저 측정 — 애초에 헷갈릴 만한 패턴이면 측정 이미지에서 못 찾는 게 당연하므로, 이 진단으로 "key 품질" 문제부터 분리.
  2. 왜 그 좌표가 선택됐는지를 화면 겹쳐보기(overlay)와 기록만으로 설명 가능하게 — 실패 원인을 눈으로 확인.
  3. 후보를 하나만 믿지 않고 여러 후보를 비교해, 비슷한 패턴이 여러 개일 때 성급히 틀린 곳을 고르지 않도록.
  4. 유망 후보에만 추가 검증을 적용해 오답을 걸러냄(전체 화면이 아닌 후보 영역에만 적용해 비용 최소화).
  5. 확신이 없으면 "보류"를 우선 — 틀린 좌표를 다음 단계로 넘기는 것이 가장 위험하므로 안전하게 멈춤.
  6. (오피스) 실장비 연결 어댑터와 안전장치(이동·확대 횟수 제한, 영역 밖 클릭 차단) 구현 후 실 화면 회귀 테스트.
