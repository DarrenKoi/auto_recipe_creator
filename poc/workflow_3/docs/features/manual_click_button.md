# tool 창 버튼 클릭 + 버튼 레지스트리

> CLAUDE.md 에서 옮겨 온 원문(2026-09-19). 이 기능을 고치기 전에 끝까지 읽을 것 - 계약은 오피스 실측에서 나왔고 Mac 에서 재현할 수 없다.

**tool 창 버튼 클릭 + 가림 해제 폴백** (2026-09-18 오피스 확인, `monitor/manual_click_button.py`, `MANUAL_CLICK_*`): 알람과 무관한 진입점. 엔지니어가 먼저 연 tool 창에서 버튼 하나(기본 **File Manager** - 화면 아래쪽 버튼 그룹의 오른쪽)를 확인 후 누르고, 열린 창 제목 `File Manager( Class, IDW, IDP, Recipe )` 까지 확인한다(종료 코드 0 클릭+창 확인 / 2 사전조건 / 3 가림 해제 후에도 못 찾음 / 4 라벨 불일치 / 5 클릭했지만 창 미확인). 다른 버튼은 파일 상단 `TARGET_*`/`OPENED_*` 상수만 바꾼다. 가림 해제는 **폴백**이다(이름에 hidden 을 넣지 않은 이유): 'SECS Terminal'/'Terminal Service' 같은 창이 버튼 그룹을 덮으면 엔지니어가 하듯 **Alt+click 으로 덮은 창을 뒤로 보낸다**. 배선은 `demonstration_rcs_control` 의 `build_click_kit`(capture/locate/read_tokens/click/reveal/alt_click_at - 오피스 실측 클릭 조건을 포크하지 않으려고 뽑았다)와 `locate_with_reveal`(요소 확인 + `should_reveal_fn` 이 허락할 때만 가림 해제, 해제 횟수는 호출을 넘어 누적) 을 쓴다. 오피스 실측 여섯 번이 만든 계약: ① **첫 글자 anchor 금지** - 'F' 로 시작하는 라벨이 많아 이웃을 짚었다. 라이브 SEM box 기준 설명도 뺐다(VLM 이 그 box 를 모를 수 있다) - 전체 문구 + '아래쪽 버튼 그룹, 오른쪽' 으로 둔다. ② **라벨 불일치 ≠ 가림.** 미검출/불일치일 때 버튼이 있어야 할 예상 영역(`REVEAL_X/Y_RATIO` 0.80/0.90 중심, 창의 ±25%x±8%)을 확대 OCR 해 라벨이 읽히면 **VLM 이 잘못 짚은 것**이라 Alt+click 하지 않고, 그 영역 crop 으로 VLM 을 다시 돌린다(crop 좌표 + box 원점; 오피스에서 이 재탐색이 맞는 점을 찾았다). 영역에 라벨이 없을 때만 가림이다. ③ **Alt+click 지점은 VLM 이 찾은 덮은 창의 제목줄**이다 - 고정 비율 지점은 버튼 주변 어디에나 놓이는 창을 빗나갔다(창보다 약간 위를 눌러 효과 없음). 라운드마다 새로 캡처해 앞 창을 찾으므로 두 장 겹침도 두 번에 걷힌다(`REVEAL_ATTEMPTS` 3). 짚은 곳에서 대상 라벨이 읽히면 tool 화면 자체라 누르지 않고(tool 창이 뒤로 간다), 못 찾으면 고정 지점으로 대신 누르지 않는다. ④ **확인은 strict + forbidden 비움.** lenient 는 덮은 창 라벨('SECS Terminal')을 '못 읽음' 으로 통과시키고, forbidden(Exit/Close)은 이웃 버튼이 확인 crop 에 반드시 함께 읽혀 맞는 점을 거부했다(시연 Work Sheet 와 같은 교훈). ⑤ **확인 crop 은 버튼 한 개 크기**(`CONFIRM_HALF_*_RATIO` 0.10/0.015 - `build_click_kit` 기본 0.30/0.05 는 시연용): 넓은 crop 은 여러 줄을 담아 PaddleOCR 이 위 줄만 읽었다. ⑥ **needle 은 `manag`** - Alt+click 뒤 **장비 커서가 버튼 위에 남아** 끝 글자를 가려 'Manage' 로 읽혔다(원격 뷰 커서는 프레임에 찍힌다). 더 잘리면 확인 캡처 전 커서를 치우는 것이 다음 수다. 창 확인이 실패해도 다시 누르지 않는다(떴는데 확인만 놓친 경우 두 번째 클릭이 무엇을 할지 모른다). `SAFE_MODE=0` 이 진입점 기본값(`SAFE_MODE=1` 이면 클릭/Alt 모두 차단), 산출물 `debug_images/manual_click_button/<tag>/`(VLM 마킹, 확인/예상 영역 OCR crop).

**버튼 레지스트리 + 공통 프롬프트** (2026-09-19, `monitor/button_registry.py`, Codex 논의): File Manager 한 번 누르는 데 오피스 6회 프롬프트 수정이 들었던 것을 데이터로 바꿨다. `manual_click_button` 은 `TARGET`(key/label/'window/label') 하나로 `BUTTONS` 의 `ButtonSpec`(label·hint·required·center·search/confirm 크기·reveal·opens_title)을 고르고, VLM 설명문은 `describe` 한 곳이다. 새 버튼 = 레지스트리 한 줄, 위치 모르면 `center=None` 으로 두고 첫 성공 실행이 찍는 `center=(x, y)` 를 옮긴다. 탐색은 `find_button`: 등록 영역 crop -> (미검출/라벨 불일치 모두) 전체 화면 + hint, 확인은 `_confirm_point` 재사용(`locate_with_reveal(confirm_fn=)`). 계약: ① **식별은 (window, label)** - 여러 창에 있는 라벨(OK)은 이름만으로 고르지 않고 거부, 팝업 안 버튼은 탐색을 그 팝업 내부로 제한할 수단이 없어 **클릭 미지원** ② 빈 `required` 등록 금지(strict 에서도 확인을 건너뛴다) ③ 짧은 라벨은 `whole_word`(AMP 가 'Sample' 에 걸린다) ④ 가림 해제 Alt+click 은 `reveal=True`(오피스 검증된 File Manager)만 - 덮은 창 제목을 긍정 확인하지 않는 Alt+click 을 일반화하지 않는다 ⑤ 열릴 창이 클릭 전부터 보이면 누르지 않는다(exit 6) ⑥ 클릭 후 `poll_until` 로 **처음 확인된 시각**(`first_seen_after_click_sec`, VLM+OCR 지연 포함)을 [DIGEST] 에 남기고 재클릭하지 않는다; 열릴 창 미등록 버튼은 `effect=unverified`. `manual_screen_inventory.py` 는 클릭 없이 등록 버튼마다 **버튼 한 개 크기** 라벨 영역을 OCR 해 `label_seen/not_seen/read_error/no_region` 표 + 앞 창 제목줄 1회(미검출=unknown, 창 없음 증거 아님)를 찍는다 - 관찰용이며 클릭 승인에 쓰지 않는다. 등록: file_manager / amp(File Manager 아래) / rotation('Rot.', PM 근처) - AMP·Rot 은 위치·라벨 문구 오피스 미확인. 무클릭 벤치는 두지 않는다(사용자 결정: 클릭 무해한 버튼으로 실클릭 시험해 원격 지연까지 본다). 설명 모델(Kimi/Qwen thinking low)과 두 장 비교는 후속.
