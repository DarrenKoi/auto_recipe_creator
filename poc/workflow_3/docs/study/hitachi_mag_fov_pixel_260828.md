# Hitachi CD-SEM 배율(Mag) · FOV · 픽셀 관계 — workflow_3 참조

원본: `skewnono_v3_nuxt/docs/datatables/hitachi/mag_pixel.txt` (2026-08-28 기준). 이 파일은
그중 **align fail 보정/탐색(live_search, sem_monitor)이 필요로 하는 부분만** 옮긴 것이다.
원본이 진실이고 이 문서는 사본이다 — 상수가 바뀌면 원본을 먼저 고친다.

## 1. 메커니즘

SEM 배율은 렌즈 배율이 아니다. 빔이 시료 위 사각 영역(FOV)을 raster 로 훑고 그 신호를
**고정 크기 기준 화면**에 그린다.

    Mag = 기준 화면 폭 / 시료 위 스캔 폭(FOV)

따라서 **픽셀 수(512/1024/…)는 FOV 를 바꾸지 않는다** — 같은 배율이면 같은 영역을 보고,
픽셀 수는 그 영역을 몇 샘플로 나누느냐(nm/px)만 정한다.

## 2. 계산식

    FOV_µm        = 135,000 / Mag        # 기준 화면 폭 135 mm = 135,000 µm
    PixelSize_nm  = FOV_µm × 1000 / N     # N = 가로 픽셀 수
    half-FOV      = FOV / 2               # 더블클릭 recenter 1회의 최대 이동량

- 상수 135,000 의 단위는 **µm** (원본 표의 nm 표기는 오류, 2026-07-25 정정).
- **OFFICE-VERIFY**: 오피스 cond.txt 표본 1건이 Magnification `30000` ↔ Field_Size
  `4.499 um` → 곱 134,970 (0.02 % 차). 정확히 135,000 인지는 표본 1건뿐이다.
  nm/px 표기나 탐색 반경 추정에는 차이가 없다.
- FOV 는 **폭**이다. 비정사각 픽셀은 아직 관측된 적 없다(OFFICE-VERIFY).

### 대표값 (512 px 기준)

| Mag | FOV (µm) | half-FOV (µm) | nm/px @512 | nm/px @1024 |
|---|---|---|---|---|
| 5,000 | 27.0 | 13.5 | 52.7 | 26.4 |
| 10,000 | 13.5 | 6.75 | 26.4 | 13.2 |
| 20,000 | 6.75 | 3.38 | 13.2 | 6.6 |
| 30,000 | 4.50 | 2.25 | 8.8 | 4.4 |
| 50,000 | 2.70 | 1.35 | 5.27 | 2.64 |
| 100,000 | 1.35 | 0.675 | 2.64 | 1.32 |
| 200,000 | 0.675 | 0.338 | 1.32 | 0.66 |

**OM 은 이 식으로 계산하지 않는다.** OM Magnification 은 `'104'` 부근(recipe 마다 다름)이고
cond.txt 의 OM `Field_Size` 는 **key 만 있고 값이 없다**. SEM 상수로 채우면 안 된다
(2026-07-30 이전 mock 이 `'1297.788 um'` 을 지어냈던 실수). OM 의 실제 FOV 는 미상이다.

## 3. 장비 상수 — PM 드롭다운이 고를 수 있는 배율 단

계열 판정은 모델코드 **접두사**(`CG…`/`GT…`).

- **CG 계열** (CG6300 등) 23단:
  1000, 2000, 5000, 8000, 10000, 20000, 50000, 60000, 70000, 80000, 100000, 120000,
  150000, 180000, 200000, 220000, 250000, 300000, 350000, 400000, 420000, 450000, 500000
- **GT 계열** (GT2000 등) = CG 23단 + 600000, 700000, 800000, 900000, 1000000 (28단)
- 픽셀 설정 공통: 512, 1024, 2048, 4096 (실사용은 512·1024).
- 표기는 항상 K 단위(1000K, 1M 아님).

탐색 설계에 중요한 점: **배율은 이산값**이라 "R 을 덮는 FOV" 는 정확히 맞출 수 없고
그 이상인 가장 높은 단을 고른다. 예: 30K 에서 한 단계 아래는 20K(FOV 6.75 µm), 그 아래
10K(13.5 µm), 5K(27 µm).

## 4. 실데이터에서 배율이 나타나는 자리

- recipe cond.txt (`read_align_image_condition`): `Magnification` = 단위 없는 **str**
  (`'30000'`), `Field_Size` = `'4.499 um, 4.499 um'` (SEM 만), `Pixel` = `'512,512'`.
  Magnification 과 Field_Size 는 한 설정을 두 번 본 것이다.
- msr_file pickle `meas_condition mag`: 정수지만 **정격값이 아니다**(250030 처럼 실현값).
  빈 row 센티널은 mag 0 / pixel "0,0" → 135000/0 이 되므로 null 로 게이팅.
- 화면(PM box): `sem_box_detect.py` 가 라이브 SEM box 옆 PM 배율을 읽어 OM/SEM 을
  가른다 — 104/210 = OM, K 접미사 = SEM.

## 5. workflow_3 탐색(search-around)에 대한 함의

- 더블클릭 recenter 는 클릭점을 중심으로 옮기므로 **1회 최대 half-FOV**. pan N 회의
  이론 상한은 N/2 FOV 이고, 프레임 픽셀 단위 step 은 배율에 역비례로 줄어든다.
- 등록 배율(cond.txt Magnification)과 현재 배율(PM 드롭다운 절대값)을 둘 다 알면
  템플릿 scale = 현재/등록 을 **정확히** 알 수 있어 scale band 탐색이 1-scale 매칭이 된다.
  휠 zoom 은 배율이 미보정이라 이것이 불가능하다.
- 매칭기 scale 하한 0.15(`WIDE_SCALES`) → 배율 축소는 최대 ≈6.7× (30K → ≥4.5K, 실제 단
  5K; 100K → ≥15K, 실제 단 20K). SEM key 는 프레임 80-100 % 라 그 축소에서도 ~77 px 로
  남지만 OM key(10-20 %)는 8-15 px 라 매칭 불가 → OM 은 zoom-out 이 아니라 pan.
- 컨트롤러의 `nm_per_pixel` 은 현재 `None` — 위 식을 넣어야 "N µm 이동" 을 표현할 수 있다.
