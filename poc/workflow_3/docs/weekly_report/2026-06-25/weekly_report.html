이번 주는 "align-key 변별력이 약하다"는 하나의 근본 병목을 세 갈래로 공략해, "매처를 더 정교하게 만드는 길은 막혀 있고 진짜 레버는 align-key 재등록"이라는 결론에 도달했습니다. ① 재등록 리포트 Phase 1(S-only 변별력 스크리닝, 완료)·Phase 2(E-frame 승급, 오피스 실측서 신호 신뢰 불가 → 종료), ② 별개로 두 번째 MES 알람(측정 연속 실패) 자동 abort 잡을 workflow_3e 확장 패키지로 추가(notify-only 기본, 코드 shipped), ③ template-bank matcher 벤치를 구현·오피스 평가까지 완료했으나 rank-1 ≈ 0.5(반반) → 출하 불가, 기각(ADR 0006).

① 재등록 리포트 Phase 1·2 — 무엇을 시도하고 무엇이 나왔나

시도 · PHASE 1S-only 스크리닝 — success 프레임만으로 align-key 변별력을 평가, 약한 key 를 latent-risk 순으로 랭킹 + 더 변별력 있는 대체 박스 제안(3단 evidence tier).
결과 · 완료드라이버 완성. box-suggestion fidelity 전 recipe 0 버그를 끝까지 추적(후보 xy=patch 중심, align_offset 미적용) → _box_offset_xy + tight scale band + tolerance widen 으로 w_sugg 0 → 1(양 modality) 복구.
시도 · PHASE 2E-frame confirmation — 같은 free-search 를 fail(E) 프레임에 돌려 S→E 점수 collapse로 latent → confirmed 승급(SDD 6태스크, 60 tests, 전용 EFRAME_ROOT + dataset-health).
결과 · 종료오피스 실측 2회 — 실제 점수대 ~0.2-0.3인데 임계 ~0.5 가정이라 confirmed 0; 임계 낮추니 5/6 false positive. 117 중 28만 E-bearing. 근본 원인 = key 가 S 에서도 약함 → 무너질 높이가 없는 구조적 모순.
핵심 교훈: 재등록 리포트가 "약하다"고 flag 하는 recipe 는 애초에 success 에서도 약한 key라 "S 에서 높다가 E 에서 무너지는" collapse 신호 자체가 성립하지 않습니다. Phase 2 는 이 데이터에서 신뢰할 신호가 아니므로 종료(코드·dataset-health 는 보존).

③ template-bank matcher 벤치 — 시도·가설·결과(기각)

동기: rcp align-key 가 충분히 distinctive 하지 않아 매처가 success 에서도 약하게(~0.2-0.3) localize, SEM recall ~68% 병목. 가설 H1 = N 개 S-crop 을 개별(sharp) 유지하고 dense 응답을 heatmap soft-voting(SUM) 으로 융합하면 median-consensus(blur 로 뭉갬)보다 낫다. RRF 는 extra arm. 반대가설 H0(kill-test 로 먼저 배제) = 주기 distractor 가 S 간 일관되면 합의가 distractor 를 강화해 더 나쁠 수도.
검증 단계판정내용
1. kill-test (H0 배제)통과 ✅near_periodic om 0.014 / sem 0.052 로 낮음 → distractor 강화는 일어나지 않음.
2. in_topk (천장 지표)이김 ✅정답을 상위 후보 안엔 잘 넣음 — consensus 대비 우위.
3. rank-1 (실제 출하 성능)막힘 ❌OM/SEM 둘 다 ≈ 0.5(동전 던지기). RRF 는 OM 0.902 지만 이미 consensus 와 redundant.
결론 (ADR 0006 · 기각): 실전은 후보 8개가 아니라 1등 좌표 하나를 클릭하므로 rank-1 이 실제 출하 성능(in_topk 는 천장일 뿐). rank-1 0.5 는 출하 불가. heatmap·RRF·기타 3가지 융합이 모두 같은 벽에 막힘 → SEM 은 어떤 멤버 융합(member-fusion)으로도 못 푸는 ranking/distinctiveness 문제. 매처-융합은 소진됐고 레버는 upstream 재등록. 코드는 TBANK_HEATMAP=0 kill switch 뒤 보존(16/16 tests), workflow_3 포팅 안 함.
이번 주 가장 비싸게 배운 규율: 벤치 A/B 는 in_topk(천장)가 아니라 rank-1(실제 출하 성능)으로 비교한다.
